# /dev-loop

`/dev`는 세션마다 정지·인수인계하고 사용자가 `/clear` 후 재호출해야 한다. `/dev-loop`는 이 재호출 루프를 자동화한다 — **노드를 별도 Claude 세션에 위임**하고 DEV_PLAN이 `done`이 될 때까지 반복한다.

루프를 도는 세션 자신도 포화한다. 그래서 **지휘 기능을 사용자 대면 세션에서 떼어 별도 tmux 세션으로 옮기고, 그 세션이 포화하면 통째로 갈아끼운다.**

## 핵심 개념

**세 계층으로 나눈다.**

| 계층 | 어디서 도는가 | 소유하는 것 | 소유하지 않는 것 |
|---|---|---|---|
| **창구** | 사용자와 붙어 있는 이 세션 | 지휘의 생명주기(스폰·종료·중계 상태 파일 갱신), 교체 실행, 사용자 통보, **계획서가 없을 때의 신규 인테이크**(아래 예외) | 노드 실행 판단, 위임·회수, 루프가 도는 동안의 DEV_PLAN 갱신 — 지휘가 무엇을 하는지에 개입하지 않는다 |
| **지휘** | tmux, 고정 UUID 1개 | 노드 위임·회수·판정, DEV_PLAN 갱신·커밋, 자기 포화도 계측, 사용자에게 보낼 질문·알림 | 자기 교체 실행(창구 몫), 비가역 조작("비가역 조작 경계") |
| **작업** | tmux, 노드 1개당 1개 | 자기 워크트리 안 작업과 자기 브랜치 커밋, 회신·알림 | DEV_PLAN 쓰기(읽기 전용), 워크트리 밖 수정, 머지 |

- **창구는 판단하지 않고 지휘는 죽지 않는 척하지 않는다.** 창구가 계획 내용을 들여다보기 시작하면 창구도 같은 속도로 포화해 계층이 무의미해진다. 지휘는 포화를 스스로 재어 임계에서 교체를 요청한다.
- **예외는 신규 인테이크 하나다.** 계획서가 아직 없으면 창구가 `/dev` Phase 1을 직접 돌려 DEV_PLAN을 만든다 — 인테이크는 사용자와의 왕복이라 대면 세션 말고는 할 자리가 없다. **계획서가 서는 순간 창구의 계획 관여는 끝난다** — 그 뒤로는 읽지도 고치지도 않고 지휘에 넘긴다.
- **작업 세션 = tmux로 띄운 별도 Claude 세션.** 노드 1개당 1개를 지휘가 생성하고, 완료 후 지휘가 종료한다. 별도 프로세스이므로 컨텍스트가 완전히 격리되고 중첩 스폰 계층을 소모하지 않는다.
- **지휘가 직접 처리하는 노드는 둘뿐이다.** ① 주체가 사용자인 디자인 노드 — 작업 세션에는 시안을 고를 사람이 없다. ② 노드 브랜치 합류·머지 — 여러 브랜치를 하나로 합치는 것은 위임할 수 없다. **배포·데이터 이관 같은 비가역 조작은 지휘도 하지 않는다**("비가역 조작 경계").
- **DEV_PLAN 갱신은 지휘만 한다.** 작업 세션에는 읽기 전용을 명시한다.
- **작업 세션은 항상 워크트리에서 돈다.** 단독 실행이어도 워크트리를 만든다 — 같은 트리를 쓰면 커밋이 서로 잠금을 다툰다.
- **완료 판정은 산출물·커밋 실재 + 보고의 `검증:` 결과가 통과일 때로 한다.** 답신 개수로 판정하지 않는다 — 한 세션에 여러 건을 보내면 답신이 하나로 합쳐진다. 산출물과 커밋이 있어도 검증 결과가 실패·중단·누락이면 완료로 보지 않는다("세션 위임" 5번).
- **동시 실행은 3개까지.** 구현 노드는 담당 파일 교집합이 비고, 단위·통합 테스트가 고정 포트·공유 DB 파일·외부 서비스를 동시에 잡지 않을 때만 동시에 둔다(`/dev` 병렬 배치 규칙과 동일 기준). 조사·연구·설계 노드는 읽기·산출 전용이므로 이 조건을 적용하지 않는다.
- **정지선은 개수가 아니라 토큰이다.** `/dev`의 "컨텍스트 임계 판정"을 그대로 쓴다 — 약함 200,000·강함 300,000토큰, 검사 자리는 노드 위임 직전. 지휘는 임계에서 정지하는 대신 **교체를 요청한다**("교체 프로토콜").

## 진입 (역할 분기)

첫머리에서 자기가 어느 계층인지 가른다.

1. **`--commander <절대경로>`로 호출됐으면 지휘다.** 이 인자는 창구가 스폰할 때 첫 프롬프트로 넣는 것이고 사람이 직접 치지 않는다. `--followup`이 함께 있으면 경로는 후속 항목 대장이고 → "후속 소진 루프"로, 없으면 경로는 DEV_PLAN이고 → "지휘 루프"로 간다.
2. **`--commander` 없이 `--followup`만 있으면 창구다** → "후속 소진 절차"로 간다.
3. **그 외는 창구다** → "창구 절차"로 간다.

## 창구 절차

창구가 하는 일은 지휘를 세우고, 갈아끼우고, 사용자에게 전달하는 것이다. **계획서가 선 뒤로는 그 내용을 읽지 않는다** — 신규 인테이크(2번)만이 예외다.

1. **DEV_PLAN 확정.** `--resume <경로>`가 있으면 그 DEV_PLAN을 쓰고, 없으면 `docs/dev/plan/`을 스캔한다(경로 규약은 `/dev`와 동일). `status: in-progress`가 2개 이상이면 제목을 1줄씩 보여주고 어느 것을 이어갈지 질문 후 답 대기.
2. **DEV_PLAN이 없으면 창구가 직접 `/dev`를 Skill로 호출해 계획 세션을 수행한다**(핵심 개념의 인테이크 예외) — 인테이크는 사용자와의 왕복이라 이미 대화 중인 창구가 하는 편이 빠르다. **계획서를 쓰고 커밋하는 데서 멈춘다** — 그 세션에서 노드를 하나라도 실행하지 않고 3번으로 넘어간다.
3. **우체부 기동.** 텔레그램 중계 프로그램이 도는지 확인하고 없으면 **`POSTMAN_PROJECT=<프로젝트슬러그>`를 실어** 띄운다 — 비우면 발신문의 출처 표시와 다른 프로젝트가 도는 동안의 기동 거부가 함께 잠든다(`skills/postman/README.md` 기동 절). **우체부가 아직 설치되지 않은 프로젝트면 이 단계를 건너뛰고 "텔레그램 통로 없음 — 질문은 이 화면으로만 옵니다"를 1줄 알린다.**
4. **스폰 전 최소 검사.** 넷을 확인하고 **하나라도 실패하면 지휘를 띄우지 않는다** — 실패 항목을 사용자에게 알리고 멈춘다. "기동은 됐는데 자리를 비운 뒤에야 드러나는" 실패를 스폰 시점으로 끌어오는 것이 목적이다.
   1. `tmux` 실행 가능
   2. DEV_PLAN 경로 실재
   3. 전역 상태줄 설정 존재 — 이것이 없으면 지휘가 자기 포화도를 못 재고, 못 재는 지휘는 교체 시점을 놓친다
   4. 우체부 heartbeat 신선(15분 이내) — 우체부를 띄우지 않은 경우(3번을 건너뛴 경우)는 이 항목도 건너뛴다
5. **통합 워크트리 준비.** 지휘가 노드 브랜치를 합칠 자리를 만든다 — `git worktree add <저장소>-nodes/integration -b integration/<계획서번호>`(이미 있으면 그대로 재사용). **메인 워킹트리를 지휘에게 주지 않는다** — 자동 push 잡이 도는 저장소에서 지휘의 머지 커밋이 그대로 원격에 나가는 것을 막고("비가역 조작 경계"), 사용자가 옆에서 쓰는 트리와 잠금을 다투지 않게 한다.
6. **지휘 스폰** ("지휘 스폰 절차"). 첫 프롬프트에 DEV_PLAN 절대경로·통합 워크트리 경로·세대·**창구 주소**를 담는다. **창구 주소는 스폰 직전에 `ListAgents`를 한 번 불러 출력 첫 줄(`This session is <이름> [<ref>] …`)의 `<이름> [<ref>]`를 그대로 복사한다** — 지휘가 창구를 깨우는 유일한 경로이고, 창구는 주소록에서 찾아지지 않으므로 창구 자신이 넘기는 수밖에 없다("세션 주소 규약"). 첫 줄이 없거나 형식이 다르면 `창구 주소: 없음`으로 적고 넘어간다 — 지어내지 않는다.
7. **대기 — 지휘 우편함을 훑는다.** 지휘의 통보는 **알림 파일로 온다**("사용자에게 닿는 통로"). **창구가 훑지 않으면 교체도 완주 처리도 일어나지 않는다** — 화면에 오기를 기다리지 않는다.
   - 훑을 자리는 `~/.claude/postman/sessions/dev-cmd-<프로젝트슬러그>/`의 `notify-*.json`이다. 우체부가 없는 프로젝트에서도 같다 — 파일 통로는 우체부와 무관하게 선다.
   - **차단형 대기를 건다** — 조건 감시 도구를 쓰고, `sleep`을 낀 폴링 명령은 그것이 없을 때만 쓴다(전경 `sleep`을 막는 환경이 있다). 한 번의 대기는 최대 10분이고, 새 파일 없이 끝나면 다시 건다.
   - **대기는 그 턴의 마지막 행동이어야 한다** — 턴이 끝나면 훑기도 멈춘다. 사용자 응대로 대기가 끊기면 응대를 마친 직후 다시 건다.
   - **턴이 끝나 유휴가 돼도 통로는 닫히지 않는다.** 지휘가 알림 파일을 쓴 직후 창구 주소로 깨우기 발신을 한 통 보내므로, 유휴 상태의 창구는 그 한 통에 깨어난다(실측 11초). **깨어나면 발신 본문을 처리하지 않고 우편함부터 훑는다** — 발신에는 변별자와 한 줄 요약만 실려 있고 내용의 정본은 알림 파일이다("사용자에게 닿는 통로"의 「깨우기 신호」). 처리를 마치면 대기를 다시 건다.
   - **처리한 변별자는 다시 처리하지 않는다.** 같은 통보가 `SendMessage`로 한 번 더 들어와도 중복 실행하지 않는다.
   - **변별자의 세대가 중계 상태 파일의 현재 세대와 다르면 처리하지 않는다.** 알림 파일은 최대 7일 남으므로, 창구가 새로 떠 옛 세대의 교체 요청을 다시 읽으면 멀쩡한 지휘를 죽인다.

   `text`의 변별자가 `[cmd `로 시작하는 것만 제어 통보다. 창구가 스스로 움직이는 것은 넷뿐이다.
   - **교체 요청** → "교체 프로토콜"
   - **계측 불능 보고** → 같은 사유로 이미 연속 2회 교체했으면 교체하지 않고 사용자에게 알린다("교체 프로토콜" 6번). 아니면 교체한다
   - **우체부 재기동 요청** → heartbeat가 신선하면(15분 이내) 아무것도 하지 않는다. 낡았으면 우체부 프로세스를 끝낸 뒤 3번을 다시 돌린다 — heartbeat가 멎은 우체부는 살아 있어도 통로가 아니라 3번의 "없으면 띄운다"만으로는 낫지 않는다
   - **완주 보고** → 8번

   그 밖의 통보(진행 상황)에 대해 창구가 하는 일은 **전달뿐이다** — 지휘의 문장을 사용자에게 그대로 옮기고 사용자의 답을 지휘에 그대로 되돌린다. **요약·판정·보완을 하지 않는다.**

   **되돌릴 것은 답만이 아니다.** 지휘가 묻지 않았는데 사용자가 새 지적·지시를 내면 창구가 그것도 지휘에 올린다 — 올리지 않으면 지휘는 그 말을 영영 모르고, 사용자는 자기 지시가 반영되는 중인 줄 알고 기다린다.
   - **원문 그대로 옮긴다.** 요약·해석하지 않고, 어느 노드를 어떻게 고치라는 절차를 창구가 붙이지 않는다. **창구가 전달하는 것은 사용자의 발화이지 창구의 지시가 아니다** — 그 발화를 계획의 어디에 어떻게 반영할지는 지휘가 정한다. 이 구분이 「창구는 판단하지 않는다」와 이 경로가 충돌하지 않는 자리다.
   - **전달 수단은 `SendMessage`다.** 지휘는 tmux 행이 있어 주소를 잡을 수 있다 — ref는 "세션 주소 규약"의 ①(그 세션에 처음 보낼 때)에서 맺어 그 지휘 인스턴스가 사는 동안 재사용하고, **교체로 새 지휘를 띄웠으면 다시 맺는다**(옛 ref는 죽은 인스턴스를 가리킨다). 변별자는 제어 메시지와 같은 자리를 쓰되 발신자가 창구이므로 `[cmd g<세대>#<n>]`로 붙이고, 첫머리에 **사용자 발화임을 밝히는 한 줄**을 둔 뒤 원문을 인용한다.
   - **창구는 지휘 우편함에 파일을 쓰지 않는다.** 지휘는 자기 우편함을 훑지 않으므로 파일은 닿지 않는다 — 이 방향에는 파일 폴백이 없다. 발신이 실패하면 "세션 주소 규약"에 따라 ref를 다시 맺어 1회 재발신하고, 그래도 실패하면 **전달하지 못했다는 사실을 사용자에게 알린다.** 전달된 것으로 가정하고 넘어가지 않는다.
8. **정리.** 지휘 tmux 종료, 중계 상태 파일 갱신, "주의사항"의 세션·워크트리 정리를 수행하고 완주를 사용자에게 보고한다. **통합 브랜치를 메인에 합치는 것은 사용자 몫이므로 창구가 실행하지 않는다** — 합칠 브랜치명과 워크트리 경로를 알리는 데서 멈춘다.

> **Do:** 계획서가 선 뒤의 창구는 지휘를 세우고 갈아끼우고 전달만 하며, 대기 동안 지휘 우편함을 계속 훑고, 사용자가 새로 낸 지적은 원문 그대로 지휘에 올린다
> **Don't:** 창구가 DEV_PLAN을 읽어 다음 노드를 고르거나, 지휘의 판정을 검토하거나, 인테이크 세션에서 노드까지 실행하거나, 지휘의 통보가 화면에 뜨기를 기다리거나, 사용자의 새 지적에 절차 지시를 덧붙이거나 자기 선에서 삼킨다

## 지휘 스폰 절차

창구가 수행한다. 지휘는 **저장소가 아니라 전용 작업 폴더에서 돈다** — 스킬 목록·프로젝트 지시문을 통째로 지고 시작하면 바닥이 실사용 구간의 절반을 먹고, 그 값을 교체할 때마다 다시 낸다.

**1. 전용 작업 폴더를 준비한다** (없으면 만든다). `~/.claude/dev-loop/<프로젝트슬러그>/`

```
~/.claude/dev-loop/<프로젝트슬러그>/
  .claude/skills/dev-loop → ~/.claude/skills/dev-loop 심링크
  .claude/skills/dev      → ~/.claude/skills/dev 심링크
  .claude/skills/impl     → ~/.claude/skills/impl 심링크
  .claude/skills/adr      → ~/.claude/skills/adr 심링크
  settings.json           # 아래 2번
```

지휘가 쓰는 스킬은 이 넷뿐이고 **`dev-loop` 자신을 빠뜨리지 않는다** — `--setting-sources project`가 사용자 스코프 스킬을 끊으므로, 이 심링크가 없으면 첫 프롬프트의 `/dev-loop --commander`가 "Args from unknown skill"로 흘러 지휘가 아무것도 하지 않는다.

**이어서 이 폴더를 신뢰 등록한다.** `~/.claude.json`을 통째로 읽어 `projects["<폴더 절대경로>"].hasTrustDialogAccepted`만 `true`로 더하고(항목이 없으면 만든다), 임시 파일에 쓴 뒤 rename하는 원자 쓰기로 되돌린다. **이 파일은 모든 프로젝트가 공유하므로 다른 항목·키를 지우지 않는다.** 등록하지 않으면 지휘가 「이 폴더를 신뢰합니까」 창에서 정지하고 `--permission-mode bypassPermissions`로도 넘어가지 않는다. 한 번 등록하면 이후 세대는 그대로 통과한다.

저장소 밖이므로 **지휘는 git을 `git -C <통합 워크트리 절대경로>`로 조작한다** — cwd가 저장소 안이라고 가정하는 명령을 쓰지 않는다.

**2. 지휘 전용 설정을 쓴다.** `statusLine` 키를 **전역 설정과 같은 값으로 명시 포함한다** — 이 키가 빠지면 지휘의 상태 파일이 생기지 않고, 상태 파일이 없으면 포화도 계측이 죽어 교체 루프의 입구가 된다.

```json
{
  "statusLine": { "type": "command", "command": "<전역 설정의 statusLine.command 값 그대로>" },
  "permissions": { "allow": [], "defaultMode": "bypassPermissions" },
  "model": "<전역과 같은 값>",
  "effortLevel": "<전역과 같은 값>"
}
```

**3. 새 UUID를 발급하고 스폰한다.** tmux 세션명은 `dev-cmd-<프로젝트슬러그>`이고 **교체해도 바뀌지 않는다**(세대 불변). 바뀌는 것은 UUID뿐이다.

```bash
tmux new-session -d -s dev-cmd-<프로젝트슬러그> -c ~/.claude/dev-loop/<프로젝트슬러그> \
  "env -u CLAUDE_JOB_DIR -u CLAUDE_CODE_SESSION_ID -u CLAUDECODE CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false claude \
     --name dev-cmd-<프로젝트슬러그> \
     --session-id <새 UUID> \
     --permission-mode bypassPermissions \
     --strict-mcp-config \
     --settings ~/.claude/dev-loop/<프로젝트슬러그>/settings.json \
     --setting-sources project \
     '/dev-loop --commander <DEV_PLAN 절대경로>  통합 워크트리는 <경로>, 세대는 <n>이다. 창구 주소: <이름> [<ref>]. 재진입이면 진행 표시 노드부터 처리하라.'"
```

- **첫 프롬프트는 tmux 주입이 아니라 `claude` 실행의 위치 인자로 넣는다.** 창구는 tmux에 키를 넣지 않는다 — 주입은 우체부의 몫이고, 두 주체가 같은 pane에 쓰면 초기화 중인 화면에서 섞인다.
- **`env -u CLAUDE_JOB_DIR`을 빠뜨리지 않는다.** 창구가 백그라운드 잡이면 이 변수를 물려받은 지휘가 창구의 주소록 이름을 뒤집어쓰고 `--name`이 무시된다 — 이름 상속을 막는 것은 이 변수 하나다. 나머지 둘(`CLAUDE_CODE_SESSION_ID`·`CLAUDECODE`)은 세션 식별자가 흘러드는 것을 막으려 함께 벗기며 이름 상속과는 무관하다("세션 주소 규약").
- **`--name`에 tmux 세션명과 같은 값을 준다.** 주소록 행의 이름이 그 값으로 고정돼 대상 판별이 쉬워진다.
- **첫 프롬프트에 창구 주소를 싣는다.** 창구가 자기 `ListAgents` 출력 **첫 줄**의 `<이름> [<ref>]`를 그대로 복사해 넣는다 — 이 값이 지휘가 창구를 깨우는 유일한 경로다("사용자에게 닿는 통로"). **주소를 확인하지 못했으면 `창구 주소: 없음`으로 적는다** — 지어내지 않는다.
- **`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false`로 프롬프트 제안을 끈다.** 켜져 있으면 빈 입력줄에 제안 문구가 떠서, 화면을 읽는 쪽이 사용자가 쓰다 만 입력으로 오인한다.
- **`--setting-sources project`가 사용자 스코프 스킬 노출을 끊는 결정타다.**

**4. 준비 신호를 확인한다.** **상태 파일 생성만으로 기동 성공을 판정하지 않는다** — 신뢰 확인 창에 멈춘 지휘도, 스킬을 못 찾은 지휘도 상태 파일은 정상으로 만든다. 둘을 순서대로 통과해야 성공이다.

   1. `~/.claude/status/<새 UUID>.json`이 생길 때까지 최대 60초 기다린다.
   2. `tmux capture-pane -p -t dev-cmd-<프로젝트슬러그>`로 화면을 한 번 보고 **`/dev-loop`가 실제로 로드돼 지휘 루프에 들어갔는지** 확인한다. 신뢰 확인 창이 떠 있거나 스킬을 못 찾은 표시가 보이면 실패다.

둘 다 통과하면 중계 상태 파일을 `running`으로 갱신한다. 2번이 실패하면 `running`으로 넘어가지 않고 "Fallback"의 지휘 스폰 실패로 간다.

**실측 (2026-08-22, 볼트).** 이 구성의 바닥은 **35,940토큰**이고, 같은 기계의 기준선(프로젝트 워크트리에서 평소대로 띄운 세션)은 **70,032토큰**이었다. `--setting-sources project`를 빼면 52,112로 되돌아간다 — 절감의 대부분이 이 인자에서 나온다. 스폰한 세션에서 `/dev` 호출도 정상 동작했다.

**폴백.** 상태 파일이 안 생기거나 `/dev`가 호출되지 않으면 이 구성을 버리고 **`--strict-mcp-config`만 붙여 프로젝트 워크트리에서 띄운다.** 바닥은 기준선으로 되돌아가지만 계획은 그대로 돈다 — **바닥 절감은 임계값의 전제가 아니다.** 임계는 어느 쪽이든 200,000·300,000 그대로다.

> **Do:** 전용 폴더·전용 설정으로 띄우고, 상태 파일과 화면을 둘 다 확인한 뒤 `running`으로 넘어간다
> **Don't:** 상태 파일만 보고 `running`으로 넘어가거나, 지휘 전용 설정에서 `statusLine`을 빼거나, 첫 프롬프트를 tmux 주입으로 넣는다

## 교체 프로토콜

지휘가 임계에 닿으면 스스로 마무리하고 창구가 갈아끼운다. **순서가 곧 유실 방지 장치다.**

**지휘 쪽 (1번)**

1. 약한 임계(200,000) 도달 → 신규 위임을 멈추고, 진행 중인 노드는 끝까지 회수하고, 미결 질문과 미회수 노드를 DEV_PLAN에 적어 적립 커밋한 뒤 창구에 **교체 요청**을 낸다 — 자기 우편함에 `kind`가 `alert`인 알림 파일로 쓰고 변별자 `[cmd g<세대>#<n>]`를 붙인 뒤, **그 직후 창구 주소로 깨우기 발신을 한 통 보낸다**("사용자에게 닿는 통로"의 「깨우기 신호」). **강한 임계(300,000)면 회수하지 않는다** — 진행 상태 한 줄만 적립 커밋하고 곧바로 교체를 요청한다. 두고 나온 노드는 다음 지휘가 `/dev`의 "미회수 노드 재진입 분기"로 흡수한다.

**창구 쪽 (2~6번)**

2. **유예를 건다.** 우체부 heartbeat를 확인하고 중계 상태 파일을 `replacing`으로 바꾼다 — 우체부는 `replacing` 동안 그 지휘로의 신규 주입을 멈춘다. 이어서 **주입 도중에 끊긴 항목이 없는지 확인한다**(최대 30초 대기, 넘으면 그 주입을 실패로 보고 보관함으로 옮긴다).
3. **죽이고 새로 띄운다.** `tmux kill-session -t dev-cmd-<슬러그>` → **새 UUID**로 같은 세션명에 재스폰("지휘 스폰 절차"). **`--resume`으로 되살리지 않는다** — 같은 UUID 재개는 컨텍스트를 그대로 복원해 포화를 전혀 덜지 못한다(실측). 교체는 새 UUID + 인수인계다.
4. **준비 신호를 확인하고 세대를 올린다.** "지휘 스폰 절차" 4번의 확인 둘(상태 파일 생성 + 화면에서 스킬 로드 확인)을 그대로 거친 뒤 중계 상태 파일의 세대를 +1 하고 `running`으로 바꾼다. **보관해 둔 답장의 재주입은 이 시점 이후에만 시작된다.**
5. **재스폰이 실패하면 1회만 재시도한다.** 재실패하면 중계 상태 파일을 `failed`(시각·사유)로 두고 사용자에게 알린 뒤 대기한다 — 무한 재시도하지 않는다.
6. **같은 사유 연속 교체는 2회까지다.** 중계 상태 파일에 직전 교체 사유와 연속 횟수를 적어 두고, **같은 사유의 3회째는 실행하지 않는다.** 지휘를 신규 위임 중단 상태로 두고 사용자에게 알린 뒤 기다린다 — 계측 배선 고장처럼 교체로 낫지 않는 원인이 교체 루프를 돌리는 것을 끊는다.

**창구가 받았는지는 중계 상태 파일로 확인한다** — 교체 요청 뒤 10분 안에 `state`가 `replacing`으로 바뀌지 않으면 창구가 훑지 않는 것이다. 요청을 1회 더 낸 뒤에도(알림 파일 + 깨우기 발신 한 쌍을 그대로 다시 낸다) 그대로면 **신규 위임 중단 상태로 대기한다.** 혼자 계속 돌지 않는다.

> **Do:** 유예 → 미완 주입 확인 → 죽이기 → 재스폰 → 준비 신호 → 세대 올리기 순서를 지킨다
> **Don't:** `--resume`으로 교체하거나, 준비 신호 전에 보관분을 다시 넣거나, 같은 사유로 세 번째 교체를 돈다

## 중계 상태 파일

`~/.claude/postman/relay.json` — **창구만 쓰고** 지휘·우체부·작업 세션은 읽기만 한다. 임시 파일에 쓴 뒤 rename하는 원자 쓰기로 갱신한다.

```json
{"project": "<슬러그>", "dev_plan": "<DEV_PLAN 절대경로>",
 "command": {"tmux": "dev-cmd-<슬러그>", "uuid": "<UUID>", "spawned_ts": "<ISO8601>", "generation": 3},
 "state": "running|replacing|failed", "state_ts": "<ISO8601>",
 "replace_reason": "<사유>", "consecutive_same_reason": 1, "updated_ts": "<ISO8601>"}
```

갱신 시점은 넷이다 — **스폰 직후**(`running`, 세대 기록) · **교체 시작**(`replacing`) · **준비 신호 확인**(세대 +1, `running`) · **재스폰 실패**(`failed`, 사유). 그 밖의 시점에 쓰지 않는다.

**한 기계에서 프로젝트 하나만 돌린다.** 이 파일은 지휘 하나만 담으므로, 두 프로젝트가 동시에 돌면 두 창구가 같은 파일을 다툰다. 이미 다른 프로젝트가 `running`으로 잡고 있으면 지휘를 띄우지 말고 사용자에게 알린다.

## 세션 주소 규약

**1차 키는 tmux 세션명이다.** 주소록 행에 노출되는 유일한 안정 식별자다.

- **이름 규칙** — 지휘 `dev-cmd-<프로젝트슬러그>`(교체해도 불변), 작업 `dev-<프로젝트슬러그>-<노드ID 소문자>`(`~/.claude/scripts/dev-view.sh --name <노드ID> <저장소 절대경로>`가 단일 출처). **저장소 경로를 반드시 함께 넘긴다** — 지휘는 저장소 밖 전용 폴더에서 돌아 경로를 생략하면 스크립트가 슬러그를 뽑을 데가 없다(생략 시 오류로 거절된다).
- **`ListAgents`에서 볼 것은 `tmux ` 표시가 붙은 행뿐이다.** 나머지는 Remote Control 잔재라 이 루프의 대상이 될 수 없다 — 실측(2026-08-23) 60행 중 52행이 Remote Control 잔재였고 `tmux ` 표시가 붙은 행은 4행뿐이었다(남은 4행은 이 루프와 무관한 로컬 세션이다). 잔재를 빼고 넘겨받을 방법은 없다: 창구·지휘는 별개 프로세스라 창구가 걸러 줄 수 없고, 목록을 좁히는 인자도 없으며, `claude agents --json`은 `[ref]`를 주지 않아 대체 경로가 못 된다. **그래서 목록을 줄이는 대신 조회 횟수를 줄인다.**
- **ref는 세션 인스턴스마다 한 번 맺어 그 인스턴스가 사는 동안 재사용한다.** 다시 맺는 자리는 셋뿐이다 — ① 그 세션에 처음 보낼 때 ② 발신이 실패했을 때 ③ 세션을 죽였다 다시 띄웠을 때(교체·재기동). **답신이 없어 화면을 확인하고 재전송할 때도 ②에 준해 다시 맺는다** — 세션은 살아 있는데 발신만 삼켜진 경우가 여기 걸린다.
- **발신 실패문의 "Did you mean" 대안을 절대 따르지 않는다.** 이름이 겹치는 다른 세션을 대안으로 제시하는 것이 실측됐고, 따르면 오배송이다. 대상 판별은 tmux 세션명이 든 행으로만 한다. 행이 없으면 실패로 처리한다.
- **이름은 `--name`으로 고정한다.** `claude --name <이름>`이 주소록 행의 이름까지 고정하는 것이 실측됐다(2026-08-23). 지휘·작업 세션 모두 **tmux 세션명과 같은 값**을 준다 — 그러면 주소록 행의 이름과 `tmux ` 표기가 일치해 대상 판별이 한 겹 준다. 이름이 붙어도 **키는 여전히 tmux 세션명이고, 발신에는 ref를 붙인다** — 이름 고정은 판별을 쉽게 할 뿐 ref를 대신하지 않는다.
- **이름 상속을 끊는 변수는 `CLAUDE_JOB_DIR` 하나다.** 부모가 백그라운드 잡이면 이 변수를 물려받은 자식이 같은 잡의 일부로 취급돼 **부모의 주소록 이름을 뒤집어쓰고 `--name`이 무시된다.** 이분 탐색으로 확정된 결과이고, 종전에 이 자리가 지목하던 `CLAUDE_CODE_SESSION_ID`·`CLAUDECODE`는 **이 현상과 무관하다**(둘만 벗겨도 상속됐다). 그 둘은 세션 식별자가 자식에 흘러드는 것을 막으려 종전대로 함께 벗기되, **이름 상속을 막는 것은 `-u CLAUDE_JOB_DIR`이므로 이것을 빠뜨리지 않는다.** 일반 인터랙티브 세션에는 이 변수가 없어 함정은 창구가 백그라운드 잡일 때만 발동한다. **차단이 실패해도 오배송은 없다** — 이름은 애초에 키가 아니다.
- **창구에도 주소가 있다 — 창구가 자기 주소를 지휘에 넘긴다.** 창구는 tmux 세션이 아니어서 주소록에 `tmux ` 표기가 없고 **지휘가 주소록을 훑어 찾아낼 수는 없다.** 하지만 창구 자신의 `ListAgents` 출력 **첫 줄**에 `This session is <이름> [<ref>] …`로 자기 주소가 적혀 있으므로, 창구가 그 `<이름> [<ref>]`를 **지휘 스폰 첫 프롬프트에 실어 보내면** 지휘가 그 값으로 선발신할 수 있다("지휘 스폰 절차" 3번). 유휴 상태로 턴을 끝낸 세션도 발신 한 통으로 깨어난다(실측 11초).
  - **그래도 제어 통보의 정본은 알림 파일이다.** 발신은 **깨우기 신호**이고 내용의 정본이 아니다 — 창구 프로세스가 죽으면 발신은 닿을 데가 없지만 파일은 폴더에 남아 다음 창구가 줍는다. 역할 분담은 "사용자에게 닿는 통로"가 정본이다.
  - **주소를 받지 못한 지휘는 발신을 시도하지 않는다.** 첫 프롬프트에 창구 주소가 없으면(옛 세대의 재진입 등) 알림 파일만 쓰고 넘어간다 — 주소록에서 창구를 찾아 보내지 않는다.

> **Do:** 세션은 tmux 세션명과 같은 이름으로 고정해 띄우고, ref는 세션마다 한 번 맺어 발신 실패·무응답 재전송·세션 재기동 때만 다시 맺는다
> **Don't:** 보낼 때마다 주소록을 새로 훑거나, 세션을 다시 띄운 뒤에도 옛 ref를 그대로 쓰거나, 실패문의 대안 이름으로 다시 보내거나, 첫 프롬프트로 받지 않은 창구 주소를 주소록에서 찾아 보낸다

## 회신 변별자

**세션 간 모든 메시지는 첫머리에 변별자를 붙인다: `[<노드ID> g<세대>#<n>]`** (예: `[002-N4 g2#3] 완료 — ...`). 노드에 속하지 않는 제어 메시지(교체 요청 등)는 노드 ID 자리에 `cmd`를 쓴다(`[cmd g2#1]`).

- **세대**는 중계 상태 파일의 값이 단일 출처다. 작업 세션은 위임 메시지로 받아 쓴다.
- **`n`**은 발신 세션이 자기 발신마다 1부터 올린다. 세대가 붙으므로 교체 후 되감겨도 변별자는 유일하다.

목적은 둘이다.

1. **본문 상이화** — 같은 본문의 회신이 중복 차단에 걸려 **조용히 사라지고 발신자에게 실패로도 보고되지 않는 것**이 실측됐다(회신 1건 실제 유실). 변별자는 그 확률을 낮추는 조치이지 보장이 아니다.
2. **유실 탐지** — 받는 쪽은 일련번호의 공백을 유실로, 낮은 세대의 변별자를 이전 세대의 지연분으로 읽는다.

**변별자 없는 회신은 신뢰하지 않고 재발신을 요청한다.** 그리고 **`SendMessage`가 실패하면 같은 내용을 자기 알림 파일로 남긴다** — 작업 세션이 지휘에 보내는 방향의 폴백 채널이다. **지휘가 창구에 보내는 방향은 반대다** — 알림 파일이 **내용의 정본**이고 `SendMessage`는 **깨우기 신호**다. 둘은 갈음 관계가 아니다 — `SendMessage`만 보내고 알림 파일을 생략하지 않는다. 다만 창구 주소가 없거나 발신이 실패하면 파일만 남기고 넘어간다("사용자에게 닿는 통로"의 「깨우기 신호」 3번).

## 비가역 조작 경계

현행의 "되돌릴 수 없는 것은 사람이 직접"은 *옆에 사람이 있다*가 근거였다. 지휘가 무인이 되면 그 근거가 사라지므로 다시 가른다.

**지휘가 직접 하는 것 (가역).** 노드 브랜치 머지, 충돌 해소, DEV_PLAN·노드 문서 갱신과 로컬 커밋, 워크트리·tmux 정리. 가역인 근거는 노드 브랜치가 남아 있고 머지 커밋을 되돌릴 수 있다는 것이다.

**무인 머지의 사후 검증 3겹** — 하나도 생략하지 않는다.

1. **`--ff-only` 우선.** 이어붙이기가 안 되는 일반 머지에 코드 파일이 섞이면 **변경 범위 회귀를 1회** 돌린다. 코드 충돌을 지휘가 해소한 경우에도 면제되지 않는다.
2. **저장소 상태 가드** — 머지 전에 작업 트리가 clean한지, 기대한 브랜치에 서 있는지 확인한다.
3. **커밋 실재 검증** — 머지 후 `git merge-base --is-ancestor <노드브랜치> HEAD`로 그 브랜치가 실제로 조상에 들어왔는지 확인한다.

**지휘가 하지 않는 것 (비가역).** **통합 브랜치를 메인에 합치기**, 원격 올리기(`push` 자체), 배포, 데이터 이관, 저장소 밖 파일 삭제. 이것들은 **주체=사용자 노드로 남기고** 안내 + 완료 신고 경로로 처리한다. **버튼 승인으로도 풀지 않는다** — 사람이 원격에서 읽는 것은 잘린 요약뿐이라, 요약 승인으로 비가역을 여는 것은 관문의 취지를 버리는 것이다.

**볼트처럼 자동 push 잡이 도는 저장소에서는 시작부터 워크트리에서 돈다.** 지휘의 머지는 **통합 브랜치까지만** 간다 — 메인에 올리는 마지막 한 걸음이 사용자 노드로 남으면서 자동 push 경로 자체가 닫힌다.

> **Do:** 머지는 지휘가 하되 사후 검증 3겹을 매번 통과시킨다
> **Don't:** 지휘가 메인에 합치거나 push하거나, 버튼 승인으로 비가역을 연다

## 지휘 루프

지휘가 수행한다. DEV_PLAN이 `done`이 되거나 실행 가능 노드가 없을 때까지 아래를 반복한다. **화면 출력은 아무에게도 도달하지 않는다** — 창구에 보낼 제어 통보도 사용자에게 보일 질문·알림도 모두 우편함에 파일로 쓴다("사용자에게 닿는 통로").

**지휘의 작업 폴더는 저장소 밖이다.** DEV_PLAN·노드 문서는 첫 프롬프트로 받은 통합 워크트리 경로를 앞에 붙인 **절대경로**로 읽고 쓰며, git은 전부 `git -C <통합 워크트리>`로 부른다.

**창구가 올린 사용자 발화는 흘리지 않는다.** 창구에서 `[cmd g<세대>#<n>]`를 달고 오는 `SendMessage`는 사용자가 새로 낸 지적이지 지휘가 물은 것에 대한 답이 아니다("창구 절차" 7번). 처리 시점은 발화가 정한다 — **중단·방향 전환 지시면 진행 중인 노드를 회수한 뒤 곧바로, 그 밖이면 그 사이클을 마친 뒤** 처리한다. 반영은 `/dev`의 "반영·보고 선택 기준"으로 가르되, 진행 중인 노드에 닿는 발화는 그 노드를 계속 둘지 되돌릴지 판정해 **근거를 노드 표에 적고 커밋한다.** 처리가 끝나면 **무엇을 어떻게 반영했는지 1줄을 알림 파일로 창구에 되돌린다** — 창구는 전달만 하므로, 되돌리지 않으면 사용자는 자기 지시가 반영됐는지 알 방법이 없다.

1. **재진입 처리.** DEV_PLAN을 Read하고 상태가 `진행`인 노드가 있으면 `/dev`의 **"미회수 노드 재진입 분기"**를 먼저 돌린다 — 앞 세대가 보내 놓고 회수하지 못한 노드가 여기 걸린다. 위임처가 살아 있으면 회수부터 하고, 죽었으면 워크트리·브랜치를 보고 회수하거나 재위임한다.
2. **다음 노드 선정.** 노드 표에서 **선행이 모두 완료·건너뜀이면서 상태가 대기**인 노드를 찾는다. 그중 `조건` 칸이 채워진 노드는 선행 결과로 판정해 미선택 갈래를 `건너뜀`으로 바꾼다(`/dev` Phase 2의 분기 정리와 동일). 남는 노드가 없으면 → 대기 중인 사용자·외부 노드와 사용자 직접 접속으로 넘겨 `진행`에 머문 노드를 함께 창구에 알리거나, 완주를 보고하고 종료.
3. **위임 직전 검사·적립.** 노드를 시작하기 전에 순서대로 둘을 한다.
   1. **컨텍스트 임계 판정**(`/dev`) — 약한 임계를 넘었으면 **이 노드를 시작하지 않고 "교체 프로토콜" 1번으로 간다.** 계측이 연속 2회 실패해도 같다(약한 임계 도달로 간주하고 계측 불능을 창구에 함께 보고한다).
   2. **위임 시점 기록**(`/dev`의 "인수인계 상시 적립" 1번) — 노드 상태를 `진행`으로 바꾸고 위임할 tmux 세션명과 워크트리 경로를 노드 표에 적어 태그 없이 커밋한다. **기록이 위임에 선행한다.**
4. **노드 표의 `종류` 칸으로 분기**:
   - **디자인 노드·합류 노드** → 지휘가 `/dev`를 Skill로 호출하되 **args에 "노드 <ID> 1개만 처리하고 정지하라. 노드 표의 그 행만 갱신하고 다른 노드는 손대지 마라"를 명시한다**(`/dev`의 "단일 노드 실행"). 이 문구가 없으면 `/dev`가 Phase 2 전체를 돌며 준비된 노드를 전부 처리해 버린다. 합류 시 순서와 시안 확정 방법은 `/dev`가 가진다. **합류를 `/dev` 호출 없이 지휘가 직접 처리하지 않는다** — 남은 실질 작업이 전체 테스트 1회뿐이어도, 스킬 적재 비용이 더 커 보여도 예외를 만들지 않는다. 남은 작업의 양·비용은 이 갈래를 벗어날 근거가 되지 않는다.
   - **비가역 실행 노드** → 지휘가 처리하지 않는다. "비가역 조작 경계"에 따라 주체를 사용자로 되돌리고 안내한 뒤 그 노드를 `진행`으로 두되 **위임처 칸은 비워 두고** 넘어간다.
   - **그 외 노드(조사·연구·설계·구현)** → 아래 "세션 위임"을 실행한다. 실행 가능한 노드가 여럿이면 위 동시 실행 조건에 맞는 것끼리 최대 3개까지 동시에, 아니면 표의 위쪽 것부터 하나씩. **구현 노드를 2개 이상 동시에 띄우려면 그 노드 전체를 선행으로 삼는 합류 노드(종류=실행, 주체=메인)가 DEV_PLAN에 있어야 한다** — 계획이 직렬로 그려 둔 노드를 지휘 판단으로 동시에 돌리는 경우가 여기 걸린다. 없으면 지휘가 노드 표·흐름도에 합류 노드를 추가하고 커밋한 뒤 시작한다. 노드별 머지는 "세션 위임" 6번에서 이미 끝나므로, 그 합류 노드로 `/dev`를 호출할 때 args에 "브랜치는 이미 통합 브랜치에 병합됐으니 「병렬 구현 노드의 격리와 합류」 4번의 1(브랜치 머지)을 생략하고 2(전체 스위트)부터 수행하라"를 명시한다.
5. **회수·갱신.** `nodes/<노드ID>.md`를 Read해 `## 계획 변경 제안`과 발견된 후속·유보 항목을 **`/dev`의 "반영·보고 선택 기준"으로 가른다** — 계획 구조를 바꾸는 것은 DEV_PLAN에 반영하고, 그 노드 안에서 닫힌 것은 창구에 1줄 보고만 하며, 애매하면 반영한다. 이어서 노드 표의 상태를 `완료`로 바꾸고 작업 세션이 보고한 산출 경로와 판정 근거를 적는다. 갱신 직후 태그 없이 커밋한다(`/dev`의 "인수인계 상시 적립" 2번). 전 노드가 완료·건너뜀이면 `status: done`.
6. **다음 사이클.** 1번으로 돌아간다. **개수로 정지하지 않는다** — 정지·교체 판정은 3번의 임계 판정 한 곳에서만 난다.

> **Do:** 위임 직전에 임계를 재고 기록을 남긴 뒤에 보낸다
> **Don't:** 배포·데이터 이관·메인 머지를 지휘나 작업 세션이 실행하거나, 합류 노드 없이 구현 노드를 동시에 띄우거나, 합류를 `/dev` 호출 없이 직접 처리한다

## 세션 위임

`<세션명>`은 `~/.claude/scripts/dev-view.sh --name <노드ID> <통합 워크트리 절대경로>`가 출력하는 값이다(`dev-<프로젝트 슬러그>-<노드 ID 소문자>` 형태). 노드마다 이 명령으로 한 번 얻어 그 노드의 모든 tmux 명령에 쓴다 — 이름을 직접 지어 쓰지 않는다. **두 번째 인자를 빠뜨리지 않는다** — 지휘의 cwd는 저장소 밖 전용 폴더라 슬러그를 뽑을 데가 없고, 넘기지 않으면 스크립트가 이름을 내지 않고 거절한다. 프로젝트 이름이 들어가므로 다른 프로젝트가 같은 노드 ID를 돌려도 세션이 겹치지 않는다.

**지휘는 저장소 밖에서 도므로 아래의 모든 git 명령에 `-C <통합 워크트리 절대경로>`를 붙인다.** cwd가 저장소 안이라고 가정하는 형태로 쓰지 않는다.

1. **워크트리 준비.** `git -C <통합 워크트리> worktree add <경로> -b node/<노드ID>`. 동시 실행이어도 **하나씩 순차로** 만든다 — 동시에 만들면 저장소 설정 파일이 잠금을 다툰다. 중단된 노드를 재개하는 것이면 `git worktree list`로 기존 워크트리를 찾아 그대로 재사용한다.
2. **세션 생성.** 전 계층 공통 스폰 인자를 붙인다 — 환경 격리(`env -u`)·무인 진행(`bypassPermissions`)·MCP 차단(`--strict-mcp-config`).

   ```bash
   tmux new-session -d -s <세션명> -c <워크트리 절대경로> \
     "env -u CLAUDE_JOB_DIR -u CLAUDE_CODE_SESSION_ID -u CLAUDECODE CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false claude \
        --name <세션명> \
        --permission-mode bypassPermissions --strict-mcp-config"
   ```

   **`-u CLAUDE_JOB_DIR`과 `--name`을 빠뜨리지 않는다** — 이름 상속을 막는 것은 그 변수 하나이고, 이름을 tmux 세션명과 같게 고정해 두어야 3번의 주소 확보에서 행을 바로 짚는다("세션 주소 규약").

   화면에 뜨지 않고 백그라운드에서 돈다. 작업 세션은 프로젝트 지시문과 전체 스킬이 필요하므로 **지휘의 경량화 구성(전용 폴더·`--setting-sources project`)을 적용하지 않는다.** 생성 직후 `~/.claude/scripts/dev-view.sh`를 인자 없이 실행해 작업 세션 화면을 분할 창에 비춘다 — 첫 호출이 창을 열고, 이후 호출은 그때 살아 있는 작업 세션에 pane을 맞춘다(다른 프로젝트의 세션도 함께 뜬다). **뷰어 호출이 실패해도 위임은 그대로 진행한다** — 뷰어는 읽기 전용 미러라 노드 처리와 무관하다. 반면 `tmux new-session` 자체가 실패했으면 세션이 없는 것이므로 3번으로 가지 않고 Fallback으로 간다.

> **Do:** 세션을 만든 뒤·정리한 뒤에 인자 없이 불러 뷰어가 스스로 목록을 잡게 한다
> **Don't:** 세션명을 인자로 넘기거나, 뷰어 pane을 직접 만들고 지운다
3. **주소 확보.** `ListAgents`로 `tmux <세션명>:`을 포함한 행을 찾아 `<이름> [<ref>]`를 통째로 얻는다. **`tmux ` 표시가 없는 행은 읽지 않는다** — 주소록의 대부분은 Remote Control 잔재라 대상이 될 수 없다. **발신에는 반드시 ref를 붙인다** — 이름만으로는 거부된다. 등록에 몇 초 걸리므로 첫 조회에 없으면 1회 더 조회하고, 그래도 없으면 Fallback으로 간다. **여기서 맺은 ref는 이 노드가 끝날 때까지 그 세션에 계속 쓴다 — 발신 실패·무응답 재전송·세션 재기동 때만 다시 맺는다**("세션 주소 규약").
4. **위임.** 아래 "위임 메시지"를 `SendMessage`로 보낸다.
5. **대기·검증.** 답신이 오면 워크트리에서 `git log -1 --format=%H`로 커밋을, 보고에 산출 경로가 있으면 그 파일 실재를 확인한다. **검증은 여기까지다 — 지휘는 테스트를 돌리지 않는다.** 작업 세션이 `/impl` 안에서 이미 회귀·끝단 검증을 마쳤으므로 같은 트리를 다시 검사하는 셈이다. 대신 **보고의 검증 결과가 실패·중단이면 커밋과 산출 파일이 있어도 완료로 처리하지 않고** 노드 상태를 `실패`로 두고 창구에 1줄 보고한다. 결과 줄이 아예 없는 보고도 통과로 보지 않고 그 한 줄만 재요청한다. 다만 `검증:` 값이 `해당 없음`·`중단: 적용 가능한 테스트 없음`인데 그 노드가 코드를 고친 노드면, 아무 검증도 돌지 않은 것이므로 지휘가 변경 범위 회귀를 1회 돌린다. **답신 없이 10분이 지나면** `tmux capture-pane -t <세션명> -p | tail -20`으로 화면을 본다 — 작업 중이면 계속 대기, 멈춰 있으면 **"세션 주소 규약"에 따라 ref를 다시 맺은 뒤** "진행 상황을 SendMessage로 보고하라"를 1회 재전송한다 — 세션은 살아 있는데 발신만 삼켜진 경우가 여기서 풀린다. 재전송 후 10분이 더 지나도 커밋·답신이 없으면 노드 상태를 `실패`로 두고 Fallback으로 간다.
6. **머지·정리.** 검증되면 지휘가 `node/<노드ID>`를 **통합 브랜치**에 머지한다. **"비가역 조작 경계"의 사후 검증 3겹을 매번 통과시킨다** — 머지 전 저장소 상태 가드(트리 clean·기대 브랜치), `--ff-only` 우선, 머지 후 `git merge-base --is-ancestor`로 커밋 실재 확인. `--ff-only`가 **통과하면 머지 결과가 작업 세션이 검증한 트리와 같으므로 테스트를 돌리지 않는다.** 거절되면 통합 브랜치가 앞서 있는 것이니 `git diff --name-only node/<노드ID>...HEAD`(분기 이후 통합 브랜치에만 들어온 변경)로 코드 파일에 닿는지 본다 — DEV_PLAN·`nodes/*.md` 등 문서뿐이면 그대로 머지하고 재실행하지 않고, 코드에 닿았으면 머지 후 **변경 범위 회귀만 1회** 돌린다(전체 스위트·e2e는 합류 노드가 담당한다). 충돌은 지휘가 해소하되 그 경우에도 변경 범위 회귀 1회는 면제되지 않는다. DEV_PLAN·`nodes/<ID>.md`가 충돌하면 통합 브랜치 쪽을 남긴다. 머지가 끝나면 `tmux kill-session -t <세션명>`과 `git worktree remove`로 정리하고, `~/.claude/scripts/dev-view.sh --sync`를 인자 없이 실행해 뷰어에서 그 pane을 거둔다. 도는 세션이 하나도 없으면 창은 마지막 화면을 유지하고 다음 노드가 뜰 때 갱신된다.

> **Do:** 이어붙이기로 머지되면 그대로 넘어가고, 코드 파일이 섞였거나 충돌을 해소했으면 변경 범위를 다시 본다
> **Don't:** 답신 도착만으로 완료 처리하거나, 작업 세션에 머지를 시키거나, 세션이 이미 검증한 트리에 스위트를 다시 돌린다

## 사용자에게 닿는 통로

**지휘 앞에는 사람이 없다.** 화면 출력은 아무에게도 도달하지 않으므로, 사람에게 닿아야 하는 것은 아래 둘 중 하나로 보낸다.

| 통로 | 무엇을 | 어떻게 |
|---|---|---|
| **창구** | 교체 요청·계측 불능·완주 보고 등 제어 | **자기 우편함의 알림 파일이 정본이다** — 교체 요청·계측 불능·우체부 재기동 요청은 `kind`를 `alert`로, 완주 보고는 `done_report`로 쓰고 변별자 `[cmd g<세대>#<n>]`를 붙인다. 창구가 그 파일을 훑는다("창구 절차" 7번). **파일을 쓴 직후 창구를 깨운다** — 아래 「깨우기 신호」 |
| **알림·질문 파일** | 사용자에게 물을 질문, 사용자가 알아야 할 사건 | 세션별 우편함에 파일로 쓴다. 우체부가 읽어 텔레그램으로 보내고, 답을 그 세션 화면에 다시 넣는다 |

- **사용자에게 물을 질문은 지휘가 올린다. 창구는 질문 파일을 쓰지 않는다.** 답은 질문을 쓴 쪽 우편함에만 떨어지므로 중계 단계가 없는 쪽이 유실 지점이 하나 적다. 창구가 지휘의 질문을 받아 자기 우편함에 다시 올리면 같은 질문의 버튼이 두 벌 나가고, 답은 누른 쪽에만 떨어져 반대쪽은 영영 깨어나지 않는다. **금지되는 것은 창구가 질문 파일을 쓰는 것뿐이다** — 창구가 사용자에게 낼 알림 등 `sessions/counter/`의 알림 파일은 그대로 쓴다.
- 알림 파일은 **텍스트만** 쓴다(버튼 없음). 선택지를 붙이려면 질문 파일에 적는다 — 이름·필드 규약은 아래 「우편함 파일 규약」이 유일한 상세 서술이다.
- **한 파일에 쓰는 주체는 하나다.** 세션은 자기 우편함의 알림·질문과 응답 표식만 쓰고, 답과 보관분은 우체부가 쓴다. 읽기는 이 제한을 받지 않는다 — 창구는 지휘 우편함을 읽는다.
- **제어 통보는 우체부 프로세스와 무관하게 선다.** 창구가 지휘 우편함의 파일을 직접 읽으므로 우체부가 죽어 있어도 교체·완주가 막히지 않는다. 우체부가 더하는 것은 같은 파일의 텔레그램 사본뿐이다.
- **우체부가 살아 있는지 먼저 본다.** 노드 경계와 질문 파일을 쓰기 직전에 heartbeat가 15분 이내인지 확인하고, 부실하면 창구에 재기동을 요청한다. **그래도 질문 파일은 그대로 쓴다** — 파일은 남으므로 우체부가 돌아오면 발신된다.
- 우체부가 설치되지 않은 프로젝트에는 **알림·질문 파일 통로가 없다.** 제어 통보는 그대로 파일로 쓰고(창구가 읽는다), 사용자에게 보일 것은 창구가 화면에서 전달한다.

**깨우기 신호 — 알림 파일은 내용, `SendMessage`는 깨우기.** 창구는 턴이 끝나면 아무것도 훑지 않으므로, 파일만 남기면 사용자가 화면 앞에 돌아올 때까지 통로가 멎는다. 둘의 역할을 갈라 쓴다.

1. **먼저 알림 파일을 쓴다.** 이것이 내용의 정본이다. 순서를 뒤집지 않는다 — 발신이 먼저 닿으면 깨어난 창구가 훑을 파일이 아직 없어 헛걸음한다.
2. **그다음 첫 프롬프트로 받은 창구 주소로 `SendMessage`를 한 통 보낸다.** 담을 것은 **변별자와 한 줄 요약뿐**이고 통보 본문을 옮겨 싣지 않는다 — 창구는 그 변별자로 우편함의 같은 파일을 찾아 처리하고, 이미 처리한 변별자는 다시 처리하지 않으므로 중복 실행이 생기지 않는다("창구 절차" 7번).
3. **발신이 실패하거나 창구 주소를 받지 못했으면 그대로 넘어간다.** 창구가 죽었거나 옛 세대의 재진입인 경우이고, **파일은 남아 다음 창구가 줍는다.** 실패를 사유로 재시도를 돌리거나 주소록에서 창구를 찾아 보내지 않는다("세션 주소 규약").

> **Do:** 질문 파일은 지휘만 쓰고, 창구는 지휘의 질문 문장을 화면으로 전달만 하며, 제어 통보는 파일을 쓴 직후 깨우기 발신을 한 통 붙인다
> **Don't:** 창구가 같은 질문을 자기 우편함에 다시 올려 버튼을 두 벌 내보내거나, 지휘가 제어 통보를 `SendMessage`로만 보내고 알림 파일을 남기지 않거나, 깨우기 발신에 통보 본문을 실어 파일과 두 벌로 흐르게 한다

### 우편함 파일 규약

**이름과 필드는 우체부의 계약이다** — 지어낸 이름은 우체부의 훑기에 걸리지 않아 **조용히 사라진다.** 정본은 `skills/postman/README.md`의 「세션이 우체부에게 말하는 법」이고, 여기서는 쓸 때 필요한 최소만 적는다. 우편함은 `~/.claude/postman/sessions/<자기 tmux 세션명>/`이고, 창구는 tmux 세션이 아니라 `sessions/counter/`에 쓴다. **창구가 읽는 자리는 그곳이 아니다** — 지휘 우편함(`sessions/dev-cmd-<프로젝트슬러그>/`)을 훑는다.

**알림** — `notify-<밀리초>-<난수6>.json`

```json
{"text": "노드 002-N4B 완료 — 커밋 3519d2a", "kind": "notify"}
```

`kind`는 `notify`·`alert`·`done_report` 셋 중 하나이고 생략하면 `notify`다. **`alert`와 `done_report`만 연성 발신 상한을 면제받는다** — 사람이 붙어야 풀리는 통보(`[대화 필요]`의 attach 안내 등)와 **창구로 가는 제어 통보**(교체 요청·계측 불능·우체부 재기동 요청은 `alert`, 완주 보고는 `done_report`)는 `notify`로 쓰지 않는다. `buttons`를 넣어도 버려진다.

**질문** — `question-g<세대>-NN.json` (`NN`은 그 세대 안의 일련번호, 1부터)

```json
{"text": "[002-N4B g2#3] 이 노드를 계속 진행할까요?",
 "question": "이 노드를 계속 진행할까요?",
 "choices": ["진행", "중단"], "node": "002-N4B"}
```

- **이미 있는 파일이 어느 세대 것인지는 이름이 정본이다.** 본문 필드가 이름과 어긋나도 이름을 믿는다 — 이름이 곧 세대 간 덮어쓰기 방지 장치다. (새로 쓸 세대 **값**의 출처는 「회신 변별자」의 중계 상태 파일이다. 판별과 작성은 다른 시점이라 둘은 충돌하지 않는다.)
- `text`가 텔레그램에 나가는 본문(변별자를 세션이 붙인다), `question`은 **주입 직전 화면에 그 질문이 아직 열려 있는지 대조하는 재료**다. 생략하면 `text`로 대조하므로, 변별자가 섞인 `text` 하나만 두면 대조가 어긋난다 — **둘 다 적는다.**
- `choices`가 인라인 버튼이 된다(최대 8개).
- 발신 뒤에도 원본은 그대로 남고 `.sent` 표식만 붙는다. 답이 오면 같은 좌표에 `answer-g<세대>-NN.json`이 생기지만 **이 파일은 사후 기록이지 답 도착의 증거가 아니다** — 주입이 성공해도 우체부의 반영 확인이 실패했거나 기록 쓰기가 실패하면 파일이 생기지 않는다.
- **답 도착의 정본은 대상 세션 화면이다.** `tmux capture-pane -p -S -120 -t <세션명>`에서 선택지 문구를 찾아 확인한다. **어떤 세션도 `answer-g<세대>-NN.json`의 생성에 대기를 걸지 않는다** — 이 파일을 기다리는 세션은 답이 화면에 들어온 뒤에도 영영 깨어나지 않는다.
- **답을 받아 처리한 직후 응답 표식을 남긴다** — 그 질문 파일 이름 뒤에 `.answered`를 붙인 파일에 `{"ts": <시각>}`을 쓴다(`question-g2-03.json.answered`). 우체부가 중복 주입을 막고 반영을 확인하는 1차 근거이고, 빠뜨리면 우체부는 화면 판정으로 내려선다. **표식은 600으로 남긴다** — 리다이렉션·편집기로 바로 만들면 644가 되고, 우체부는 어긋난 권한을 **검출만 하고 고치지 않는다.** 자리를 먼저 잡고 채운다.

  ```bash
  install -m 600 /dev/null <질문 파일 경로>.answered   # 그 뒤 리다이렉션으로 채운다 — 권한은 그대로 남는다
  ```

  형식 정본은 `skills/postman/README.md`의 「답을 받았다고 알리는 법 — 응답 표식」이다.

> **Do:** 이름은 위 형식 그대로 쓰고, 질문에는 `text`와 `question`을 둘 다 적고, 답을 처리한 직후 응답 표식을 600으로 남긴다
> **Don't:** 대기 해제성 통보를 `kind` 없이 쓰거나, 세대를 본문 필드로만 적거나, `answer-g<세대>-NN.json`이 생기기를 기다리거나, 답을 받기 전에 응답 표식을 미리 남기거나, 644로 두고 우체부가 고쳐 줄 것으로 기대한다

## 사용자 개입

**어느 방식이 필요한지는 작업 세션이 판정해 태그로 알린다.** 지휘는 태그로 라우팅한다.

- `[결정 필요]` — 선택지가 정해져 답 하나로 진행되는 질문. 지휘가 위 통로로 사용자에게 전달하고 답을 세션에 되돌린다.
- `[대화 필요]` — 요구사항·범위를 캐야 해서 되묻기가 이어질 질문. 중계하지 않는다. **`tmux attach -t <세션명>`으로 직접 이어가야 한다는 안내를 알림 파일로 남기고**, 그 노드를 `진행`으로 두고 다른 실행 가능 노드로 넘어간다. 사용자가 자리에 없으면 그 노드는 사람이 붙을 때까지 그 상태로 있는다 — **화면에만 안내를 뿌리고 답을 기다리지 않는다.**

**같은 노드에서 `[결정 필요]` 왕복이 3회를 넘으면** 세션의 판정이 틀린 것으로 보고 `[대화 필요]`와 같이 처리한다. 사용자가 마쳤다고 알리면 "세션 위임" 5번(검증)부터 재개한다.

> **Do:** 라우팅은 태그로 하고, 왕복이 3회를 넘으면 세션의 판정을 뒤집는다
> **Don't:** 세션의 질문을 지휘가 임의로 답하거나, 자리에 없는 사용자에게 화면 안내를 남기고 대기한다

## 후속 소진 (`--followup`)

`/dev` Phase 3의 묶음 소진을 tmux 작업 세션 병렬 위임으로 돌린다. **노드 표가 없고 후속 항목 대장(`docs/dev/plan/FOLLOWUP.md`)의 묶음 표가 그 자리를 대신한다** — "지휘 루프"의 노드 선정·분기 정리는 이 분기에 적용하지 않고, "세션 위임"·"교체 프로토콜"·"세션 주소 규약"·"회신 변별자"·"비가역 조작 경계"·"사용자에게 닿는 통로"·"사용자 개입"은 노드를 묶음으로 바꿔 그대로 쓴다. **치환이 성립하지 않는 자리는 다섯이다.** 그 밖의 서술은 노드를 묶음으로 바꿔 그대로 읽는다.

| 자리 | 노드 경로 | 후속 경로 |
|---|---|---|
| 「미회수 노드 재진입 분기」 1번 | 위임처 빈칸 = 사람 대기 | 대응 개념이 없다 — 빈칸은 **기록 누락**이다. 대기하지 말고 워크트리·브랜치·산출 파일을 보아 회수하거나 재위임한다 |
| 「지휘 루프」 2번 | 선행·`조건` 칸으로 분기 정리 | 묶음 표에 두 칸이 없다 — 「후속 소진 루프」 3번의 착지 파일 교집합 재확인이 그 자리를 대신한다 |
| 「지휘 루프」 4번 | `종류` 칸으로 디자인·합류·비가역 갈래를 가른다 | 묶음은 전부 `/impl` 한 갈래다. 배포·운영 성격 항목은 정리 게이트가 보류로 빼므로 비가역 갈래가 오지 않는다 |
| 「지휘 루프」 5번 끝 | 전 노드 완료 시 `status: done` | 대장에 그 필드가 없다 — 「후속 소진 루프」 도입부의 반복 종료 조건(`대기`·`진행` 묶음 0)이 완주 판정이다 |
| 「지휘 루프」 4번의 합류 노드 | 합류 노드가 전체 스위트·e2e를 맡는다 | **합류 묶음이 없다.** 동시 실행 시 작업 세션의 e2e를 끄게 하므로 끝단 검증을 아무도 하지 않는다 — 「후속 소진 루프」 2번이 그런 묶음을 단독으로 돌려 막는다 |

**3단계 분업.**

| 단계 | 주체 | 내용 |
|---|---|---|
| 1. 수확 | **창구 직접** | `/dev` Phase 3-1 |
| 2. 정리 게이트·묶음 편성 | **창구 직접** | `/dev` Phase 3-2·3-3 |
| 3. 묶음 소진 | **지휘 → 작업 세션 병렬** | 묶음마다 워크트리 + tmux 세션 + `/impl` |

1·2단계는 항목 단위 승인 왕복이라 사용자와 붙은 창구가 쥔다. 창구가 지휘에게 넘기는 것은 **대장 절대경로와 승인 범위 두 줄**이고 대장 본문을 발췌해 싣지 않는다. 지휘가 교체돼도 새 지휘는 같은 두 줄만 받는다.

> **Do:** 사용자 승인이 걸린 수확·게이트·편성은 창구가 하고, 지휘에게는 확정된 대장 경로와 승인 범위만 넘긴다
> **Don't:** 수확부터 지휘에 맡겨 승인 질문을 창구 경유로 중계한다

### 후속 소진 절차

창구가 수행한다.

1. **수확·정리 게이트·묶음 편성.** `/dev`를 Skill로 `--followup`으로 호출하고 args에 **"Phase 3의 3번(묶음 편성)까지만 수행하고 4번(실행·갱신)에는 들어가지 말고 정지하라"**를 명시한다. 이 문구가 없으면 `/dev`가 묶음을 직접 소진해 버려 지휘가 할 일이 남지 않는다. 대장이 이미 있을 때의 재개·재수확 판정은 `/dev` Phase 3이 가진다.
2. **우체부 기동** — "창구 절차" 3번과 같다.
3. **스폰 전 최소 검사** — "창구 절차" 4번과 같다. 둘째 항목 "DEV_PLAN 경로 실재"는 **대장 경로 실재**로 읽는다.
4. **통합 워크트리 준비** — "창구 절차" 5번과 같고 브랜치명만 `integration/followup-<대장 수확일에서 숫자만 남긴 8자리>`로 한다.
5. **지휘 스폰** — "지휘 스폰 절차"를 그대로 쓰되 첫 프롬프트의 스킬 호출을 `/dev-loop --commander <대장 절대경로> --followup`으로 넣고, 통합 워크트리 경로·세대·창구 주소에 더해 **승인 범위 한 줄**(어느 묶음까지 승인됐는지)을 담는다. 중계 상태 파일의 `dev_plan`에는 대장 경로를 적는다. **"교체 프로토콜"의 재스폰도 같은 첫 프롬프트를 쓴다** — `--followup`이 빠지면 새 지휘가 노드 루프로 들어가 대장을 읽지 않는다. 재사용하는 첫 프롬프트와 준비 신호 확인 문구의 "노드"는 "묶음"으로, "지휘 루프"는 "후속 소진 루프"로 바꿔 쓴다.
6. **대기·정리** — "창구 절차" 7·8번과 같다.

### 후속 소진 루프

지휘가 수행한다. 대장의 묶음 표에 상태가 `대기`·`진행`인 묶음이 없을 때까지 아래를 반복한다. **지휘의 작업 폴더는 저장소 밖이다** — 대장·출처 계획서는 첫 프롬프트로 받은 통합 워크트리 경로를 앞에 붙인 절대경로로 읽고 쓰며, git은 전부 `git -C <통합 워크트리>`로 부른다.

1. **재진입 처리.** 상태가 `진행`인 묶음이 있으면 `/dev`의 **"미회수 노드 재진입 분기"**를 노드 대신 묶음에 적용하되, 위임처 빈칸의 해석은 "후속 소진 (`--followup`)"의 치환 대조표를 따른다. 위임처가 살아 있으면 회수부터 하고, 죽었으면 `node/<묶음ID>` 브랜치의 커밋이나 `nodes/<묶음ID>.md`가 있는지 본다 — 있으면 그것을 산출로 보아 회수·검증부터 재개하고, 둘 다 없으면 재위임한다.
2. **병렬 폭 결정.** **기본 3.** 아래 조건에서만 옮긴다.
   - **2로 내린다** — 묶음에 크기 `중`·`대`가 섞였을 때, 또는 지휘의 입력 토큰이 **150,000을 넘었을 때**. 회수 한 건마다 지휘 컨텍스트가 늘므로 약한 임계에 닿기 전에 폭을 줄여 진행 중인 묶음을 다 회수하고 나갈 여지를 남긴다. **아래 4 조건과 동시에 성립하면 2가 이긴다.**
   - **4로 올린다** — 2 조건에 해당하지 않으면서, 동시에 띄울 묶음이 전부 `기능 외`이고 `/impl` 크기가 `소`로 예상되며, 착지 파일이 순수 단위 테스트만 건드릴 때.
   - **1(단독)로 내린다** — 그 묶음이 끝단 검증(e2e)을 거쳐야 할 때. 동시 실행이면 작업 세션의 e2e를 끄게 되는데 후속 경로에는 그것을 대신 돌릴 합류 묶음이 없다. 필요 여부는 `/impl`의 "검증 단계 유무 판정"이 가리는 대로 따른다.
   - **5 이상은 두지 않는다.**
3. **묶음 선정·교집합 재확인.** 상태가 `대기`인 묶음을 표 위쪽부터 폭만큼 고르고, **동시에 띄울 묶음끼리 착지 파일 교집합을 위임 직전에 다시 확인한다** — 겹치면 뒤 묶음을 다음 사이클로 미룬다. 고아 항목 합본 묶음은 파일이 흩어져 있어 편성 시점에 없던 겹침이 여기서 드러난다.
4. **위임 직전 검사·적립.** "지휘 루프" 3번과 같다 — 컨텍스트 임계 판정(약한 임계를 넘었으면 위임하지 않고 "교체 프로토콜" 1번으로) 후, 묶음 상태를 `진행`으로 바꾸고 `위임처`·`워크트리` 칸을 채워 태그 없이 커밋한다. **기록이 위임에 선행한다.**
5. **위임.** "세션 위임" 1~4번을 묶음 단위로 수행한다. 세션명은 `~/.claude/scripts/dev-view.sh --name <묶음ID> <통합 워크트리 절대경로>`로 얻고 브랜치는 `node/<묶음ID>`다. 보낼 것은 아래 "후속 묶음 위임 메시지"다.
6. **회수·검증·머지.** "세션 위임" 5·6번과 같다. 산출 파일 실재 확인 대상은 `nodes/<묶음ID>.md`다. **재전송 후에도 답신이 없어 묶음을 `실패`로 두려는 시점에, 실패로 두기 전에 이 파일이 브랜치에 있는지 먼저 본다** — 있으면 그것을 산출로 보아 검증을 진행한다.
7. **대장·출처 갱신.** 먼저 `nodes/<묶음ID>.md`를 Read해 발견 사항·항목 보완 제안·리뷰어 비차단 지적을 **`/dev`의 "반영·보고 선택 기준"으로 가른다** — 대장의 "소진 중 발견된 신규 후속 항목"에 등재할 것은 등재하고, 그 묶음 안에서 닫힌 것은 창구에 1줄 보고만 하며, 애매하면 등재한다. 이어서 묶음 상태를 `완료`로 바꾸고 `위임처`·`워크트리` 칸을 비운 뒤, 출처 계획서의 해당 항목을 닫고 커밋한다. **대장과 출처 계획서는 지휘만 쓴다** — 병렬 묶음이 각자 고치면 머지마다 충돌한다. `/impl`이 승인 범위 밖이라며 되돌려 보낸 기능 추가는 대장에 `보류(미승인)`으로 **적기만 하고 즉시 창구에 올리지 않는다.** 소진이 끝나거나 교체될 때 한 번에 보고하고, 승인은 다음 `--followup` 호출의 정리 게이트가 처리한다.
8. **다음 사이클.** 1번으로 돌아간다. **정지는 토큰 절대량 단독 판정이다** — `/dev` Phase 3의 "묶음 무게" 판정을 쓰지 않는다. 병렬에서는 여러 묶음이 한꺼번에 끝나 방금 마친 묶음의 무게로 다음을 가를 수 없다. 약한 임계(200,000)에서 새 묶음을 위임하지 않고 진행 중인 것만 회수하며, 강한 임계(300,000)에서 위임처를 대장에 남긴 채 나간다.

> **Do:** 대장과 출처 계획서는 지휘가 통합 워크트리에서만 고치고, 위임 직전에 착지 파일 교집합을 다시 본다
> **Don't:** 작업 세션에 대장·출처 계획서를 갱신시키거나, 되돌려 보낸 기능 추가를 그때그때 창구에 올리거나, 묶음 무게로 정지를 판정하거나, 발견 사항을 대장에 등재하지 않고 창구 보고로만 넘긴다

### 후속 묶음 위임 메시지

"위임 메시지"를 쓰되 아래 넷을 바꾼다. `[환경 — 반드시 준수]`의 나머지 줄과 `[사용자 개입]`은 그대로다.

- `[역할]` — "너는 후속 묶음 `<묶음ID>` 전담 세션이다. Skill 도구로 `/impl`을 호출해 아래 항목을 구현한다." 노드 분기 두 줄은 넣지 않는다.
- `[환경 — 반드시 준수]`의 "DEV_PLAN은 읽기 전용이다" 줄을 **"후속 항목 대장과 출처 계획서는 읽기 전용이다. 항목을 닫거나 대장을 고치지 마라. 항목을 더 손봐야 한다고 판단하면 완료 보고에 적어라"**로 바꾼다.
- `[완료 보고]` 맨 앞에 **"회귀까지 마친 뒤 `docs/dev/plan/nodes/<묶음ID>.md`를 워크트리 안에 Write해 최종 커밋에 함께 넣고, 그다음 SendMessage로 보고하라"**를 넣는다. 담을 것은 항목별 처리 결과 · 착지 파일 밖 발견 사항 · 항목 보완 제안 · 리뷰어 비차단 지적이다. **이 파일이 정본이고 회신은 그 요약이다** — 회신이 유실돼도 파일은 브랜치에 남아 지휘가 줍는다.
- `[입력]`을 아래로 바꾼다.

```
- 묶음 항목 원문: <대장 그 묶음 행의 항목 전문>
- 착지 파일: <대장 `착지 파일` 칸 — 이 밖의 파일은 수정하지 말고 발견 사항으로만 보고하라>
- 출처 계획서 경로: <경로 — 읽기 전용>
- 승인 범위: 이 묶음 항목 밖의 기능 추가는 구현하지 말고 후속 작업으로 되돌려 보고하라
- 대장 경로: <FOLLOWUP.md 절대경로>
- 세대: <중계 상태 파일의 generation 값 — 변별자에 쓴다>
- 알림 파일 경로: <이 세션의 우편함 디렉토리 — 우체부가 없는 프로젝트면 "없음">
- 동시 실행 여부: <2개 이상 동시면 "evaluator·e2e는 돌리지 말고 통합 code-reviewer 통과 시점에 종료하라">
```

## Fallback

**작업 세션 위임 실패.** 어느 단계든 실패하면(워크트리 생성 거부·세션 미등록·재촉 후에도 진전 없음) **1회 재시도**하고, 그래도 실패하면 그 노드에 한해 **지휘가 직접 처리**한다(구현이면 `/impl`, 그 외면 `/dev`). 넘어가기 전에 그 노드로 만든 tmux 세션을 종료하고, 커밋이 없는 워크트리는 제거한다. "세션 위임 실패 → 노드 <ID>는 지휘 직접 처리" 1줄을 창구에 보고한다. 컨텍스트 격리는 포기하되 진행은 보장한다. 다음 노드는 다시 세션 위임을 시도한다.

**지휘 스폰 실패.** "지휘 스폰 절차"의 폴백 구성으로 1회 재시도한다. 그래도 실패하면 **창구가 지휘 역을 겸해 "지휘 루프"를 직접 돈다** — 계층 분리와 무한 루프는 포기하되 계획 진행은 보장한다. 이 경우 임계에 닿으면 교체 대신 정지하고 "새 세션에서 `/dev-loop --resume <DEV_PLAN 경로>`로 이어가세요"를 안내한다. 사용자에게 겸직 사실을 1줄 알린다.

## 주의사항

- 노드 실행 로직을 `/dev-loop`에 복제하지 않는다 — 작업 세션이 `/dev`·`/impl`을 호출하게 하고, 본 스킬은 세션 생성·중계·상태 갱신만 한다.
- **인수인계·커밋·태그는 `/dev`의 "인수인계 상시 적립"을 따른다** — 위임 직전·회수 직후·결정 시점에 경로를 지정해 태그 없이 커밋하고, `git add -A`를 쓰지 않으며, SHA를 계획서에 적지 않는다.
- **자기 개조는 즉시 반영되지 않는다.** 이 스킬 파일을 노드에서 고쳐도 워크트리 안에서만 바뀌고, 돌고 있는 세션은 메인 워킹트리의 원본을 쓴다. 머지 뒤에 뜨는 세션부터 새 본문으로 돈다.
- 정지·완료로 끝내기 전에 `tmux list-sessions`·`git worktree list`로 이번 호출에서 만든 세션과 `node/*` 워크트리를 확인한다. **정리 대상은 이 프로젝트 접두사(`dev-<프로젝트 슬러그>-`)를 가진 세션뿐이다** — 다른 프로젝트의 `dev-*` 세션은 건드리지 않는다. 머지된 것은 제거하고, 미커밋·미머지로 남은 것은 경로와 사유를 사용자에게 보고한다. 정리가 끝나면 `~/.claude/scripts/dev-view.sh --close`를 실행한다 — 다른 프로젝트 작업 세션이 남아 있으면 스크립트가 닫기를 거부하고 그 목록을 알리는데, 이때는 창을 그대로 두고 넘어간다.
- 분할 창은 스냅샷을 비추는 읽기 전용이다. 작업 세션에 직접 입력이 필요하면 **사용자가** 별도 창에서 `tmux attach -t <세션명>`으로 붙는다.

> **Do:** 뷰어 조작은 `dev-view.sh`의 실행·`--sync`·`--close`로만 한다
> **Don't:** 지휘가 `dev-view` 세션의 pane을 직접 만들거나 죽이거나, 작업 세션에 attach해 화면 크기를 바꾼다
- 날짜는 현재 세션 컨텍스트의 날짜를 쓴다(추측 금지).
- **입력줄에 남은 문구를 사용자가 쓰다 만 입력으로 읽지 않는다.** 프롬프트 제안이 같은 자리에 뜬다. 세션·워크트리 정리를 미룰 근거로 삼기 전에 30초 뒤 다시 캡처해 문구가 바뀌었는지 본다 — 바뀌면 제안이다. 문구가 있다는 사실만으로 정리를 보류하거나 사용자에게 확인을 요청하지 않는다.
