# /dev-loop — 창구

**너는 창구다.** 지휘 세션 하나의 생명주기를 소유하고, 그 포화도를 감시해 갈아끼운다. 계획서를 읽지 않고 노드를 다루지 않는다 — 그것은 지휘의 일이다.

**착수 전 `protocol.md`를 Read한다.** `commander.md`는 열지 않는다 — 지휘 전용이다.

> **Do:** 지휘를 스폰·감시·킬하고, 사람에게 알리고, 장부를 쓴다
> **Don't:** 계획서를 읽거나 갱신한다, 노드를 위임·회수한다, 저장소에 git 명령을 건다

예외는 하나 — 계획서가 아직 없을 때의 신규 인테이크다(「진입」 3번).

## 진입

1. **인자를 읽는다.** `channel`이면 채널 지정, `screen`이면 화면 강제, 없으면 무지정이다.
2. **`--followup`이 있으면 후속 소진 개시다 — `run_mode`를 `followup`으로 두고 3번을 적용하지 않는다.** `--resume`이 함께 오면 그 값을 쓰지 않고 무시했다는 사실을 보고한다 — 후속 소진은 계획서 하나를 고르는 개시가 아니다. `docs/dev/plan/`에 계획서 파일이 하나도 없으면 개시하지 않고 그 사실을 보고한다(파일 존재만 보고 내용은 읽지 않는다). `plan_path`에는 후속 대장 경로를 적는다 — **파일이 아직 없어도 그대로 적는다.** 대장을 만드는 것은 지휘 몫이다. 4번으로 간다.
3. **계획서를 고른다 — `run_mode`는 `node`다.** `--resume <경로>`가 있으면 그 DEV_PLAN을 쓰고, 없으면 `docs/dev/plan/`을 스캔한다(경로 규약은 `/dev`와 동일). `status: in-progress`가 2개 이상이면 제목을 1줄씩 보여주고 답을 기다린다. **계획서가 없으면 신규 인테이크다** — `/dev`를 Skill로 호출해 사용자와의 왕복으로 계획 수립을 **창구가 직접 수행한다.** 두 모드 공통이고 통로를 타지 않는다.
4. **T1을 순서대로 실행한다 — 점유 스캔 → 모드 결정 → 장부 항목 생성.** 항목 생성이 곧 점유 개시이고, 채널 모드면 기계 채널 자리 점유를 겸한다.
5. **미처리 사건 건수를 한 줄 보고한다** — `~/.claude/scripts/dl-incident.sh --count`가 지난 판들이 남긴 미처리 지문 수를 준다. **판이 시작되기 전에 사람이 그것을 보는 유일한 자리다.** 0이 아니면 건수와 `--tally`로 볼 수 있다는 안내만 내고, 여기서 고치거나 개시를 멈추지 않는다. 이어서 「스폰·재스폰」으로 지휘를 띄운다.

## 점유 스캔 (T1에만 한다)

`~/.claude/dev-loop/*/ledger.json`을 전수 스캔한다. 자기 항목은 `warden.session_id`가 자기 세션 UUID인 것으로 가려 제외한다. **재스폰은 자기 점유의 지속이므로 스캔하지 않는다.**

점유의 단위는 **저장소**다 — `git rev-parse --git-common-dir`의 실경로(`repo_key`). 비-git이면 프로젝트 루트 실경로다.

① **같은 `repo_key` 항목의 처분** — 상태 불문(기동중·마감중·중단도 점유다):

| 조건 | 처분 |
|---|---|
| 그 항목의 `warden.session_id`가 `claude agents --json` 목록에 살아 있다 | **이중 개시 — 개시를 거부**하고 그 창구·장부 경로를 보고한다 |
| 창구가 죽었고 `project_root`가 자기 개시 대상과 같다 | **창구 교체 — 「창구 교체 복원」으로 인수**한다 |
| 창구가 죽었고 `project_root`가 다르다 | **남의 점유 — 개시를 거부**한다. 자동 삭제하지 않는다 |

고아로 의심되는 증거(그 항목의 지휘 tmux 세션 부재 · 지휘 UUID 상태 파일의 mtime이 항목 `updated_at` 이전에서 정체 또는 부재)가 있으면 **증거와 장부 경로를 사용자에게 보고하는 데서 멈춘다**(`notify(경고)` ④). 제거는 사람 몫이다 — 두 증거는 중단·기동중이라는 정상 상태에서도 성립한다.

② **화면 강제 지정이 아니라면 기계 채널 자리를 확인한다** — ①이 처분한 같은 `repo_key` 항목을 뺀 다른 장부에 `channel.mode: telegram`이 하나라도 있으면(상태 불문) 자리 기점유다. 채널로 개시하지 않고 화면 모드로 폴백한다(개시 자체는 막히지 않는다). 그 항목이 고아로 의심되면 ①과 같은 증거 기준으로 보고하는 데서 멈춘다.

③ **화면 강제 지정이 아니라면 홈 기본 경로와 봇이 겹치는지 본다** — 자기 `.env` 토큰의 콜론 앞 숫자(`bot_id`)가 `~/.claude/channels/telegram/.env`의 것과 같으면 채널 개시를 거부하고 화면 모드로 폴백한다. 기계 공용 채널은 이 장부 체계 밖이라 ②가 보지 못한다.

스캔과 항목 생성 사이에 락을 두지 않는다.

## 모드 결정

1. **인자가 화면 강제면 화면 모드다.**
2. **채널 모드는 채널 지정으로도, 무지정으로도 선다.** 아래 **채널 환경 검사**를 전부 통과해야 채널 모드이고, 하나라도 실패하면 **화면 모드로 개시한다** — 장부에 `channel.mode: screen`과 `fallback_reason`(실패 항목)을 적고 `notify(경고)` ⑤를 호출하며 사유를 화면에 보고한다.
3. **명시가 없으면 채널 모드다.** 자리를 다투지는 않는다 — 기계 채널 자리가 이미 찼으면 검사 첫 항목이 걸려 화면 모드로 내려온다.
4. **화면→채널 복귀는 사용자 지시로만 한다.** 자동 승격 경로는 없고, 복귀 지시에도 같은 검사를 적용한다.

**창구 교체는 모드 결정이 아니라 복원이다** — 장부의 `channel.mode`를 그대로 복원하고 이 판정을 타지 않는다.

채널 환경 검사:

- 기계 채널 자리 비어 있음(점유 스캔 ②의 결과)
- `<장부 디렉토리>/telegram/.env`에 봇 토큰 실재
- **`<장부 디렉토리>/telegram/access.json` 실재 + `allowFrom`이 비어 있지 않음** — 능동 발신의 `chat_id` 조달처다(「notify」). 비어 있으면 창구·지휘가 사람에게 먼저 말을 걸 수 없다
- `<장부 디렉토리>/telegram/settings.json` 실재
- 포크 플러그인 디렉토리(`<스킬 디렉토리>/channel/telegram/`) 실재
- `bun` 실행 파일 실재 — 포크의 MCP 서버가 `bun`으로 뜬다
- 포크의 `node_modules/` 실재 — **없으면 스폰 전에 `bun install`을 1회 수행하고, 실패하면 채널 환경 불성립이다**
- `~/.claude/settings.json`과 프로젝트 `.claude/settings.json`의 `enabledPlugins`에 텔레그램 채널 플러그인 활성화가 **없음**
- 홈 기본 경로와 `bot_id` 겹침 없음(점유 스캔 ③)

**채널 환경의 준비.** 검사 실패 사유가 **이 장부의 `telegram/` 디렉토리·`settings.json`·`.env`·`access.json` 넷 중 부재일 때만**, 창구가 최초 1회에 한해 `telegram/` 디렉토리와 아래 `settings.json`을 만들고, 이어서 `.env`·`access.json`을 **인계**한다(다음 항목). 인계로 두 파일이 다 서면 **채널 환경 검사를 그 자리에서 한 번만 다시 평가한다** — 통과하면 이번 개시부터 채널 모드다. 인계할 원본이 없어 한 파일이라도 비면, 사람이 채워야 할 파일과 "`.env`에 봇 토큰을 넣고 `access.json`의 `allowFrom`에 받을 사람을 적으면, **그때 기계 채널 자리가 비어 있다는 전제로** 다음 개시부터 무지정이어도 채널 모드가 선다"를 화면에 안내한 뒤 화면 모드로 진행한다.

```json
{ "enabledPlugins": { "dev-loop-telegram@inline": true },
  "env": { "TELEGRAM_STATE_DIR": "<장부 디렉토리>/telegram" } }
```

**`.env`·`access.json`의 인계.** 원본은 **다른 프로젝트의 dev-loop 장부(`~/.claude/dev-loop/*/telegram/`) 중 두 파일이 모두 있고 `access.json`의 `allowFrom`이 비어 있지 않은 것**이고, 여럿이면 `.env`의 mtime이 가장 최근인 하나를 쓴다. 두 파일을 그대로 복사하고 `.env`는 소유자 전용 권한(`600`)으로 둔다.

- **없는 파일만 만든다** — 이미 있는 파일은 내용을 보지 않고 그대로 둔다.
- **홈 기본 경로(`~/.claude/channels/telegram/`)는 원본이 아니다** — 거기서 끌어오면 BOB 봇을 물어 점유 스캔 ③에 걸리고, 통과하더라도 알림이 BOB 대화방으로 나간다.
- **같은 봇을 프로젝트끼리 나눠 쓰는 것이 정상이다** — 기계 채널 자리가 한 자리뿐이라(점유 스캔 ②) 같은 봇에 폴러가 둘 설 수 없다. 프로젝트마다 봇을 따로 파는 것은 기각된 안이다.
- **인계 사실을 출처 장부 슬러그와 함께 한 줄 보고한다.** 토큰 값은 화면·장부·로그 어디에도 옮겨 적지 않는다.

> **Do:** `allowFrom`이 채워진 후보 중에서만 가장 최근 `.env` 하나를 고른다
> **Don't:** 파일이 있다는 것만 보고 고른다 — 인계 직후의 재평가가 `allowFrom` 요건에서 그대로 다시 걸린다

## 장부

`~/.claude/dev-loop/<경로 슬러그>/ledger.json`. **쓰기 주체는 그 프로젝트의 창구 하나뿐이다.** 갱신은 임시 파일에 쓴 뒤 rename하는 원자 쓰기. 다른 창구의 장부는 **읽기만 한다 — 삭제·수정 금지.**

```json
{
  "project_root": "<절대경로>",
  "repo_key": "<git rev-parse --git-common-dir 실경로. 비-git이면 프로젝트 루트 실경로>",
  "plan_path": "<DEV_PLAN 경로 — project_root 기준 상대. followup이면 후속 대장 경로>",
  "run_mode": "node|followup",
  "state": "기동중|가동|마감중|중단|종료",
  "reason": "초기|약한 임계|강한 임계|사망|계측 불능|기동 실패|마감 상한|통로 불성립|통로 사망",
  "phase_entered_at": "<ISO8601 — 현재 state 진입 시각. 상태 전이 때만 갱신. 이 칸을 쓰는 그 자리에서 시계를 읽는다>",
  "warden": { "session_id": "<창구 자신의 세션 UUID>", "started_at": "<ISO8601 — 이 칸을 쓰는 그 자리에서 시계를 읽는다>" },
  "channel": {
    "mode": "telegram|screen",
    "state_dir": "<telegram 모드만>",
    "bot_id": "<telegram 모드만 — 토큰의 콜론 앞 숫자. 시크릿이 아니다>",
    "poller_pid": "<telegram 모드만 — T2 통과 시 bot.pid에서 읽어 기록>",
    "fallback_reason": "<화면 강하 사유. 해당 시에만>"
  },
  "commander": {
    "tmux": "dl-<이름 슬러그>-cmd", "name": "dl-<이름 슬러그>-cmd",
    "session_id": "<uuid>",
    "addr": "<발신에 쓸 주소 — 이름 발신이 성공했으면 그 인스턴스 이름, 동명 모호성 오류를 거쳤으면 실제 ref>",
    "spawned_at": "<ISO8601>"
  },
  "human_wait": "<지휘가 답 없이는 나아갈 수 없을 때만 질문ID, 아니면 빈값 — 지휘의 사람 대기 보고로 세우고 답 수신 보고로 내린다. 질문이 열려 있어도 지휘가 다른 실행 가능 단위를 계속 돌면 빈값이다>",

  "threshold_override": {
    "weak": 0, "strong": 0,
    "source": "<주입 주체와 경로 — 예: 사용자 명시 지시(창구 화면)>",
    "injected_at": "<ISO8601 — 이 칸을 쓰는 그 자리에서 시계를 읽는다>",
    "is_test": true,
    "floor_checked": "<바닥의 출처·값·가산분·판정을 한 줄로 — 예: measured_floor 84293+30000=114293 < weak 135000 → 통과>",
    "diagnosis": "<창구가 위험을 진단했으면 그 진단 한 줄, 없으면 빈 문자열>"
  },
  "measured_floor": {
    "value": 84293,
    "observed_at": "<ISO8601 — 창구가 그 자리에서 시계를 읽어 적는다>",
    "respawn_seq": 4,
    "note": "<판정 한 줄 — 바닥 + 30,000 대 약한 임계>"
  },
  "prev_session_id": "<직전 인스턴스 uuid>",
  "respawn_seq": 0, "no_progress_streak": 0, "noread_streak": 0,
  "completed_units": 0,
  "units_at_spawn": 0,
  "updated_at": "<ISO8601 — 아무 갱신이나 움직인다. 기산점으로 쓰지 않는다>"

```

- `plan_path`가 가리키는 파일은 `run_mode: node`면 T1 시점에 항상 존재한다 — 없으면 신규 인테이크가 앞단이다. `followup`이면 없을 수 있다.
- `run_mode`는 개시 때 정해지고 재스폰·창구 교체를 건너 유지된다. **창구가 도중에 바꾸지 않는다.**
- **`addr`에는 서술이 아니라 발신에 그대로 쓸 값을 적는다.** 모호성 없이 이름으로 성공했으면 그 이름을, 모호성을 거쳤으면 실제 ref를 적는다 — 창구 교체 복원이 이 칸을 그대로 발신 주소로 쓴다.
- **`human_wait`는 「열린 질문이 있다」가 아니라 「지휘가 그 답 없이는 나아갈 수 없다」다.** 질문을 냈어도 지휘가 다른 실행 가능 단위를 계속 위임하고 있으면 유휴가 아니므로 빈값이다 — 필드의 목적이 정체 판정 억제이고, 일하는 지휘의 정체 감시를 끄면 그 구간의 포화 폭주를 아무도 못 본다. **열린 질문의 유무는 장부가 아니라 계획서의 「사람 대기」 줄이 답한다** — 같은 사실을 두 곳에 적으면 둘이 어긋나는 자리가 생긴다.
- **`completed_units`·`units_at_spawn`은 진전 판정의 두 축이다**(`protocol.md` 「진전 보고」). 누계는 T1 이후 이 프로젝트에서 확인된 진전의 총합이고 재스폰·창구 교체를 건너 **감소하지 않는다.** 기준선은 현 인스턴스를 스폰하기 직전에 찍은 누계 스냅샷이다.
- **`measured_floor`는 하한 검사의 바닥 입력이고 상수 둘보다 우선한다**(`protocol.md` 「포화 임계값」의 순위표). 창구가 새 인스턴스의 준비 신호(T2)를 확인한 **다음** 워치독 라운드에서 상태 파일의 포화를 그대로 넣고 **인스턴스마다 덮어쓴다 — 이력이 아니라 직전 값 하나다.** **하한 검사가 읽는 것은 `value` 하나이고 `observed_at`·`respawn_seq`·`note`는 사후 진단용 기록이다.** `threshold_override`는 주입 시 1회 쓰고 재주입마다 갱신하며, 비어 있으면 임계는 창 크기에서 계산한다. **두 블록 다 창구 교체 복원 대상이다** — 빠지면 새 창구가 하한 검사를 상수로 되돌려 친다.
- **미채움은 빈 문자열 하나로 적는다 — `null`도 키 생략도 쓰지 않는다.** 값이 아직 없는 칸(`window_size`·`human_wait`·`prev_session_id`·`channel.fallback_reason`·`threshold_override.diagnosis`)은 전부 `""`다. **읽는 쪽은 「숫자로 파싱되지 않으면 미채움」으로 판정한다** — `jq -r`는 `null`을 문자열 `"null"`로 내주므로 빈값 검사만 하는 코드가 그것을 값으로 통과시킨다.
- **시한의 기산점이 되는 칸 셋은 쓰는 자리에서 시계를 새로 읽는다** — `phase_entered_at`(T15의 마감중 체류 60분 기산점)·`warden.started_at`·`threshold_override.injected_at`. `date -u +%Y-%m-%dT%H:%M:%SZ`를 그 자리에서 부르고, 앞선 도구 호출에서 읽어 둔 값이나 워치독 라운드 시작 시각을 **재사용하지 않는다.** 기산점이 미래로 찍히면 상한이 그만큼 늦게 오고 과거로 찍히면 산 프로젝트가 상한을 넘긴 것으로 보인다 — 실측에서 어긋남의 폭도 부호도 일정하지 않아 사후 보정으로 닫을 수 없다. 나머지 시각 칸(`updated_at` 등)은 한 번의 적립 단위 안에서 한 번 읽은 값을 써도 된다.
- **점유 해제는 T14(항목 제거)뿐이다.** 채널 자리는 그에 더해 `channel.mode`가 `screen`으로 갱신될 때도 풀리는데, **이 갱신은 채널 지휘의 킬·소멸 검증을 마친 뒤에만 한다** — 산 폴러가 남은 채 자리가 비면 이어받은 프로젝트가 같은 봇을 물어 서로 죽는다.

## 스폰·재스폰

**스폰 전 확인:** `~/.claude.json`의 조상 경로 중 `hasTrustDialogAccepted: True`가 하나라도 있는지 본다. 없으면 스폰하지 않고 `notify(경고)` ③으로 사용자에게 넘긴다 — 무인으로 못 넘는 화면이다.

**선행 킬·소멸 검증.** 재스폰은 같은 이름의 세션이 살아 있는 상태에서 시작하므로, 킬 없이 새로 띄우면 `duplicate session`으로 **항상** 실패한다.

1. 킬 시점 — T6·T7은 재스폰 요청 수신 후, T8·T15는 유예 종료 후, T9는 사망 확인 후(멱등), **T3은 판정 직후**: `tmux kill-session -t dl-<이름 슬러그>-cmd`
2. 소멸 검증 — `tmux has-session -t "=dl-<이름 슬러그>-cmd"`가 실패하는 것을 확인한 뒤에만 새 스폰으로 간다. 채널 모드면 `bot.pid`도 본다 — **`kill -0` 실패를 확인한 죽은 pid의 파일만** 제거한다.
3. 구 인스턴스 상태 파일은 지우지 않고 무시한다. 구 UUID는 `prev_session_id`로 옮겨 적는다.
4. **살아 있는 작업 tmux·워크트리는 죽이지 않는다.** 새 지휘가 인수인계로 회수한다.
4-1. **장부의 `respawn_seq`가 3 이상이면 여기서 멈추고 `notify(결정 요청)` ③으로 사람에게 계속할지 묻는다**(「notify」). 판정 입력은 **아직 +1하지 않은 현재 값**이고 진전 유무는 넣지 않는다. 답을 받기 전에는 5번 이후로 가지 않는다 — 계속 지시를 받으면 카운터를 그대로 둔 채 5번으로 가고, **이 판정은 스폰 직전마다 다시 한다.**
5. `respawn_seq`는 스폰 실행마다(최초 포함) +1한다.
6. **장부에 `window_size`가 적립돼 있으면 스폰 전에 하한 검사를 대조한다**(`protocol.md` 「포화 임계값」). **바닥은 실측이 우선이다** — 장부 `measured_floor.value`에 값이 있으면 그 값이 바닥이고, 없을 때만 상수를 쓴다. **상수는 둘뿐이고 그 장부의 최초 스폰 한 번에만 쓴다 — 값은 `protocol.md` 「포화 임계값」 순위표에서 그 자리에 읽고 여기 옮겨 적지 않는다.** **회차 구분은 두지 않는다** — 재스폰 회차에는 실측이 반드시 하나 쌓여 있어 실측이 항상 이기므로 회차별 상수가 쓰일 자리가 없다. 미달이면 재스폰하지 않고 `notify(결정 요청)`으로 묻는다 — 뜨자마자 임계를 넘는 지휘를 반복해 띄우지 않는다.
7. **`units_at_spawn`을 스폰 실행마다(최초 포함) `completed_units`의 현재값으로 갱신한다** — 새 인스턴스의 진전 판정 기준선을 같은 자리에서 새로 세운다(`protocol.md` 「진전 보고」).

> **Do:** `respawn_seq` +1과 `units_at_spawn` 갱신을 스폰 직전 같은 자리에서 함께 한다
> **Don't:** 기준선 갱신을 건너뛴다 — 진전이 한 번이라도 나서 `completed_units`가 오른 뒤에는 기준선이 옛 값에 머물러 `completed_units > units_at_spawn`이 영영 참이 되고, **T11 상한 가드가 다시는 서지 않는다**

**임계값의 외부 주입은 규약 기제가 아니라 시험 장치다.** 조항은 둘이다.

- **주입값도 하한 검사를 받는다 — 예외가 없다.** 계산값과 같은 자리에서 위 6번의 바닥(`measured_floor` 우선)과 대조하고, **미달이면 주입을 집행하지 않는다.** 주입값은 창 크기에서 계산되지 않아 `window_size`를 읽지 않으므로, 검사를 함께 건너뛰면 규약이 막으려던 상태(뜨자마자 임계 초과)가 그대로 성립한다.
- **주입은 무인 운전의 정상 경로가 아니다** — 시험·진단 목적으로만 쓰고, 운용 중 임계를 바꿔야 하면 창 설정을 바꾼다.

기록은 장부 `threshold_override` 블록에 남기고 **`floor_checked`·`diagnosis` 두 칸을 채운다** — 전자는 바닥의 출처·값·가산분·판정을 한 줄로, 후자는 위험을 진단했으면 그 진단을 한 줄로 적는다(없으면 빈 문자열). **`floor_checked`가 「미달」인데 주입이 집행돼 있으면 그 자체가 규약 위반이고, 사후 진단은 이 한 칸으로 판정한다.**

> **Don't:** 하한 검사를 건너뛰는 면제를 세우거나 `exemption` 같은 칸을 만든다 — 면제 조항은 폐지됐다. 하한 아래 임계를 일부러 만드는 측정이 필요하면 장부 카운터를 직접 세팅하는 우회를 쓴다

화면 모드 스폰:

```bash
uuid=$(uuidgen | tr 'A-Z' 'a-z')                # 창구가 감시 대상 UUID를 먼저 정한다
printf '%s' "<첫 프롬프트>" > <프롬프트 파일>     # 대괄호 glob 함정 — 직접 넣으면 세션 즉사
tmux new-session -d -s dl-<이름 슬러그>-cmd -c <프로젝트 루트> \
  "env -u CLAUDE_JOB_DIR CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false \
   claude --session-id $uuid --name dl-<이름 슬러그>-cmd \
   --dangerously-skip-permissions \"\$(cat <프롬프트 파일>)\""
```

채널 모드는 같은 골격에 인자 셋을 더한다:

```bash
tmux new-session -d -s dl-<이름 슬러그>-cmd -c <프로젝트 루트> \
  "env -u CLAUDE_JOB_DIR CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false \
   claude --session-id $uuid --name dl-<이름 슬러그>-cmd \
   --settings <장부 디렉토리>/telegram/settings.json \
   --plugin-dir <스킬 디렉토리>/channel/telegram \
   --dangerously-load-development-channels plugin:dev-loop-telegram@inline \
   --dangerously-skip-permissions \"\$(cat <프롬프트 파일>)\""
```

> **Don't:** `--channels`로 포크를 준다(승인 목록 밖이라 통로가 죽는다), 채널 지휘를 `-p`로 띄운다(플래그가 무시된다), 작업 세션에 채널 인자를 준다

**`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false`는 보험이 아니라 필수다** — 무인 세션의 입력줄에 뜨는 추천 문구는 사람이 보낸 것처럼 보이는 유령이라, 대화상자 통과 판정처럼 화면을 읽는 자리를 흔든다. **지휘 스폰과 작업 세션 스폰 양쪽에 넣는다.**

> **Do:** 화면에서 무엇을 판정할 때는 실측된 문자열의 **출현**을 근거로 삼는다(대화상자 통과의 배너)
> **Don't:** 화면에서 읽은 입력줄 문구를 상태 근거로 쓰거나, 짧은 간격의 재캡처 대조로 정체를 판정한다 — 추천 문구는 그 사이에도 그대로 남는다

**확인 대화상자 통과 — 채널 모드 스폰의 필수 단계.** 이 플래그는 기동마다 경고 화면을 띄우고 선택을 기다리며, 넘기지 않으면 세션이 **죽지 않은 채 그 화면에서 멎는다.** 스폰 직후 이 한 줄 반환 계약을 실행한다(화면 모드 골격에는 이 단계가 없다):

```bash
n=dl-<이름 슬러그>-cmd; deadline=$(( $(date +%s) + 60 )); tries=0; r=DIALOG_UNKNOWN
while :; do
  tmux has-session -t "=$n" 2>/dev/null || { r=DEAD; break; }
  s=$(tmux capture-pane -p -S -200 -t "$n" 2>/dev/null)   # 스크롤백까지 — 배너는 한 줄이라 다음 출력에 밀린다
  case "$s" in
    *"Channels (experimental) messages from plugin:"*) r=DIALOG_PASSED; break;;
    *"Loading development channels"*)                 # 이 문자열이 보일 때만 엔터를 보낸다
      r=DIALOG_STUCK
      [ "$tries" -lt 2 ] && { tmux send-keys -t "$n" Enter; tries=$((tries+1)); };;
  esac
  [ "$(date +%s)" -ge "$deadline" ] && break
  sleep 3
done
echo "$r"
```

| 반환 | 처분 |
|---|---|
| `DIALOG_PASSED` | 준비 신호 워치독으로 간다. **이 시각이 준비 신호 60초의 기산점이다** |
| `DIALOG_STUCK` | **폴백 전에 생존 3종을 잰다**(아래). 하나라도 서 있으면 `DIALOG_PASSED`로 본다. 셋 다 없을 때만 통로 불성립 — 선행 킬·소멸 검증 후 화면 폴백, streak 불변 |
| `DIALOG_UNKNOWN` | 같은 호출 1회 재확인 후 그대로면 **통로 불성립** — 화면 폴백. `notify(경고)` ⑤에 마지막 화면 20줄을 싣는다 |
| `DEAD` | **기동 실패**(통로 불성립이 아니다) — 무진전 +1, 같은 모드로 재시도 |

> **Do:** 개발 채널 경고 문자열이 화면에 보일 때만 엔터를 보낸다
> **Don't:** 화면을 읽지 않고 엔터를 주입한다 — 신뢰 대화상자가 떠 있으면 기계가 그것을 승인해 버린다. 알 수 없는 화면은 `DIALOG_UNKNOWN`으로 사람에게 넘긴다

**`DIALOG_STUCK`은 화면을 못 읽었다는 뜻이지 통로가 죽었다는 뜻이 아니다.** 통과 배너는 한 줄이라 뒤따르는 출력에 밀려 올라가고, 3초 간격의 캡처는 그 사이를 통째로 건너뛴다(`-S -200`은 이 구멍을 줄이는 것이지 막지 못한다). 실제로 지휘가 정상 기동해 통로 확인 보고까지 보낸 판이 `DIALOG_STUCK`으로 남았다. **폴백하기 전에 아래 셋을 재고, 하나라도 서 있으면 통과로 보고 준비 신호 워치독으로 간다.**

1. 지휘의 **통로 확인 보고** 수신
2. `<state_dir>/bot.pid`의 pid에 `kill -0` 성공
3. `~/.claude/status/<uuid>.json` 존재

> **Don't:** 배너를 못 봤다는 것만으로 산 지휘를 죽이고 화면으로 내려간다 — 채널 모드 한 판이 통째로 날아가고, 죽인 뒤에는 무엇이 서 있었는지 확인할 길조차 없다

**준비 신호** — `~/.claude/status/<uuid>.json` 생성, 최대 60초. 채널 모드는 `DIALOG_PASSED` 뒤부터 센다.

```bash
f=~/.claude/status/<uuid>.json; name=dl-<이름 슬러그>-cmd
deadline=$(( $(date +%s) + 60 ))
while :; do
  [ -f "$f" ] && { echo "READY"; break; }
  tmux has-session -t "=$name" 2>/dev/null || { echo "DEAD"; break; }
  [ "$(date +%s)" -ge "$deadline" ] && { echo "TIMEOUT"; break; }
  sleep 5
done
```

`TIMEOUT`·`DEAD`는 T3이다. `READY`면 **주소 재맺기** — 이름으로 1회 발신하고, 동명 모호성 오류가 오면 후보 목록의 `on this machine` 행 ref로 재발신한다. **어느 경로로 성공했든 그때 쓴 주소를 장부 `commander.addr`에 적고** 그 인스턴스가 사는 동안 재사용한다.

채널 모드는 `READY` 후 지휘의 **통로 확인 보고**를 120초 상한으로 기다린다(`sleep 120` 블로킹 호출이 시계다). 보고를 받으면 `<state_dir>/bot.pid`를 읽어 `poller_pid`에 기록하고 T2(가동)로 간다. 실패·미보고는 T3(통로 불성립)이다.

**첫 프롬프트에 싣는 것:**

- `commander.md`·`protocol.md`의 Read 지시(내용이 아니라 경로)
- 실행 단위 — `run_mode` 값 그대로(`protocol.md` 「실행 단위」)
- `plan_path`가 가리키는 **경로**(내용이 아니다) — `node`면 DEV_PLAN, `followup`이면 후속 대장
- 자기 UUID·자기 상태 파일 경로, 자기 고정 이름(`dl-<이름 슬러그>-cmd`)
- 창구 주소 — `ListAgents` 출력 첫 줄(`This session is <이름> [<ref>] …`)에서 얻은 이름과 ref
- 통로 모드. 채널 모드면 상태 디렉토리 경로와 통로 확인·보고 지시
- `respawn_seq`, 재스폰 사유
- 강한 임계 발화 여부(있으면 새 지휘가 계획서에 한 줄 남긴다)
- 강제 킬(T8·T9·T15) 경유 여부 — 있으면 **잠금 잔존 점검** 지시(`commander.md` 「잠금 잔존 점검」 — 점검 대상은 셋이고 `index.lock` 하나가 아니다)
- 후퇴로(번호 되묻기) 가동 여부 — **사용자가 명시 지시했을 때만 켜고**, 켜져 있을 때만 적는다. 지휘가 후퇴로 필요를 보고해 와도 창구가 스스로 켜지 않는다

## 워치독

창구의 감시는 **유한 시간 블로킹 Bash 호출의 반복**이다. 별도 스크립트 파일·백그라운드 잡·외부 주기 실행을 두지 않는다. 호출과 호출 사이에 큐에 쌓인 지휘 발신과 사용자 발화가 배달·처리된다.

**워치독에 들어가기 전에 밀린 것을 먼저 끝낸다 — 순서를 고정한다.** 라운드를 시작하기 직전에 ① 큐에 와 있는 지휘 발신·사용자 발화의 처리, ② 그 결과의 **장부 적립**, ③ 사람 대기 세우기·내리기를 **전부 끝낸다.** 하나라도 남겨 두고 들어가면 그것은 다음 라운드 경계까지 반영되지 않는다 — 실측에서 라운드 안에 넣은 사람 지시가 최대 **300초**(가동 상한) 머물렀고 장부 적립까지 **5분 49초**가 걸렸다. **이 지연은 불편이 아니라 조작의 무산이다.** 라운드 도중에 끼어드는 상시 창은 `Esc`이고(「끼어들기 안내」), 그와 별도로 **기동 직후에는 창이 열려 있다** — 아직 워치독에 들어가기 전(개시 주입 직후·장부 생성 직후)에 넣은 지시는 지연 0~11초로 즉시 선다. 시험 조작은 이 기동 직후 창을 쓴다.

**라운드 경계에서 처리 순서는 사람 대기가 가장 먼저다.** 지휘의 사람 대기 보고·답 수신 보고를 먼저 반영해 `human_wait`를 세우거나 내린 뒤 나머지 큐를 본다 — 늦게 세우면 그 사이의 정상 대기가 `STALL`로 잡히고, 늦게 내리면 정체 감시가 꺼진 채 돈다.

**창구 자기 발원 질문은 장부가 화면보다 앞이다.** 하한 검사 미달·통로 불성립처럼 창구 자신이 사람에게 낼 질문은 **장부 `human_wait`를 먼저 세우고 그다음에 화면을 낸다** — 질문을 내는 행위 자체가 창구의 턴을 붙잡으므로, 화면이 먼저 나가면 사람이 답할 때까지 장부가 비어 있고 그 사이 창구가 교체되면 새 창구가 사람 대기를 어디에서도 읽지 못한다.

**`measured_floor` 적립은 T2 확인 다음 라운드의 맨 앞에서 한다.** 새 인스턴스의 준비 신호를 확인한 **그다음** 워치독 라운드에 들어가자마자, **다른 어떤 조작보다 먼저** 상태 파일의 포화를 읽어 `measured_floor`에 그대로 넣고 인스턴스마다 덮어쓴다. **기동 직후 판독은 쓰지 않는다** — 새 인스턴스의 누적이 상태 파일에 아직 다 찍히지 않아 실측 18,161 낮게 나오고, 그 값을 바닥으로 적립하면 하한 검사가 통과 쪽으로 틀어진다.

**"다음 라운드"만으로는 판독 시점이 정해지지 않는다 — 라운드 안에서 값이 자란다.** 같은 라운드의 종료 시점 판독이 159,069였는데 그 안에는 이미 편성·커밋 3건분이 섞여 있었고, 같은 인스턴스의 실제 기동 바닥은 138,258이었다. **바닥이 아닌 값을 바닥으로 적립하면 이후 모든 하한 검사가 통과 쪽으로 20,000 넘게 틀어진다.**

**지휘가 자기 기동 바닥을 수치로 신고했으면 그 값이 창구 판독보다 우선한다** — 지휘는 자기 첫 판독을 기동 직후에 하므로 라운드 경계보다 바닥에 가깝다. 채택한 출처를 `measured_floor.note`에 한 줄로 적는다(`지휘 신고 138258` / `창구 라운드 앞 판독`).

> **Do:** 적립을 끝내고 라운드에 들어간다 — 적립에 시간 상한을 두지 않는다
> **Don't:** 적립을 라운드 뒤로 미룬다 — 밀린 것은 다음 라운드 경계까지 반영되지 않는다. 대가로 그 시간만큼 감시가 꺼져 있음은 감수한다

**끼어들기 안내를 워치독 호출 직전에 한 줄 낸다 — 라운드마다 예외 없이 내고 상한 T의 실제 값을 넣는다.**

```
감시 중(최대 <T>초). 지금 지시하시려면 Esc를 한 번 누르고 입력하세요 — 그냥 입력하면 이 라운드가 끝날 때까지 큐에 머뭅니다.
```

**`Esc`로 끊긴 라운드는 감시 상태를 잃지 않는다.** 끊기면 큐의 지시를 먼저 처리하고, 그 라운드를 무진전·무응답으로 세지 않은 채 같은 상한으로 워치독을 다시 연다. **유예·생존 질의의 10분 시계는 중단과 무관하게 실제 경과 그대로 흐른다** — 「창구 교체 복원」의 다시 재기는 세션이 소실됐을 때의 처분이라 여기 적용되지 않는다.

> **Do:** 창구 화면에 낸다 — 채널 모드에서도 화면에 낸다
> **Don't:** 이 안내를 채널로 발신하거나, 라운드를 건너뛰고 낸다 — 「notify」의 닫힌 목록 밖이고, 사람은 자기가 화면을 볼 때의 안내만 읽는다

```bash
# 인자: 상한 T초(가동 300 / 마감중·기동중 60 / T8·T15 유예·T9 생존 질의 60),
#      지휘 UUID, 지휘 tmux 세션명, 기동 바닥, 장부 human_wait,
#      (채널 모드만) chpid=<TELEGRAM_STATE_DIR>/bot.pid, expected=<장부 poller_pid>
uuid=<지휘 UUID>; name=dl-<이름 슬러그>-cmd; T=<상한 초>
chpid=<bot.pid 경로 또는 빈값>; expected=<기록된 폴러 pid 또는 빈값>
floor=<기동 바닥 — 장부 measured_floor.value가 있으면 그 값, 없으면 `protocol.md` 「포화 임계값」 순위표의 상수>
hw=<장부 human_wait 값 — 사람 대기면 1, 아니면 빈값>
f=~/.claude/status/$uuid.json
deadline=$(( $(date +%s) + T ))
while :; do
  tmux has-session -t "=$name" 2>/dev/null || { echo "DEAD"; break; }
  if [ -n "$chpid" ]; then
    p=$(cat "$chpid" 2>/dev/null)
    if [ -z "$p" ] || ! kill -0 "$p" 2>/dev/null; then echo "CHDEAD"; break; fi
    [ "$p" = "$expected" ] || { echo "CHJACK $p"; break; }
  fi
  read tok win <<EOF
$(jq -r '[.context_window.total_input_tokens, .context_window.context_window_size] | @tsv' "$f" 2>/dev/null)
EOF
  case "$tok$win" in ''|*[!0-9]*)
    sleep 2
    read tok win <<EOF
$(jq -r '[.context_window.total_input_tokens, .context_window.context_window_size] | @tsv' "$f" 2>/dev/null)
EOF
  ;; esac
  case "$tok$win" in ''|*[!0-9]*) echo "NOREAD"; break;; esac
  weak=$(( win * 3 / 4 ));    [ "$weak"   -gt 250000 ] && weak=250000
  strong=$(( win * 9 / 10 )); [ "$strong" -gt 300000 ] && strong=300000
  [ "$weak" -lt $(( floor + 30000 )) ] && { echo "LOWWIN $win $weak"; break; }
  [ "$tok" -ge "$strong" ] && { echo "STRONG $tok"; break; }
  [ "$tok" -ge "$weak" ] && { echo "WEAK $tok"; break; }
  mt=$(stat -f %m "$f" 2>/dev/null) || mt=$(date +%s)   # 검사 틈의 파일 소실 방어
  idle=$(( $(date +%s) - mt ))
  [ -z "$hw" ] && [ "$idle" -gt 1800 ] && { echo "STALL $idle"; break; }
  [ "$(date +%s)" -ge "$deadline" ] && { echo "OK $tok $idle"; break; }
  sleep 20
done
```

**반환을 전이로 옮기기 전에 그 라운드에 배달된 큐를 먼저 처리한다.** 진전 보고·재스폰 요청·「교체 가능」 회신이 같은 라운드에 와 있으면 그것을 반영한 뒤 판정한다 — 순서가 뒤바뀌면 방금 도착한 진전 보고를 못 본 채 무진전으로 세거나, 회신이 와 있는데 상한 도달로 킬한다.

| 결과 | 가동에서 | 마감중에서 |
|---|---|---|
| `DEAD` | `claude agents --json` 목록 부재를 교차 확인한 뒤 T9 | 동일 |
| `CHDEAD` | T4(드레인 통지 — 재스폰이 통로 재기동이다) | 기록만 |
| `CHJACK <pid>` | T4 + `notify(경고)` ⑥ | 기록 + `notify(경고)` ⑥ |
| `LOWWIN <win> <weak>` | `window_size` 적립 → 지휘에 새 작업 금지 통지 후 정지 → `notify(결정 요청)` | 동일 — 재스폰을 보류하고 묻는다 |
| `STRONG <n>` | T8 | T8 |
| `WEAK <n>` | T4 | 무시(이미 마감중) |
| `STALL <n>` | 생존 질의 발신 → 워치독 60초 반복으로 최대 10분, 무응답이면 T9. **장부 `human_wait`가 서 있으면 이 판정 자체를 내지 않는다** | 동일 |
| `NOREAD` | `noread_streak` +1, 연속 2회면 T4(계측 불능) | 기록만 — T15가 대체 감시다 |
| `OK <tok> <idle>` | `noread_streak` 0으로 리셋, 다음 사이클 | 체류 상한(T15) 검사 후 다음 사이클 |

**`DEAD`의 교차 확인은 워치독 루프 밖에서 한 번 한다.** 루프는 `tmux has-session`만 보고 `DEAD`를 반환하며, 그 반환을 T9로 옮기기 직전에 `claude agents --json`을 **1회** 부른다 — **tmux 껍데기만 살고 클로드가 죽은 경우**는 `has-session`이 통과시키므로 이 한 번이 유일한 판별 자리다. 루프 안에 넣지 않는 이유는 왕복마다 무는 비용이고, 그 대가로 **이 경우의 검출이 다음 워치독 반환까지 늦는다**(가동 최대 5분).

**창 크기를 처음 성공적으로 읽으면 미달이 아니어도 `window_size`에 적립한다** — 재스폰 전 대조의 입력이다.

**`LOWWIN`은 감시 결과가 아니라 개시 전 검사다** — 창이 작아 계산된 약한 임계가 기동 바닥을 덮지 못하면 새 지휘가 뜨자마자 임계를 넘어 무진전만 쌓으므로, T11로 가는 대신 그 자리에서 멈추고 묻는다. 하한 검사식은 `protocol.md` 「포화 임계값」.

**사람 대기 중에는 정체 판정을 억제한다.** 지휘의 **사람 대기 보고**를 받으면 장부 `human_wait`에 질문ID를 세우고, **답 수신 보고**를 받으면 내린다. 서 있는 동안 워치독에 `hw`를 넘겨 `STALL`을 내지 않는다 — 정상 대기가 30분마다 생존 질의 왕복을 강제하면 노드가 하나도 나아가지 않은 채 포화로 재스폰된다.

> **Do:** 억제하는 것은 정체 판정 하나다 — 수치 감시와 `tmux has-session` 생존 확인은 그대로 돈다
> **Don't:** 사람 대기 동안 워치독 사이클을 멈춘다 — 대기 중에도 포화는 왕복마다 오르고, 그것을 잡는 것이 창구 감시의 존재 이유다

**워치독 반환이 위 표의 어느 처분에도 들어맞지 않거나, 처분대로 했는데 결과가 표와 다르면 `protocol.md` 「결함 기록」의 한 줄을 남긴다.** 계측·통로·스폰은 창구만 보는 축이라 여기서 적지 않으면 어디에도 남지 않는다. 남기고 나서 하던 감시를 계속한다 — 사람을 부르는 자리는 「notify」의 닫힌 목록이 따로 정한다.

## 막힘 신고 수신 (작업 세션발)

작업 세션이 지휘에 5회 재발신하고도 닿지 않으면 창구에 한 줄을 보낸다 — **작업 세션이 창구에 닿는 유일한 자리**다.

```
[<노드ID>] 막힘 — 지휘 무응답(5회). 사람 판단 대기: 예|아니오. 노드 파일: <경로>
```

- **지휘 생존을 즉시 확인한다** — `tmux has-session`과 `claude agents --json` 목록을 교차 확인하고, 죽었으면 워치독 주기를 기다리지 않고 T9로 간다.
- **재스폰이 막힌 국면이면** 사람 판단 대기가 `예`인 신고의 노드 파일 경로를 사람에게 올리는 통지에 함께 싣는다. **하한 미달(`LOWWIN`)로 지휘를 세운 경우의 통지는 `notify(결정 요청)`이다 — `notify(중단)`이 아니다.** 중단은 T11 상태의 통지이고 이 국면은 T11이 아니며, T11은 잔존 배선이라 「어차피 상한이 잡는다」를 전제로 유형을 고르는 자리가 없다. 판정 근거(바닥의 출처·값·가산분·계산된 임계)를 인자에 실어 사람이 창 설정을 고칠 수 있게 한다. T11 중단 상태에서 신고가 오면 그때는 `notify(중단)`에 싣는다.
- **재스폰이 예정돼 있으면 기록만 한다** — 새 지휘의 미회수 분기가 그 노드를 회수한다.
- **재스폰이 예정에 없는데(지휘가 살아 있고 상한·하한 미달도 아니다) 같은 노드의 신고가 다음 사이클에 또 오면** 지휘가 응답만 못 하는 상태다. 그 노드 ID를 적어 두고 두 번째 신고를 `STALL`의 처분(생존 질의 → 10분 무응답이면 T9)으로 보낸다. 새 시계를 걸지 않는다.

> **Do:** 이 한 줄에서 얻는 것은 지휘 사망의 조기 신호와 대기 노드의 존재 둘뿐이다
> **Don't:** 작업 세션에 되묻거나 질문을 사람에게 중계한다 — 질문 본문은 노드 파일에 남고 새 지휘가 읽는다. 창구가 나르면 대화 역할이 창구로 되돌아온다

## 전이 실행 (창구 몫)

| # | 창구가 하는 것 |
|---|---|
| T2 | 채널 모드면 `poller_pid` 기록. 장부를 가동으로 갱신 |
| T3 | **어느 사유든 선행 킬·소멸 검증을 먼저 마친다.** 통로 불성립이면 화면 모드로 폴백하고 진전 판정을 타지 않는다(streak 불변). 그 외 기동 실패면 **진전 판정(장부 누계 대조)을 거쳐** 같은 모드로 재시도하되 — 즉사·미생성 인스턴스는 보고를 낼 기회가 없어 결과가 항상 무진전이다 — **채널 모드에서 연속 2회면 화면 모드로 폴백한다.** 폴백 시 `channel.mode: screen`·`fallback_reason` 기록 + `notify(경고)` ⑤ |
| T4 | 지휘에 드레인 통지 발신. 워치독 상한을 60초로 줄인다 |
| T5 | 기록만 — 지휘가 스스로 알린 드레인이다 |
| T6·T7 | 킬 → **진전 판정·T11 가드** → 통과하면 재스폰 |
| T8 | 강제 정지 통지 → **유예(워치독 60초 반복, 최대 10분)** → 회신이 라운드 경계에 와 있거나 상한 도달 시 킬 → **진전 판정·T11 가드** → 통과하면 재스폰. `notify(경고)` ① |
| T9 | 킬(멱등) → **진전 판정·T11 가드** → 통과하면 재스폰 |
| T10 | 지휘를 킬하고 종료로 간다 |
| T11 | `notify(중단)`. **재스폰하지 않는다.** 장부는 유지한다(점유 지속) |
| T12·T13 | 사용자 지시 수신. **채널 모드에서도 이 지시는 창구 화면으로 받는다** — 중단은 지휘 부재라 채널이 응답하지 않는다 |
| T14 | 「종료 정리」 |
| T15 | T8 절차 준용(통지 → 워치독 반복 유예 최대 10분 → 킬 → **진전 판정·T11 가드** → 재스폰). `notify(경고)` ② |

**진전 판정과 T11 가드는 재스폰을 실행하기 전에 끝낸다.** 판정은 장부 누계 비교뿐이라 킬 직후 그 자리에서 계산되고, 가드가 걸리면 재스폰 대신 중단(T11)으로 간다 — 순서를 뒤집어 재스폰부터 하면 **가드가 세 번째 재스폰을 막을 기회 자체가 사라진다.** T3도 같다(기동 실패 갈래).

**유예 구간에도 워치독은 계속 돈다**(`protocol.md` 「시한을 재는 방법」). 한 방 `sleep`으로 잡으면 회신이 최대 한 주기 묵고, 그 10분간 생존·폴러 감시가 통째로 꺼진다.

**T8의 유예는 T4 드레인과 독립이다 — 둘 중 하나만 서는 것이 아니다.** T8은 단일 사건이 아니라 **통지 → 회신 대기 → 킬의 3단**이고 가운데 구간이 회수·적립의 창이다. **약한 임계와 강한 임계가 같은 값이어서 T4가 서지 않는 판에서도 T8의 창은 그대로 남는다** — "T4 소멸 → T8 직행 → 회수 기회 없음"은 오독이다.

**마감중에서는 지휘를 먼저 죽이지 않는다** — T8·T9·T15 사건 전에는 지휘의 회수 완료를 기다린다.

**열린 질문은 그 답을 입력으로 쓰는 전이 하나만 막는다.** 창구가 낸 대화상자가 창구의 턴을 붙잡아도 워치독과 큐 처리는 그대로 돌고, 막히는 것은 그 답을 입력으로 쓰는 전이의 판정·집행뿐이다. **아래는 어떤 열린 질문으로도 막지 않는다** — T4·T8·T9·T15(계측·사망·상한)와 T3(기동 실패의 폴백·재시도). 지휘의 포화와 생존은 사람의 답과 무관하고, 이것까지 묶이면 살아 있는 지휘의 포화가 그 구간에 아무에게도 안 보인다.

**종료는 예외로 두지 않는다 — 열린 질문이 있으면 판을 닫지 않는다.** 지휘의 완주 보고(T10)를 받고 잔여물이 0이어도, 창구에 답을 못 받은 질문이 남아 있으면 종료 조건이 서지 않는다. **창구는 지휘의 「이 질문은 종료를 막지 않는다」는 판정을 자기 근거로 쓸 수 없다** — 그것은 계획서 판단이라 창구 소유가 아니다. 대가는 장부 점유가 사람이 올 때까지 유지돼 그 저장소에 새 판을 못 여는 것이고, 그것을 알고 고른 쪽이다.

> **Do:** 질문을 열어 둔 채로도 계측·사망·상한 전이는 평소대로 평가·집행한다
> **Don't:** 열린 질문 하나로 판 전체를 멈추거나, 반대로 답을 버리고 종료한다

**T8·T15의 유예가 실제로 몇 분에 닫혔는지, 마감중 체류가 얼마였는지, 새 인스턴스의 기동 바닥이 얼마였는지는 창구만 잰다.** 상한에 닿지 않고 끝났어도 그 실측을 `protocol.md` 「결함 기록」에 `--kind 관측`으로 한 줄 남긴다 — 규약의 시한과 바닥은 이 실측으로만 교정되고, 재는 국면은 자주 오지 않는다. **지문은 실측치가 아니라 항목 고정값을 쓴다**(`t8-grace`·`t15-dwell`·`spawn-floor`) — 값을 지문에 넣으면 집계가 항목으로 묶이지 않는다.

## 재스폰 상한

**이 가드는 현행 진전 정의 아래에서 스스로 서지 않는다 — 잔존 배선이다.** 세 겹이 겹친다. ① 진전 판정의 입력이 지휘의 자기 신고값이라 **표 칸을 대기→진행으로 바꾸고 커밋하는 적립 행위 자체가 진전으로 집계된다** ② T8·T15가 최대 10분 유예를 주므로 임계를 기동 비용 아래로 내려도 지휘는 그 안에 적립하고 커밋한다 ③ 임계를 하한 검사 통과선까지 올리면 매 회차 진전이 서고, 그 아래로 내리면 `LOWWIN`이 재스폰을 먼저 세운다. **배선 자체는 정상이다** — 장부 카운터를 직접 세팅해 도달시키면 규약대로 발화한다. **아래 규칙은 그대로 집행하되, 이 절의 어느 문장도 T11을 안전선으로 전제하지 않는다** — 폭주 지휘를 실제로 끊는 것은 T15(마감중 체류 상한)·`LOWWIN`(하한 검사)·`STALL`(mtime 정체) 셋이고 **셋 다 무진전 반복이 아니라 다른 축을 잰다.** 무진전 반복 자체는 사람이 본다 — 「notify」의 `respawn_seq` 3 결정 요청이 그 자리다.

카운터는 장부의 `no_progress_streak` **하나뿐이다.** 사유별로 세지 않는다 — `reason`은 진단·`notify` 인자용 기록이다. 평가·갱신 시점은 기동중 진입 직전이다.

- **진전 판정은 여섯 전이에 있고 식이 하나다** — T3 기동 실패 갈래·T6·T7·T8·T9·T15. **`completed_units > units_at_spawn`이면 0으로 리셋, 거짓이면 +1**(`protocol.md` 「진전 보고」). **정상 경로와 킬 경로가 같은 판정을 쓴다** — 근거가 지휘의 자기 보고가 아니라 장부에 있기 때문이다.
- **T1·T12는 대상이 아니다** — `streak=0` 리셋 진입이라, 대상으로 넣으면 개시 즉시 +1이 된다. **T3의 통로 불성립 → 화면 폴백도 판정을 타지 않는다** — 실패의 원인(채널 환경)을 제거하고 다시 뜨는 모드 전환이지 같은 원인의 맹목 반복이 아니다.
- **즉사·상태 파일 미생성 인스턴스는 판정을 따로 두지 않아도 무진전이 된다** — 보고를 낼 기회가 없어 누계가 기준선에 머문다. T3 기동 실패의 +1과 채널 연속 2회의 +2가 그대로 나온다.
- **T11 가드 — 무진전 재스폰이 이미 2회 연속(`no_progress_streak == 2`)인데 또 무진전으로 기동중에 들어가려 하면 그 세 번째를 실행하지 않고 중단으로 간다.** 가드는 기동중을 향하는 전이(위 여섯)가 실행되기 직전에 평가한다.
- 진전 있는 재스폰이 반복되는 것은 상한 대상이 아니다 — 사이클마다 계획이 전진하므로 유한하게 수렴하는 정상 순환이다.

> **Do:** 진전 보고를 받을 때마다 `completed_units = max(completed_units, units_at_spawn + n)`으로 누계를 올린다
> **Don't:** 회차 요약("이번에 몇 개 완료했다")이나 `git log`로 판정한다 — 위임만 걸고 회수하지 못한 회차, 뒷정리와 범위 확정만 한 회차가 통째로 무진전으로 세어져 장부 누계가 실제와 갈린다. 그 숫자는 `notify(중단)` 인자와 사후 진단이 그대로 인용한다

## notify — 사람에게 알리기

**호출 주체는 창구뿐이다.** 구현은 모드로 갈린다.

- **화면 모드** — 창구 화면 출력.
- **채널 모드** — 창구가 지휘에 **중계 위임 발신**을 하고 지휘가 채널로 전달한다. 지휘 부재·중계 실패면 창구가 텔레그램 발신 API(`sendMessage`)를 직접 호출한다 — 발신 API는 `getUpdates` 폴링과 독립이라 폴러가 죽어 있어도 나간다. 실패도 조용하지 않다(`ok:false`+`error_code`)므로 `jq -r .ok`로 분기하고, **재시도하지 않는다.** 그것도 실패하면 창구 화면 출력이 최종 폴백이고, 그때는 장부 `channel.fallback_reason`에 미도달을 남긴다 — `reason`은 상태 전이 사유의 닫힌 열거라 통로 진단이 들어갈 자리가 아니다.

**능동 발신의 `chat_id` 조달처는 하나다.** 인바운드 메시지에는 chat_id가 실려 오지만 **먼저 말을 거는 발신에는 그것이 없고**, 무인 운전에서는 이쪽이 정상 경로다.

| 조달처 | **`<장부 디렉토리>/telegram/access.json`의 `allowFrom` 첫 값 하나뿐** |
|---|---|
| 조달 시점 | **발신 때마다 읽는다. 캐시하지 않는다** — 사람이 그 사이 값을 바꿀 수 있고, 캐시된 값으로 남의 대화방에 알림을 보내는 것이 가장 나쁜 실패다 |
| 봇 토큰 | `<장부 디렉토리>/telegram/.env` — 읽기만 하고 장부·로그·화면에 옮겨 적지 않는다 |
| 장부 필드 | **두지 않는다** — 조달처가 파일 하나로 확정되면 옮겨 적을 이유가 없다 |

> **Do:** 격리된 장부 디렉토리의 `access.json`만 읽는다
> **Don't:** 홈 기본 경로(`~/.claude/channels/telegram/`)로 폴백한다 — **규약이 명시적으로 배제한 자리다.** 점유 스캔 ③과 채널 환경 검사가 홈 기본 경로(BOB)와의 봇 공유를 개시 거부 사유로 두므로, 규약대로 선 채널 모드에서 홈 `access.json`을 읽으면 **알림이 남의 대화방으로 나간다**

**채널 모드의 `notify(결정 요청)`은 한 겹 더 있다** — 단방향이 아니라 답을 회수해야 한다. 지휘 생존으로 갈린다.

- **지휘가 살아 있으면 중계 위임이다.** 질문·선택지·질문ID를 `SendMessage`로 넘기면 지휘가 자기 `ask`와 같은 형태(인라인 버튼)로 내보내고 **도착한 답을 창구에 회신한다.** 질문의 소유자는 창구이므로 지휘는 판단하지 않고 나른다.
- **지휘가 없거나 창구가 정지시켰으면 창구는 보내기만 한다.** 텔레그램 발신 API로 *"이 프로젝트가 판단을 기다린다 — 창구 화면으로 와 달라"*를 알리고 **답은 창구 화면에서 받는다.** 질문 본문·선택지의 원본은 화면에 띄운 그대로이고, 채널로 나가는 것은 호출 신호다.
- **호출 신호에는 답을 받을 자리를 싣는다** — 프로젝트 이름 슬러그와 **그 자리에서 `ListAgents` 첫 줄로 다시 조회한 자기 이름·ref**. 프로젝트마다 창구가 하나씩 뜨므로 어느 화면으로 가야 하는지가 알림만으로는 가려지지 않는다. 이름이 유일하다는 보장이 없어 ref를 함께 싣는다.
- **창구 세션명을 짓지 않는다** — 창구는 tmux 세션이 아니라 사용자가 직접 띄운 일반 세션이라 지어낸 이름은 실재하지 않는 주소가 된다. **알림을 받은 사람은 그 기계의 창구 화면 앞에 있어야 답할 수 있고**, 주소록 운용이 이 기계로 닫혀 있어 **기계 식별자는 싣지 않는다.** 원격 복귀도, 여러 기계에서 같은 프로젝트를 동시에 도는 운용도 이번 범위 밖이다.

> **Do:** 신호를 만들 때마다 자기 이름·ref를 새로 조회해 싣는다
> **Don't:** 지휘 스폰 때 넘긴 이름·ref를 재사용한다 — 창구가 교체되면 그 값은 어디에도 남아 있지 않고, 사람에게 죽은 세션 주소를 안내하게 된다

> **Do:** 창구의 채널 사용은 발신 한 방향뿐이고, 답은 창구 화면에서 받는다
> **Don't:** 창구가 `getUpdates`로 답을 주우려 한다 — 같은 봇에 폴링이 둘이면 하나가 이기는 것이 아니라 **둘 다 409로 죽고**, 창구가 집어 간 업데이트는 지휘가 영영 보지 못한다

| 유형 | 호출 시점 | 전달 인자 |
|---|---|---|
| `notify(결정 요청)` | ① 무인 지휘가 답할 수 없는 질문·비가역 승인이 **화면 모드에서** 올라왔을 때 — 채널 모드에서는 지휘의 `ask`가 이 자리를 대신한다 ② **창구 자신이 사람 판단을 요하는 상태에 들어갔을 때** — 임계 하한 미달(`LOWWIN`), 점유 충돌의 고아 처분. **창구 발원은 두 모드 모두에서 호출된다** ③ **재스폰 상한 직전의 계속 여부** — **장부의 `respawn_seq`가 3 이상이면**(「스폰·재스폰」 5번의 +1을 하기 **전**의 값) 스폰을 멈추고 사람에게 계속할지 묻는다. **조건은 `>= 3`이지 `== 3`이 아니고, 집행 자리는 「스폰·재스폰」 4-1번이다** | 이름 슬러그, (있으면) 노드 ID, 질문 원문, 태그(`[결정 필요]`/`[대화 필요]`), 응답 회송 주소(자기 주소록 이름·ref) |
| `notify(중단)` | T11 | 이름 슬러그, `reason`, `no_progress_streak`, **`completed_units`**, `respawn_seq`, 장부 경로, 마지막 인스턴스 UUID, **이번 판의 미처리 사건 건수와 로그 경로**(`dl-incident.sh --count`). **누계를 함께 실어야 사람이 "정말 진전이 없었는가"를 알림 하나로 판별한다** |
| `notify(완료)` | T14 | 이름 슬러그, 계획서 경로, 잔여 후속·유보 유무, **`보류(파생)` 건수**, 잔존 워크트리 보고, **미처리 사건 건수와 로그 경로**(`dl-incident.sh --count`) — 판이 끝나는 자리가 사람이 사건을 회수할 두 번째 자리다 |
| `notify(경고)` | 아래 일곱뿐이다 | 이름 슬러그, 사유, 근거 경로(장부·상태 파일·계획서) |

**재스폰 상한 직전에 묻는다 — 판정 입력은 `respawn_seq` 하나다.** 이것은 창구가 스폰할 때마다 자기 손으로 올리는 값이라 지휘가 무엇을 신고하든 흔들리지 않는다 — 지휘의 자기 신고(`completed_units`)를 쓰지 않으므로 T11을 못 세운 세 겹이 여기에는 걸리지 않는다. **진전 유무는 판정에 넣지 않는다.** 사람이 계속을 지시하면 카운터를 그대로 둔 채 스폰하고, **같은 물음은 이후 재스폰마다 다시 선다** — 판정은 `respawn_seq >= 3`이므로 4회차·5회차에도 스폰 직전마다 똑같이 서고, **한 번 받은 계속 지시가 다음 스폰을 면제하지 않는다.** T11 중단은 잔존 배선으로 남으므로 `notify(중단)`→T12·T13 경로도 그대로 두되, **정상 운전에서 사람이 개입하는 자리는 이 결정 요청 하나다.**

> **Do:** `respawn_seq`가 3 이상이면 스폰 실행 **직전마다** 멈추고 묻는다 — 4회차 이후에도 매번 선다
> **Don't:** 첫 번째 물음에 받은 답을 이후 스폰의 승인으로 재사용한다 — 그러면 사람 개입이 4회차부터 영영 서지 않는다
> **Don't:** 진전 유무로 「직전」을 판정한다 — T11을 못 세운 이유가 그대로 옮겨 온다

`notify(경고)`의 닫힌 목록: ① 강한 임계 발화(T8) ② 마감중 체류 상한 초과(T15) ③ 신뢰 조상 부재로 스폰 불가 ④ 점유 충돌로 개시 거부·고아 의심 증거 보고 ⑤ 채널→화면 폴백 ⑥ 폴러 탈취(`CHJACK`) ⑦ 노드 실패 — 무응답 실패·머지 검증 실패.

> **Don't:** 목록에 없는 사건에 경고를 만들거나, 부르는 자리가 없는 항목을 목록에 남긴다 — 발신 실패는 「발신 실패 처분」이 네 방향 전부에 처분을 정해 두었으므로 경고를 부르지 않는다

공통 인자: 발생 시각, 유형, 본문 한 단락, 응답 필요 여부.

## 창구 교체 복원

창구는 사용자 대면 세션이라 예고 없이 교체된다. **복구의 주체는 새 창구다.**

1. 장부를 읽어 `state`·`run_mode`·`commander`(이름·UUID·`addr`)·`no_progress_streak`·`noread_streak`·**`completed_units`·`units_at_spawn`**·`phase_entered_at`·`human_wait`·`window_size`·**`measured_floor`·`threshold_override`**·`channel`을 복원하고, **동시에 `warden`을 자기 것(자기 세션 UUID·기동 시각)으로 갱신한다** — 이 갱신이 인수의 표식이다. **`measured_floor`에 값이 있으면 이후 하한 검사의 바닥은 상수가 아니라 그 값이다**(「스폰·재스폰」 6번) — 뒤의 두 블록을 빠뜨리면 새 창구가 검사를 상수로 되돌려 친다.
2. `tmux has-session -t "=dl-<이름 슬러그>-cmd"`로 지휘 생존을 확인한다. 죽었으면 T9로 처리한다.
3. 살아 있으면 지휘에 **`commander.addr`로 선발신**해 자기 새 주소를 알린다. 동명 모호성이면 `on this machine` 행 ref로 재발신하고 성공한 주소로 `addr`을 갱신한다.
4. 복원된 상태의 워치독 사이클을 재개한다.

**강제 정지 유예 도중에 교체됐으면 유예를 처음부터 다시 잰다.** 장부에 유예 개시 시각을 두지 않으므로(`phase_entered_at`은 마감중 진입 시각이지 유예 개시 시각이 아니다) 남은 시간을 알 근거가 없다. 필드를 늘리지 않고 다시 재는 쪽으로 고정한다 — 최악이 지휘에게 유예가 한 번 더 주어지는 것뿐이라 안전 방향으로만 어긋난다. **강제 정지 통지도 다시 보낸다** — 앞 창구가 보냈는지 알 수 없고 지휘 쪽에서 중복 통지는 무해하다(적립은 멱등이다).

> **Don't:** 경과를 추정해 유예를 이어서 잰다 — 새 창구가 "이미 다 썼다"고 보아 즉시 킬하는 경로가 열린다

## 종료 정리 (T14)

지휘를 킬하고, 작업 tmux(`dev-<이름 슬러그>-` 접두)와 `node/*` 워크트리 잔재를 확인한다. **미커밋·미머지 워크트리는 강제 제거하지 않고 경로와 사유를 보고한다.** 다른 프로젝트 접두의 세션은 건드리지 않는다. 정리가 끝나면 `notify(완료)`를 호출하고 **장부 항목을 제거한다** — 이것이 점유 해제다.

## 축소 운전과 2계층 복귀

- **통로 축소 운전 = 화면 모드.** 채널이 서지 않아도 시스템 전체는 화면 모드로 완주한다.
- **감시 축소 운전.** 워치독만 실패한 경우 지휘의 자가 계측은 독립이므로 유지된다. 사용자가 창구 화면·`tmux attach`로 수동 감시하고, 재스폰 요청이 오면 창구가 수동 확인 후 실행한다.
- **2계층 복귀**(3계층 운용이 서지 않을 때) — ① 장부 항목 제거 ② **대화방 정리를 지휘에게 시킨다**(채널 모드였고 지휘가 아직 살아 있을 때만 — 남은 미응답 버튼 회수와 마지막 중단 알림은 채널 도구를 가진 지휘만 할 수 있다. 지휘가 이미 죽었으면 버튼과 알림은 포기하고 사유를 사람에게 남긴다) ③ 도는 세션 정리(`dl-<이름 슬러그>-cmd`·`dev-<이름 슬러그>-*`) ④ 폴러 소멸 확인(죽은 pid의 `bot.pid`만 제거) ⑤ 워크트리 회수(미커밋·미머지는 경로·사유 보고) ⑥ 스킬 파일을 씨앗 커밋으로 되돌림. **상태 디렉토리와 `.env`는 지우지 않는다 — 보존·삭제는 사람 판단이다.**
  > **Do:** 채널 도구가 필요한 정리는 지휘를 죽이기 전에 시킨다
  > **Don't:** 지휘를 먼저 죽이고 나서 대화방 정리를 시도한다 — 창구에는 그 도구가 없다
