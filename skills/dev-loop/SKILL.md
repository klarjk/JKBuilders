# /dev-loop

`/dev`는 세션마다 정지·인수인계하고 사용자가 `/clear` 후 재호출해야 한다. `/dev-loop`는 이 재호출 루프를 자동화한다 — **노드를 별도 Claude 세션에 위임**하고 DEV_PLAN이 `done`이 될 때까지 반복한다.

## 핵심 개념

- **작업 세션 = tmux로 띄운 별도 Claude 세션.** 노드 1개당 1개를 메인이 생성하고, 완료 후 메인이 종료한다. 별도 프로세스이므로 컨텍스트가 완전히 격리되고 중첩 스폰 계층을 소모하지 않는다.
- **메인이 직접 처리하는 노드는 둘뿐이다.** ① 되돌릴 수 없는 실행(배포·데이터 이관·병렬 노드 합류) — 작업 세션은 승인 프롬프트 없이 실행하므로 제동할 사람이 없다. ② 주체가 사용자인 디자인 노드 — 작업 세션에는 시안을 고를 사람이 없다.
- **DEV_PLAN 갱신은 메인만 한다.** 작업 세션에는 읽기 전용을 명시한다.
- **작업 세션은 항상 워크트리에서 돈다.** 단독 실행이어도 워크트리를 만든다 — 메인과 같은 트리를 쓰면 커밋이 서로 잠금을 다툰다.
- **완료 판정은 산출물·커밋 실재 + 보고의 `검증:` 결과가 통과일 때로 한다.** 답신 개수로 판정하지 않는다 — 한 세션에 여러 건을 보내면 답신이 하나로 합쳐진다. 산출물과 커밋이 있어도 검증 결과가 실패·중단·누락이면 완료로 보지 않는다("세션 위임" 5번).
- **동시 실행은 3개까지.** 구현 노드는 담당 파일 교집합이 비고, 단위·통합 테스트가 고정 포트·공유 DB 파일·외부 서비스를 동시에 잡지 않을 때만 동시에 둔다(`/dev` 병렬 배치 규칙과 동일 기준). 조사·연구·설계 노드는 읽기·산출 전용이므로 이 조건을 적용하지 않는다.
- **컨텍스트 예산은 메인 세션 기준.** 둘 중 먼저 걸리는 쪽에서 DEV_PLAN을 갱신·커밋한 뒤 "새 세션에서 `/dev-loop --resume <DEV_PLAN 경로>`로 이어가세요"를 안내하고 정지한다.
  - 위임 노드를 **12개 완료**
  - 메인이 직접 처리한 노드가 **3개 누적**

## 진입 (매 호출, 메인 직접)

1. `--resume <경로>`가 있으면 그 DEV_PLAN을 사용, 없으면 `docs/dev/plan/`을 스캔한다(경로 규약은 `/dev`와 동일).
2. DEV_PLAN이 없으면 → 아래 "메인 루프" 1번(신규 계획)부터.
3. `status: in-progress` DEV_PLAN이 있으면 → "메인 루프" 2번(다음 노드)부터. 2개 이상이면 제목을 1줄씩 보여주고 어느 것을 이어갈지 질문 후 답 대기.

## 메인 루프

DEV_PLAN이 `done`이 되거나 실행 가능 노드가 없을 때까지 아래를 반복한다.

1. **DEV_PLAN이 없으면** `/dev`를 Skill로 호출해 계획 세션을 메인이 직접 수행한다 — 인테이크는 사용자와의 왕복이라 이미 대화 중인 메인이 하는 편이 빠르다. 계획이 서면 이 루프를 계속한다.
2. **DEV_PLAN을 Read**해 노드 표에서 **선행이 모두 완료·건너뜀이면서 상태가 대기**인 노드를 찾는다. 그중 `조건` 칸이 채워진 노드는 선행 결과로 판정해 미선택 갈래를 `건너뜀`으로 바꾼다(`/dev` Phase 2의 분기 정리와 동일). 남는 노드가 없으면 → 대기 중인 사용자·외부 노드와 사용자 직접 접속으로 넘겨 `진행`에 머문 노드를 함께 안내하거나, 완료 보고 후 종료.
3. **노드 표의 `종류` 칸으로 분기**:
   - **실행 노드·디자인 노드** → 메인이 `/dev`를 Skill로 호출해 그 노드만 처리한다(백업·복구 경로 확인, 합류 노드 절차, 시안 확정은 `/dev`가 가진다).
   - **그 외 노드(조사·연구·설계·구현)** → 아래 "세션 위임"을 실행한다. 실행 가능한 노드가 여럿이면 위 동시 실행 조건에 맞는 것끼리 최대 3개까지 동시에, 아니면 표의 위쪽 것부터 하나씩. **구현 노드를 2개 이상 동시에 띄우려면 그 노드 전체를 선행으로 삼는 합류 노드(종류=실행, 주체=메인)가 DEV_PLAN에 있어야 한다** — 계획이 직렬로 그려 둔 노드를 메인 판단으로 동시에 돌리는 경우가 여기 걸린다. 없으면 메인이 노드 표·흐름도에 합류 노드를 추가하고 커밋한 뒤 시작한다. 노드별 머지는 "세션 위임" 6번에서 이미 끝나므로, 그 합류 노드로 `/dev`를 호출할 때 args에 "브랜치는 이미 메인에 병합됐으니 합류 절차 1번(브랜치 머지)을 생략하고 2번(전체 스위트)부터 수행하라"를 명시한다.
4. **회수·갱신.** `nodes/<노드ID>.md`를 Read해 `## 계획 변경 제안`과 발견된 후속·유보 항목이 있으면 DEV_PLAN에 반영하거나 사용자에 1줄 보고한다. 이어서 노드 표의 상태를 `완료`로 바꾸고 작업 세션이 보고한 산출 경로를 `산출` 칸에 기록한다. 갱신 직후 메인이 DEV_PLAN 변경분을 태그 없이 커밋한다. 전 노드가 완료·건너뜀이면 `status: done`.
5. **정지 확인.** 이번 호출의 누적을 센다 — 위임 12개 또는 메인 직접 3개에 도달했으면 DEV_PLAN을 커밋하고 "핵심 개념"의 정지 안내를 출력한 뒤 종료한다. 미도달이면 1번으로.

> **Do:** 되돌릴 수 없는 실행만 메인이 쥐고, 나머지는 세션에 넘긴다
> **Don't:** 배포·데이터 이관·브랜치 합치기를 작업 세션에 시키거나, 합류 노드 없이 구현 노드를 동시에 띄운다

## 세션 위임

`<세션명>`은 `~/.claude/scripts/dev-view.sh --name <노드ID>`가 출력하는 값이다(`dev-<프로젝트 슬러그>-<노드 ID 소문자>` 형태, 예: `dev-ironheart-n3`). 노드마다 이 명령으로 한 번 얻어 그 노드의 모든 tmux 명령에 쓴다 — 이름을 직접 지어 쓰지 않는다. 프로젝트 이름이 들어가므로 다른 프로젝트가 같은 노드 ID를 돌려도 세션이 겹치지 않는다.

1. **워크트리 준비.** `git worktree add <경로> -b node/<노드ID>`. 동시 실행이어도 **하나씩 순차로** 만든다 — 동시에 만들면 저장소 설정 파일이 잠금을 다툰다. 중단된 노드를 재개하는 것이면 `git worktree list`로 기존 워크트리를 찾아 그대로 재사용한다.
2. **세션 생성.** `tmux new-session -d -s <세션명> -c <워크트리 절대경로> 'claude'`. 화면에 뜨지 않고 백그라운드에서 돈다. 생성 직후 `~/.claude/scripts/dev-view.sh`를 인자 없이 실행해 작업 세션 화면을 분할 창에 비춘다 — 첫 호출이 창을 열고, 이후 호출은 그때 살아 있는 작업 세션에 pane을 맞춘다(다른 프로젝트의 세션도 함께 뜬다). **뷰어 호출이 실패해도 위임은 그대로 진행한다** — 뷰어는 읽기 전용 미러라 노드 처리와 무관하다. 반면 `tmux new-session` 자체가 실패했으면 세션이 없는 것이므로 3번으로 가지 않고 Fallback으로 간다.

> **Do:** 세션을 만든 뒤·정리한 뒤에 인자 없이 불러 뷰어가 스스로 목록을 잡게 한다
> **Don't:** 세션명을 인자로 넘기거나, 뷰어 pane을 직접 만들고 지운다
3. **주소 확보.** `ListAgents`로 `tmux <세션명>:`을 포함한 행을 찾아 `<이름> [<ref>]`를 통째로 얻는다. **발신에는 반드시 ref를 붙인다** — 이름만으로는 거부된다. 등록에 몇 초 걸리므로 첫 조회에 없으면 1회 더 조회하고, 그래도 없으면 Fallback으로 간다. 얻은 주소는 그 노드가 끝날 때까지 재사용한다 — 사이클마다 재조회하지 않는다.
4. **위임.** 아래 "위임 메시지"를 `SendMessage`로 보낸다.
5. **대기·검증.** 답신이 오면 워크트리에서 `git log -1 --format=%H`로 커밋을, 보고에 산출 경로가 있으면 그 파일 실재를 확인한다. **검증은 여기까지다 — 메인은 테스트를 돌리지 않는다.** 작업 세션이 `/impl` 안에서 이미 회귀·끝단 검증을 마쳤으므로 같은 트리를 다시 검사하는 셈이다. 대신 **보고의 검증 결과가 실패·중단이면 커밋과 산출 파일이 있어도 완료로 처리하지 않고** 노드 상태를 `실패`로 두고 사용자에 1줄 보고한다. 결과 줄이 아예 없는 보고도 통과로 보지 않고 그 한 줄만 재요청한다. 다만 `검증:` 값이 `해당 없음`·`중단: 적용 가능한 테스트 없음`인데 그 노드가 코드를 고친 노드면, 아무 검증도 돌지 않은 것이므로 메인이 변경 범위 회귀를 1회 돌린다. **답신 없이 10분이 지나면** `tmux capture-pane -t <세션명> -p | tail -20`으로 화면을 본다 — 작업 중이면 계속 대기, 멈춰 있으면 "진행 상황을 SendMessage로 보고하라"를 1회 재전송한다. 재전송 후 10분이 더 지나도 커밋·답신이 없으면 노드 상태를 `실패`로 두고 Fallback으로 간다.
6. **머지·정리.** 검증되면 메인이 `node/<노드ID>`를 `git merge --ff-only`로 먼저 시도한다. **통과하면 머지 결과가 작업 세션이 검증한 트리와 같으므로 테스트를 돌리지 않는다.** 거절되면 메인이 앞서 있는 것이니 `git diff --name-only node/<노드ID>...HEAD`(분기 이후 메인에만 들어온 변경)로 코드 파일에 닿는지 본다 — DEV_PLAN·`nodes/*.md` 등 문서뿐이면 그대로 머지하고 재실행하지 않고, 코드에 닿았으면 머지 후 **변경 범위 회귀만 1회** 돌린다(전체 스위트·e2e는 합류 노드가 담당한다). 충돌하면 멈추고 사용자에 보고하며, 해소 후 그 노드 머지부터 재개한다. DEV_PLAN·`nodes/<ID>.md`가 충돌하면 메인 워킹트리 쪽을 남긴다. 머지가 끝나면 `tmux kill-session -t <세션명>`과 `git worktree remove`로 정리하고, `~/.claude/scripts/dev-view.sh --sync`를 인자 없이 실행해 뷰어에서 그 pane을 거둔다. 도는 세션이 하나도 없으면 창은 마지막 화면을 유지하고 다음 노드가 뜰 때 갱신된다.

> **Do:** 이어붙이기로 머지되면 그대로 넘어가고, 코드 파일이 섞였을 때만 변경 범위를 다시 본다
> **Don't:** 답신 도착만으로 완료 처리하거나, 작업 세션에 머지를 시키거나, 세션이 이미 검증한 트리에 메인이 스위트를 다시 돌린다

## 사용자 개입

**어느 방식이 필요한지는 작업 세션이 판정해 태그로 알린다.** 메인은 태그로 라우팅한다.

- `[결정 필요]` — 선택지가 정해져 답 하나로 진행되는 질문. 메인이 사용자에게 전달하고 답을 세션에 되돌린다.
- `[대화 필요]` — 요구사항·범위를 캐야 해서 되묻기가 이어질 질문. 중계하지 않고 "`tmux attach -t <세션명>`으로 직접 이어가세요"를 안내한 뒤, 그 노드를 `진행`으로 두고 다른 실행 가능 노드로 넘어간다.

**같은 노드에서 `[결정 필요]` 왕복이 3회를 넘으면** 세션의 판정이 틀린 것으로 보고 `[대화 필요]`와 같이 처리한다. 사용자가 마쳤다고 알리면 "세션 위임" 5번(검증)부터 재개한다.

> **Do:** 라우팅은 태그로 하고, 왕복이 3회를 넘으면 세션의 판정을 뒤집는다
> **Don't:** 세션의 질문을 메인이 임의로 답하거나, 긴 인테이크를 중계로 끌고 간다

## 위임 메시지

```
[역할] 너는 노드 <ID> 전담 세션이다.
- 구현 노드면: Skill 도구로 /impl을 호출해 아래 범위를 구현한다.
- 그 외 노드면: Skill 도구로 /dev를 `--resume <DEV_PLAN 경로>`로 호출하고, args에 "노드 <ID> 1개만 처리하고 정지하라. DEV_PLAN은 노드 표·흐름도뿐 아니라 아키텍처 결정·후속·유보 작업까지 **어떤 섹션도** 갱신하지 마라 — 기록할 것은 모두 `nodes/<ID>.md`의 `## 계획 변경 제안` 절에 적어라. `/clear` 후 이어가라는 안내는 출력하지 마라"를 명시한다.

[환경 — 반드시 준수]
- 네 앞에 사용자는 없다. 화면에 출력하는 평문은 아무에게도 도달하지 않는다.
- 작업 폴더는 이 워크트리 안으로 한정한다. 밖의 파일을 수정하지 마라.
- DEV_PLAN은 읽기 전용이다. 계획을 바꿔야 한다고 판단하면 docs/dev/plan/nodes/<ID>.md의 `## 계획 변경 제안` 절에 적고 보고만 하라.
- 머지·배포·되돌릴 수 없는 조작은 하지 마라. 네 브랜치에 커밋까지만 하라.

[사용자 개입]
- 결정·입력·확인이 필요하면 작업을 멈추고, 이 메시지의 `from` 값을 `to`에 그대로 복사해 SendMessage로 물어라. 답이 오면 재개하라.
- 질문 앞에 성격을 태그로 붙여라 — 선택지가 정해져 답 하나로 진행되면 `[결정 필요]`, 요구사항·범위를 캐야 해서 되묻기가 이어질 것 같으면 `[대화 필요]`.

[완료 보고]

- 검증이 통과하지 않았거나 사이클 상한으로 중단됐으면 완료가 아니라 실패로 보고하라. 커밋이 남아 있다는 사실로 완료를 대신하지 마라.
```

## Fallback

세션 위임의 어느 단계든 실패하면(워크트리 생성 거부·세션 미등록·재촉 후에도 진전 없음) **1회 재시도**하고, 그래도 실패하면 그 노드에 한해 **메인이 직접 처리**한다(구현이면 `/impl`, 그 외면 `/dev`). 넘어가기 전에 그 노드로 만든 tmux 세션을 종료하고, 커밋이 없는 워크트리는 제거한다. 사용자에게 "세션 위임 실패 → 노드 <ID>는 메인 직접 처리" 1줄 보고한다. 컨텍스트 격리는 포기하되 진행은 보장한다. 다음 노드는 다시 세션 위임을 시도한다.

## 주의사항

- 노드 실행 로직을 `/dev-loop`에 복제하지 않는다 — 작업 세션이 `/dev`·`/impl`을 호출하게 하고, 본 스킬은 세션 생성·중계·상태 갱신만 한다.
- 커밋·태그는 `/dev`의 태그 없는 세션 종료 커밋 규칙을 따른다.
- 정지·완료로 끝내기 전에 `tmux list-sessions`·`git worktree list`로 이번 호출에서 만든 세션과 `node/*` 워크트리를 확인한다. **정리 대상은 이 프로젝트 접두사(`dev-<프로젝트 슬러그>-`)를 가진 세션뿐이다** — 다른 프로젝트의 `dev-*` 세션은 건드리지 않는다. 머지된 것은 제거하고, 미커밋·미머지로 남은 것은 경로와 사유를 사용자에게 보고한다. 정리가 끝나면 `~/.claude/scripts/dev-view.sh --close`를 실행한다 — 다른 프로젝트 작업 세션이 남아 있으면 스크립트가 닫기를 거부하고 그 목록을 알리는데, 이때는 창을 그대로 두고 넘어간다.
- 분할 창은 스냅샷을 비추는 읽기 전용이다. 작업 세션에 직접 입력이 필요하면 **사용자가** 별도 창에서 `tmux attach -t <세션명>`으로 붙는다.

> **Do:** 뷰어 조작은 `dev-view.sh`의 실행·`--sync`·`--close`로만 한다
> **Don't:** 메인이 `dev-view` 세션의 pane을 직접 만들거나 죽이거나, 작업 세션에 attach해 화면 크기를 바꾼다
- 날짜는 현재 세션 컨텍스트의 날짜를 쓴다(추측 금지).
