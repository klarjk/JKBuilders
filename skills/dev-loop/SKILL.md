# /dev-loop

`/dev`는 세션마다 정지·인수인계하고 사용자가 `/clear` 후 재호출해야 한다. `/dev-loop`는 이 재호출 루프를 자동화한다 — **구현 외 노드는 `/dev`에 위임(메인 직접)**, **구현 노드만 러너 서브에이전트로 격리 실행**하며 DEV_PLAN이 `done`이 될 때까지 반복한다.

## 핵심 개념

- **러너 = teammate.** 구현 노드 1개당 러너 1개를 `name` 지정으로 스폰한다(teammate·깊이 0·Agent 도구 보유). 러너가 `/impl`의 오케스트레이터 역할을 대행한다. `name`을 생략하면 Agent 도구를 잃어 `/impl` 내부 스폰이 불가능하다.
- **손자 통지는 메인으로 온다.** 러너가 스폰한 `/impl` 내부 에이전트(손자)의 완료 통지는 러너가 아니라 메인에 배달된다. 러너는 손자 결과를 통지·반환값으로 받지 못하므로 **`_workspace/` 산출 파일로만** 확인한다.
- **러너는 항상 1개, 직렬.** DEV_PLAN이 구현 노드를 병렬로 배치했더라도 **자동 루프에서는 한 번에 하나씩** 처리한다(중계 왕복이 노드당 6~10회라 동시 진행 시 누락 위험이 크다). 병렬 실행이 필요하면 `/dev`로 수동 진행한다. 직렬 처리이므로 **노드 워크트리를 만들지 않고** 메인 워킹트리에서 `/impl`을 돌린다 — 합류 노드에서는 머지가 no-op이 되고 전체 스위트 1회만 남는다.
- **컨텍스트 예산은 메인 세션 기준.** 구현 세부는 러너·손자에 격리되지만 그 외 노드는 메인에 직접 누적된다. 자동 루프에는 `/dev`의 "무거운 노드 후 정지" 안전판이 없으므로 아래로 대신한다. 둘 중 먼저 걸리는 쪽에서 DEV_PLAN을 갱신·커밋한 뒤 "새 세션에서 `/dev-loop --resume <DEV_PLAN 경로>`로 이어가세요"를 안내하고 정지한다.
  - `/dev`에 위임한 노드(구현 외)가 **이번 호출에서 3개 누적**
  - 러너 루프를 **5회 완료**

## 진입 (매 호출, 메인 직접)

1. `--resume <경로>`가 있으면 그 DEV_PLAN을 사용, 없으면 `docs/dev/plan/`을 스캔한다(경로 규약은 `/dev`와 동일).
2. DEV_PLAN이 없으면 → 아래 "메인 루프" 1번(신규 계획)부터.
3. `status: in-progress` DEV_PLAN이 있으면 → "메인 루프" 2번(다음 노드)부터. 2개 이상이면 제목을 1줄씩 보여주고 어느 것을 이어갈지 질문 후 답 대기.

## 메인 루프

DEV_PLAN이 `done`이 되거나 실행 가능 노드가 없을 때까지 아래를 반복한다.

1. **DEV_PLAN이 없으면** `/dev`를 Skill로 호출해 계획 세션을 수행하게 한다(대화형 인테이크·발견 우선 배치·노드 배치는 `/dev` Phase 1이 메인 직접 처리). `/dev`가 계획을 세우고 정지·복귀하면 이 루프를 계속한다.
2. **DEV_PLAN을 Read**해 노드 표에서 **선행이 모두 완료·건너뜀이면서 상태가 대기**인 노드를 찾는다. 그중 `조건` 칸이 채워진 노드는 선행 결과로 판정해 미선택 갈래를 `건너뜀`으로 바꾼다(`/dev` Phase 2의 분기 정리와 동일). 남는 노드가 없으면 → 대기 중인 사용자·외부 노드를 안내하거나 완료 보고 후 종료.
3. **노드 표의 `종류` 칸으로 분기**:
   - **구현 노드** → 아래 "러너 루프"를 실행한다. 실행 가능한 구현 노드가 여럿이면 표의 위쪽 것부터 하나씩. 완료 후 1번으로.
   - **그 외 노드(조사·연구·설계·디자인·실행)** → `/dev`를 Skill로 호출하되 args에 "이번 호출은 노드 <ID> 1개만 처리하고, 다음 노드가 가볍더라도 이어가지 말고 정지·복귀하라. `/clear` 후 이어가라는 안내는 출력하지 말고 '노드 <ID> 처리 완료'로 대체하라"를 명시한다(`/dev`의 가벼움 연속처리 규칙 무효화 + 수동 재개 안내 억제). 복귀 후 1번으로.
4. **구현 노드 완료 시에만** 메인이 노드 표의 상태를 `완료`로 바꾸고 러너가 보고한 workspace 경로(있으면)를 `산출` 칸에 기록한다. 그 외 노드는 `/dev`가 이미 갱신했으므로 메인이 다시 갱신하지 않는다. 갱신 직후 메인이 DEV_PLAN 변경분을 태그 없이 커밋한다 — `/dev`가 재호출되지 않는 순수 구현 루프에서도 커밋 누락을 막는다. 전 노드가 완료·건너뜀이면 `status: done`.

5. **정지 확인.** 이번 호출의 누적을 센다 — `/dev` 위임 3회 또는 러너 루프 5회에 도달했으면 DEV_PLAN을 커밋하고 "핵심 개념"의 정지 안내를 출력한 뒤 종료한다. 미도달이면 1번으로.

> **Do:** 노드 종류를 먼저 판정하고, 구현 노드는 `/dev`를 호출하지 않고 러너로 직접 처리한다
> **Don't:** 구현 노드에까지 `/dev`를 호출한다 — `/dev`가 러너 없이 `/impl`을 직접 실행해 컨텍스트 격리가 깨진다

## 러너 루프 (구현 노드, 메인)

1. **러너 스폰.** `Agent(name="impl-runner-<노드ID>", subagent_type="general-purpose")`로 스폰한다. 위임 프롬프트는 아래 "러너 위임 프롬프트"를 쓴다. 이미 시작됐다 중단된 노드면(노드 표 `산출` 칸에 workspace 경로 기록) 위임에 `/impl --resume <경로>`를 명시한다.
2. **대기·중계.** 러너 스폰 후 메인은 아래 이벤트만 처리한다. 러너가 스폰한 손자 산출물 본문은 읽지 않는다.
   - **손자 완료 통지 도착** → 러너에게 `SendMessage({to:"impl-runner-<N>", message:"네 서브에이전트가 완료됐다. _workspace 산출 파일을 Read해 다음 단계를 진행하라."})`로 깨운다.
   - **러너가 "사용자 결정 필요"를 SendMessage로 보냄** → 그 질문을 사용자에게 전달하고 답을 받아 `SendMessage`로 러너에 되돌린다.
   - **러너가 "세션 완료 + workspace 경로"를 SendMessage로 보냄** → 3번으로.
3. **완료 판정.** 러너 보고에 `workspace=<경로>`가 있으면 그 `state.json`의 `phase` 종료 상태를 실재로 검증한다. workspace가 없으면(`/impl`이 소·중(검증 없음) 경량 경로로 판정 — state.json 미생성) 러너의 SendMessage 완료 보고 본문과 해당 노드 범위 파일의 최근 git 커밋(`git log -1 --format=%H -- <범위 경로>`)으로 검증한다. 러너 보고·agentId 통지만으로 판정하지 않는다(통지 오귀속 대비). 검증되면 러너 루프를 종료한다.

> **Do:** 손자 완료 신호로만 러너를 깨우고, 산출은 러너가 파일에서 읽게 한다
> **Don't:** 손자 통지 본문을 메인이 해석해 러너에게 요약 전달한다 — 메인 컨텍스트만 쌓이고 러너는 어차피 파일을 읽어야 한다

## 러너 위임 프롬프트

```
[역할] 너는 구현 노드 <ID>의 오케스트레이터다. Skill 도구로 /impl을 호출해 아래 범위를 구현한다. 너 자신이 /impl의 메인 오케스트레이터 역할을 맡는다.

[중첩 스폰 제약 — 반드시 준수]
- 네가 스폰하는 서브에이전트에는 name 파라미터를 쓰지 마라(teammate는 teammate를 못 만든다 — 스폰이 거부된다).
- 네가 스폰한 서브에이전트(손자)의 완료 통지는 너에게 오지 않고 메인에게 간다. 손자 결과를 통지·반환값으로 받으려 기다리지 마라.
- 손자를 스폰한 뒤 할 일이 없으면 그대로 멈춰라. 메인이 SendMessage로 "서브에이전트 완료"를 알리면 재개해, /impl이 약속한 _workspace 산출 파일(state.json·NN_*.md)을 Read해서 다음 단계를 진행하라.
- 손자 결과를 추측·창작하지 마라. 반드시 산출 파일 실재로 확인하라.

[사용자 개입]
- 구현 중 사용자 결정·입력·확인이 필요하면 작업을 멈추고 SendMessage({to:"main", message:"[결정 필요] <질문>"})으로 메인에 물어라. 메인이 답을 SendMessage로 주면 재개하라.

[완료 보고]
- 노드 구현이 끝나면 SendMessage({to:"main", ...})로 보고하라. state.json이 있으면 `workspace=<절대경로>`를, 없으면(경량 경로) 변경한 파일 경로 목록 + 커밋 SHA를 포함하고, 이어서 요약 5문장 이내를 담아라. 평문 출력은 메인에 도달하지 않으니 반드시 SendMessage로 보내라.

[입력]
- 구현 범위: <노드 표의 해당 범위>
- 담당 파일 집합: <노드 표 `담당 파일` 칸, 있으면 — 이 밖의 파일은 수정하지 말고 발견 사항으로만 보고하라>
- 확정 ADR 경로: <있으면 — /impl이 설계 단계를 생략하고 채택>
- 성공 조건: <그 노드에 배분된 조건 원문, 있으면>
- DEV_PLAN 경로: <경로> (읽기 전용. 노드 표·흐름도 갱신은 메인이 한다)
```

## Fallback (중첩·SendMessage가 실패할 때)

러너 스폰·재개·보고 중 하나가 **연속 2회** 실패하면(재시도 1회 후에도 무응답·손자 통지 유실·SendMessage 미도달) 그 노드에 한해 **러너 없이 메인이 직접 `/impl`을 Skill로 호출**해 진행하고, 사용자에게 "러너 위임 실패 → 노드 <ID>는 메인 직접 처리" 1줄 보고한다. 컨텍스트 격리는 포기하되 진행은 보장한다. 다음 노드는 다시 러너 루프를 시도한다.

## 주의사항

- 구현 외 노드는 반드시 `/dev`에 위임한다 — 대화형 인테이크·노드 배치·ADR 판정 로직을 `/dev-loop`에 복제하지 않는다.
- 커밋·태그는 `/dev`의 태그 없는 세션 종료 커밋 규칙을 따른다(구현 노드 완료 후 갱신·커밋은 메인 루프 4번에서 메인이 수행).
- 날짜는 현재 세션 컨텍스트의 날짜를 쓴다(추측 금지).
- 본 스킬은 지휘·중계만 한다. 계획은 `/dev`, 구현은 러너 경유 `/impl`이 수행한다.
