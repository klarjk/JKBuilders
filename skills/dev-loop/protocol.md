# /dev-loop 공용 규약

창구(`SKILL.md`)·지휘(`commander.md`)가 공히 따르는 규약이다. 한 계층 전용 절차는 그 진입점에만 있다.

## 계층과 소유

| 계층 | 소유하는 것 | 소유하지 않는 것 |
|---|---|---|
| 창구 | 지휘의 생명주기(스폰·킬·재스폰), 장부, 사용자 전달(`notify`) | 계획서 판단·갱신, 노드 위임·회수, 저장소 조회 |
| 지휘 | 계획서 지휘, 노드 위임·회수·판단·머지, 커밋, 자기 포화 계측, 채널 모드의 사람 대면 대화 | 자기 재스폰, 비가역 조작, 장부 읽기·쓰기 |
| 작업 | 자기 워크트리 안 작업, 자기 브랜치 커밋 | 계획서 쓰기(읽기 전용), 워크트리 밖 수정, 머지 |

작업 세션은 이 스킬의 파일을 열지 않는다 — 위임 메시지가 곧 지시문이고, 절차는 작업 세션이 스스로 로드하는 `/dev`·`/impl`이 가진다.

## 명명·경로

| 값 | 산출식·형태 |
|---|---|
| 프로젝트 루트 | `git rev-parse --git-common-dir`의 부모. 비-git이면 cwd |
| 경로 슬러그 | 프로젝트 루트 절대경로의 `/`를 `-`로 치환 |
| 이름 슬러그 | 프로젝트 루트 basename을 소문자화 → 영숫자 외 **연속** 문자를 `-` 하나로 축약 → 앞뒤 `-` 제거 → **16자로 자른다.** 결과가 비면 `p<프로젝트 루트 절대경로 md5 앞 6자>` |
| **작업 단위 ID** | 노드 실행이면 노드 ID(`001-N6`), 후속 소진이면 묶음·게이트 ID(`B3`·`harvest`·`gate-1`) |
| 노드ID 정규화 | **작업 단위 ID**를 소문자화하고 **영숫자 외 전부 삭제** (`001-N6` → `001n6`) |
| 지휘 세션 | tmux 세션명 = `--name` = `dl-<이름 슬러그>-cmd` |
| 작업 세션 | `dev-<이름 슬러그>-<노드ID 정규화>` |
| 워크트리 브랜치 | `node/<작업 단위 ID 소문자>` — **묶음도 이 접두를 쓴다** |
| 후속 대장 | `<프로젝트 루트>/docs/dev/plan/FOLLOWUP.md` |
| 장부 | `~/.claude/dev-loop/<경로 슬러그>/ledger.json` |
| 채널 상태 디렉토리 | `~/.claude/dev-loop/<경로 슬러그>/telegram/` |
| 세션 상태 파일 | `~/.claude/status/<세션 UUID>.json` |

- **프로젝트 루트를 cwd로 해석하지 않는다.** 워크트리에서 창구가 뜨면 같은 저장소에 장부가 둘 생기고, 점유 스캔이 자기 장부를 남의 점유로 읽어 개시가 거부된다.
- **잔재 정리 접두(`dev-<이름 슬러그>-`)도 이 산출식으로 만든다** — 절단·축약·폴백을 빼고 만들면 긴 이름·한글 이름 저장소에서 자기 세션을 못 찾는다.
- **세션명에 기계 자리를 더하지 않는다.**
- **작업 단위 ID가 세션명·브랜치·`question_id` 앞자리·메시지 첫 줄 표식의 공통 입력이다.** 묶음 브랜치도 `node/` 접두를 그대로 쓴다 — 창구의 잔재 정리와 미회수 재진입이 이 접두로 브랜치를 찾으므로 소진 경로에만 다른 접두를 주면 찾는 자리가 둘로 갈린다. 이름만으로 노드인지 묶음인지 구별되지 않는 것은 감수하고, 구별이 필요한 자리는 계획서·대장이 답한다.
- 자기 세션 UUID는 스크래치패드 경로에 박힌 값으로 지목하고, 보조가 `CLAUDE_CODE_SESSION_ID`다.

## 통로 모드

| 모드 | 장부 `channel.mode` | 뜻 |
|---|---|---|
| 채널 모드 | `telegram` | 지휘가 텔레그램 채널 세션을 겸직한다. **기계당 한 프로젝트** — 지정 없는 개시의 기본 |
| 화면 모드 | `screen` | 창구 화면이 사람 접점이다. 화면 강제 지정, 그리고 채널 환경이 서지 않을 때의 폴백 |

모드는 개시 때 정해져 장부에 적히고, 재스폰은 모드를 유지한다. 전환은 채널→화면 폴백과 사용자 명시 지시뿐이다.

## 실행 단위

장부 `run_mode`가 정한다. **창구가 개시 인자로 정해 스폰 첫 프롬프트에 싣고, 지휘는 받은 값으로 루프를 고른다.** 재스폰을 건너 유지되고 도중에 바뀌지 않는다.

| `run_mode` | 지휘가 도는 대상 | 실행 단위 |
|---|---|---|
| `node` | DEV_PLAN 노드 표 | 노드 |
| `followup` | 후속 대장의 묶음 표 | 묶음(수확 단위 포함) |

위임·회수·포화 판정·재스폰·통신·되묻기·비가역 경계는 두 값에서 **같다.** 세션명·브랜치·`question_id`·메시지 첫 줄이 쓰는 것은 둘 다 「명명·경로」의 **작업 단위 ID**다.

## 포화 임계값

**상수가 아니라 창 크기에서 계산한다.** 창 크기는 포화도와 **같은 상태 파일**이 준다.

| 임계 | 산출 | 뜻 |
|---|---|---|
| 약함 | `min(250000, 창 × 0.75)` | 새 작업 단위를 시작하지 않는다. 시작한 것은 끝까지 회수한 뒤 재스폰 |
| 강함 | `min(300000, 창 × 0.9)` | 진행 중인 것을 두고 나간다. 진행 상태 한 줄만 적립하고 즉시 재스폰 |

```bash
jq -r '[.context_window.total_input_tokens, .context_window.context_window_size] | @tsv' ~/.claude/status/<세션 UUID>.json
```

> **Do:** 창 크기를 함께 읽어 그 자리에서 임계를 계산하고, 입력 토큰 절대량을 그 값과 숫자로 비교한다
> **Don't:** 상한을 그대로 상수로 박거나, 퍼센트 필드를 쓰거나, 같은 디렉토리에서 mtime이 가장 최신인 파일을 자기 것으로 삼는다(남의 포화도를 읽는다)

**상한을 상수로 박으면 작은 창에서 감시가 죽는다.** 창이 200K로 내려오면 고정 상한은 창 전체에 가까워져 닿는 순간 이미 자연사한 뒤이고 강한 임계는 영영 울리지 않는데, 값도 코드도 정상으로 보여 그 사실조차 드러나지 않는다. **창 200K~333K는 상한이 걸리지 않아 계수만으로 값이 정해진다** — 상한을 얼마로 잡든 이 구간은 달라지지 않는다.

**약한 상한 250,000이 버는 것은 주행거리다.** 기동 바닥이 화면 80,000·채널 93,000이라(**5차 시점** 값 — 현행 값은 아래 하한 검사) 상한이 200,000이면 지휘 한 회차가 11만 남짓 일하는데, 250,000이면 16만 안팎이 된다 — 재스폰 횟수와 회차마다 새로 까는 9만이 함께 줄어든다. 대가는 약한↔강한 간격이 창 1M에서 50,000으로 좁아지는 것인데, 실측 소진폭 30,000의 1.7배이고 창 200K에서 계수가 내는 간격 30,000보다도 넓다. **강한 임계를 넘어도 유실이 아니다** — 인수인계를 상시 적립하므로 대가는 노드 하나를 다음 지휘가 다시 줍는 비용뿐이다.

**하한 검사 — 임계는 기동 바닥보다 충분히 커야 한다.**

```
약한 임계 < 기동 바닥 + 30,000   →  더 진행하지 않는다 (LOWWIN)
```

**가산분 30,000은 위 주행거리 문단이 인용한 실측 소진폭과 같은 값이다** — "작업 단위 하나분"의 현재 최선 실측치다.

**바닥은 상수가 아니라 실측이 우선한다.** 상수는 그 장부에 실측이 아직 하나도 없을 때만 쓰는 초기값이다.

| 순위 | 바닥의 출처 | 쓰는 자리 |
|---|---|---|
| 1 | **장부 `measured_floor.value`** — 같은 장부의 직전 지휘 인스턴스가 기동을 마친 시점의 실측 포화 | 실측이 하나라도 쌓인 뒤의 모든 검사(재스폰 전 대조·주입값 검사) |
| 2 | 상수 — **화면 105,000 · 채널 118,000** | 그 장부의 **최초 스폰 한 번**뿐 |

**회차별 상수를 두지 않는다.** 재스폰 회차에는 실측이 반드시 하나 쌓여 있어 순위 1이 항상 이기므로 회차별 상수가 쓰일 자리가 없다. 두 판이 `respawn_seq`를 달리 읽어 바닥을 95,000과 80,000으로 다르게 고른 자리도 이 단순화로 함께 닫힌다 — **판정할 회차 구분 자체가 사라진다.**

**상수만으로는 못 막는다 — 상수가 41,000 빗나간 판이 있었다.** 주입값 135,000이 옛 상수 95,000 + 30,000 = 125,000을 넘어 정상 통과했는데 그 회차 지휘의 실제 기동 바닥은 136,189였고, 통과한 지휘가 뜨자마자 강한 임계를 넘어 죽었다. 같은 판에서 대장에서 79,000토큰을 덜어내자 다음 회차 바닥이 84,293으로 내려갔다 — **바닥은 저장소의 고유값이 아니라 그 회차가 읽는 문서의 크기를 따라 움직이므로, 계획서·대장이 자랄수록 상수는 낮은 쪽으로 빗나간다.**

**상수 둘은 관측된 최악값을 덮는 값이지 옳은 값이 아니다.** 화면 105,000은 화면 모드 관측 최댓값 102,278을 덮고, 채널 118,000은 화면 상수에 실측된 채널 가산분 약 13,000을 얹은 파생값이다. 한 저장소·한 판의 6개 인스턴스 기동 포화가 **폭 34,922**로 흩어졌고 회차 순서로 설명되지 않았다 — **한 상수로 이 폭을 덮을 수 없으므로 규약값으로 인용하지 않는다.** 실측이 없을 때 한 번 쓰고 버린다.

계산된 약한 임계가 기동 바닥에 가까우면 새로 뜬 지휘가 뜨자마자 임계를 넘어 무진전만 쌓다가 재스폰 상한에 걸린다. 검사 자리는 **창 크기를 처음 성공적으로 읽는 자리**다. 판정에 쓴 창 크기는 장부 `window_size`에 남겨 **재스폰부터는 스폰 전에 대조하고**, 그때 쓰는 바닥은 위 순위표대로 `measured_floor`에 값이 있으면 그 값이다. 미달이면 재스폰을 보류하고 사람에게 묻는다 — 임계·창 설정은 창구 소관이라 지휘가 대신 답할 수 없다.

읽기 실패는 2초 후 1회 재시도한다. **연속 2회 실패는 계측 불능이고 약한 임계 도달로 간주한다** — 계측이 죽은 채 무한히 도는 구조를 만들지 않는다.

## 상태 어휘

상태머신은 둘이고 합치지 않는다.

| | 지휘 생명주기 | 노드 진행 |
|---|---|---|
| 값 | 기동중 / 가동 / 마감중 / 중단 / 종료 | 대기 / 진행 / 완료 / 실패 / 건너뜀 |
| 사는 곳 | 장부 | DEV_PLAN 노드 표(커밋) |
| 쓰는 주체 | **창구만** | **지휘만** |

**계획서 `## 용어` 절은 이 표와 겹치지 않는다** — 저기는 그 프로젝트의 도메인 낱말 전용이고, 위 기계 어휘의 원본은 이 절 하나다(`/dev` 「용어 통일」).

`run_mode`가 `followup`이면 노드 진행 자리를 묶음 상태가 대신한다 — 대기 / 진행 / 완료 / 실패 / 보류(미승인) / **보류(파생)**. 사는 곳은 후속 대장이고 쓰는 주체는 같다. **보류 계열은 종료를 막지 않는다** — 이번 소진의 편성 범위는 정리 게이트가 닫히는 시점에 고정되고, 실행 중에 되돌아온 파생 항목은 `보류(파생)`로 앉아 다음 소진 개시를 기다린다.

전이 요약. 실행 절차는 창구 몫이고 `SKILL.md`의 「전이 실행」에 있다. [지]는 지휘가 발신으로 일으키는 전이다.

| # | 현재 → 다음 | 사건 |
|---|---|---|
| T1 | (없음) → 기동중 | 사용자 개시 |
| T2 | 기동중 → 가동 | 준비 신호 + ref 재맺기 (+채널 모드면 통로 확인 보고) |
| T3 | 기동중 → 기동중 | 기동 실패 또는 통로 불성립 |
| T4 | 가동 → 마감중 | 워치독 `WEAK`·`NOREAD`×2·`CHDEAD`·`CHJACK` |
| T5 | 가동 → 마감중 | [지] 드레인 개시 통보 |
| T6 | 가동 → 기동중 | [지] 재스폰 요청(회수할 것 없음) |
| T7 | 마감중 → 기동중 | [지] 인수인계 적립 완료·재스폰 요청 |
| T8 | 가동·마감중 → 기동중 | 워치독 `STRONG` |
| T9 | 가동·마감중 → 기동중 | 워치독 `DEAD`, 또는 `STALL` 후 생존 질의 무응답 |
| T10 | 가동·마감중 → 종료 | [지] DEV_PLAN 완료 보고 |
| T11 | (기동중 진입 가드) → 중단 | 무진전 재스폰 상한 초과 |
| T12 | 중단 → 기동중 | 사용자 지시: 조치 후 재개 |
| T13 | 중단 → 종료 | 사용자 지시: 접기 |
| T14 | 종료 → (항목 제거) | 정리 완료 |
| T15 | 마감중 → 기동중 | 마감중 체류 60분 초과 |

## 진전 보고

무진전 재스폰 상한(T11)의 유일한 근거다 — 다만 **그 가드는 현행 진전 정의 아래에서 자연 발화하지 않는다**(`SKILL.md` 「재스폰 상한」). 이 절이 정하는 것은 그 잔존 배선이 쓰는 숫자의 산출식이고, 폭주 지휘를 실제로 끊는 것은 T15·`LOWWIN`·`STALL`과 `respawn_seq` 3의 결정 요청이다. **판정 근거는 지휘의 회차 요약이 아니라 장부의 단조 증가 숫자다** — 정상 경로(T6·T7)와 킬 경로(T3 기동 실패·T8·T9·T15)가 같은 식을 쓴다.

**진전 1건 = 「작업 단위 표의 칸이 바뀐 커밋」 하나.** 표는 DEV_PLAN의 노드 표와 후속 대장의 묶음 표이고, 칸은 `상태`·`위임처`·`워크트리`·`산출`·`담당/착지 파일`·**항목 행의 신설·제거**, 그리고 **사람 대기 줄의 제거(답 채택)**다.

> **Do:** 위임처·워크트리 칸을 채운 커밋, 범위·착지 파일을 확정한 커밋도 1건으로 센다
> **Don't:** 표를 건드리지 않은 본문·진행 기록 갱신, 같은 칸을 같은 값으로 다시 쓴 커밋, 소스 코드만 바뀐 커밋을 센다

- **지휘** — 칸이 바뀐 커밋 직후, **자기 인스턴스 안에서 1부터 세는 일련번호 `n`**을 실어 창구에 진전 보고를 보낸다. `n`은 절대값이다.
- **창구** — 보고를 받으면 `completed_units = max(completed_units, units_at_spawn + n)`으로 적는다. **`n`이 절대값이라 유실·중복·순서 뒤바뀜이 한 식에 흡수된다** — 유실분은 다음 보고가 덮고, 중복은 값을 바꾸지 않으며, 늦게 온 작은 `n`은 `max`가 무시한다.
- **판정** — `completed_units > units_at_spawn` 하나뿐이다. 참이면 `no_progress_streak`을 0으로, 거짓이면 +1.
- **기준선** — `units_at_spawn`은 스폰 직전에 찍은 `completed_units` 스냅샷이다. 즉사·상태 파일 미생성 인스턴스는 보고를 낼 기회가 없어 자동으로 무진전이 된다.
- **창구는 저장소를 조회하지 않는다** — `git log`로 진전을 판정하지 않는다. 인수인계 상시 적립이 위임 직전에도 커밋을 남기므로 커밋 유무는 진전의 증거가 못 되고, 저장소 조회는 창구의 소유 범위 밖이다.

## 메시지 첫 줄 문법

세션 간 통신은 `SendMessage` 하나로 일원화한다. 노드에 관한 모든 회신·질의는 본문 첫 줄을 이 문법으로 시작한다.

```
[<노드ID>] 완료|실패|질문|진행 — <한 줄 요지>
```

배달 봉투는 노드 ID를 주지 않는다 — 판별은 이 첫 줄로 한다. 표식이 없으면 노드 ID를 되물어 1회 재요청하고, 재요청에도 없으면 본문 판정을 포기하고 산출 파일·커밋 실재와 `검증:` 줄로 판정한다.

## 발신 실패 처분

| 형태 | 뜻 | 즉시 처분 | 적립 |
|---|---|---|---|
| 동명 모호성 / 옛 ref 409 | 상대는 살아 있고 주소가 낡았다 | 오류가 준 후보 목록에서 `on this machine` 행의 ref로 **1회 재발신**. **자동 재발신은 후보 이름이 원래 이름과 정확히 같을 때만 성립한다** — 한 글자라도 다르면 대상이 아니고, `ListAgents`로 같은 이름의 행이 실재하는지 보고 없으면 아래 행의 사망으로 처분한다 | 재발신 성공 시 없음. 실패하면 아래 행의 사망 처분으로 |
| `No agent named '…' is reachable` / 이름 발신 409 | 상대가 죽었다 | 발신자가 그 자리에서 안다 — 대기하지 않는다. **단, 오류가 `Did you mean: <다른 이름>`을 달고 오면 그 후보는 재발신 대상이 아니다** — 이름이 다르면 남이고, 재발신은 **같은 이름의 다른 ref**에만 한다. 다른 이름 제안은 상대 사망으로 처분한다 | 사망 처분과 함께 **오배송 미수를 지휘의 인수인계에 적립한다**(장부가 아니다 — 지휘는 장부를 쓰지 않는다). 적립 한 줄에 제안된 이름·원래 이름·시각을 담는다 |

> **Don't:** `Did you mean:`이 내민 이름으로 다시 보낸다 — 주소록은 이름이 비슷하다는 이유만으로 **다른 저장소의 창구**를 내밀고, 받아들이면 남의 장부가 오르고 보내는 쪽은 영영 정체하는데 발신은 `success:true`로 돌아와 **어느 쪽 로그에도 오배송이 남지 않는다**

재발신까지 실패한 사망의 방향별 처분:

| 방향 | 처분 |
|---|---|
| 창구→지휘 | 사망 증거. 장부에 사유·시각을 적고 T9 |
| 지휘→창구 | 창구 교체 창. 가역 작업 계속, 회신 필요 발신은 60초 간격 5회 재시도, 실패 시 인수인계에 미전달 적립, 약한 임계면 대기 |
| 지휘→작업 | 노드 표에 적립하고 `/dev`의 미회수 노드 재진입 분기로 처리 |
| 작업→지휘 | 위임 메시지에 실린 지휘 고정 이름으로 60초 간격 최대 5회 재발신. 초과하면 산출을 자기 노드 파일·브랜치에 커밋하고, 창구에 **막힘 신고 한 줄**을 1회 보낸 뒤 정지 |

`SendMessage`가 막히면 `tmux send-keys`를 **단방향 폴백**으로 쓴다 — 창구→지휘·지휘→작업의 지시 방향에만 쓰고, 수신을 대체하지 않는다.

## 응답 대기 상한

- **10분은 실행 시간의 상한이 아니라 다음 확인 행동까지의 간격이다.** 회신을 요구한 모든 발신(위임 포함)에 이 시계를 건다. 노드 실행 시간 자체에는 상한이 없다.
- 값은 10분, 전 축 공통(창구↔지휘·지휘↔작업).
- **사람 대기 노드는 이 감시에서 제외한다.** 사람의 침묵에는 상한을 걸지 않는다.

## 시한을 재는 방법

턴을 끝내면 유휴로 멎으므로 **블로킹 호출 없이 "10분 뒤에 본다"는 시한은 잴 주체가 없다.** 외부 타이머를 두지 않고 두 갈래로 잰다.

| 갈래 | 해당 시한 | 재는 법 |
|---|---|---|
| **회신으로 끝나는 시한** | 강제 정지 유예 10분(T8·T15), 생존 질의 10분(T9) | **워치독을 상한 60초로 계속 돌린다.** 매 라운드 경계에서 큐에 회신이 와 있는지 본다. 종료 조건은 둘 — **회신이 라운드 경계에 와 있거나, 10분 상한 도달** |
| **감시 대상이 없거나 축이 다른 시한** | 통로 확인 120초(T2), 응답 확인 10분(D3-5) | **그 길이의 유한 블로킹 `sleep` 한 방.** 전자는 아직 감시할 지휘가 없고, 후자는 작업 세션 축이라 워치독 대상이 아니다 |

어느 쪽이든 자기 턴에서 실행하고, 호출이 끝난 라운드 경계에 큐로 배달된 메시지 유무로 판정한다. **기다리던 메시지가 이미 와 있으면 대기를 생략한다.**

> **Do:** 유예·생존 질의는 워치독 60초 반복으로 잰다 — 회신이 최대 한 주기 묵는 것과, 그 10분간 생존·폴러 감시가 통째로 꺼지는 것을 한꺼번에 막는다
> **Don't:** 유예를 한 방 `sleep` 10분으로 잡거나, 백그라운드 잡 완료 알림·외부 cron·"10분 뒤에 다시 본다"는 약속에 기댄다

## 파일 경계

| 분류 | 무엇 | 규약 |
|---|---|---|
| 1 | 그 세션 안에서 소비되고 끝나는 것 — 진행 문의, 질의와 답, 완료·실패 통보, 제어 신호 | **메시지 본문만 쓴다. 파일 금지** |
| 2 | 재스폰을 건너 읽혀야 하는 것 | 계획서·`nodes/<노드ID>.md`는 **파일+커밋**, 장부·채널 상태 디렉토리는 **홈 아래 파일이며 커밋하지 않는다** |
| 3 | 노드 산출물 | **항상 파일에 쓰고 노드 브랜치에 커밋한다.** 메시지에는 경로·요지(10줄 이내)·검증 결과만 담는다 — 크기로 가르지 않는다 |
| 4 | 결함·관측 기록 | **홈 아래 한 파일에 한 줄씩 덧붙인다**(「결함 기록」). 커밋하지 않고, 읽어서 고쳐 쓰지 않는다 — 세 계층이 동시에 쓴다 |

각 세션 내부의 임시 파일은 통제 대상이 아니다.

## 결함 기록

무인 운전 중에 발견한 규약의 결함과 미결로 남은 수치는 **그 자리에서 한 줄 적고 지나간다.** 세 계층이 공히 쓰고, 쌓이는 곳은 기계당 파일 하나(`~/.claude/dev-loop/incidents.jsonl`)다.

```bash
~/.claude/scripts/dl-incident.sh --layer <창구|지휘|작업> --kind <종류> --fp <지문> \
  --expected '<규약이 이렇게 된다고 했다>' --observed '<실제로는 이랬다>' --doc '<파일#절>' \
  [--slug <이름 슬러그>] [--unit <작업 단위 ID>] [--evidence '<오류 원문·명령·경로>'] [--action '<우회|정지>']
```

| 종류 | 적는 때 |
|---|---|
| `규약이탈` | 규약대로 했는데 결과가 규약이 말한 것과 다르다 |
| `지시모순` | 두 지시가 어긋나 어느 쪽도 따를 수 없다 |
| `규약공백` | 이 상황의 자리가 규약에 없어 자기 판단으로 메웠다 |
| `도구실패` | 도구가 규약의 처분표에 없는 형태로 실패했다 |
| `관측` | 미결로 남은 수치가 눈앞을 지나갔다 — 유예·체류·기동 바닥의 실측 |

**적지 않는 것:** 노드 실패·검증 실패·머지 충돌·사람의 입력 착오. 정상적인 실패이고 계획서·노드 표가 받는 자리다.

- **`expected`·`observed`·`doc` 셋이 이 기록의 값이다.** 어느 문서 어느 절이 배신했는지가 없으면 사후에 재현부터 다시 해야 한다. `doc`은 `protocol.md#포화-임계값`처럼 파일과 절 이름으로 적는다.
- **지문(`--fp`)은 증상을 가리키는 짧은 영문 슬러그다**(`t8-grace-noreply`). 같은 증상에는 같은 지문을 쓴다 — 집계가 이것으로 묶이고, 같은 지문은 한 세션에 한 번만 나간다. **`관측`만 예외로 매번 남는다** — 실측은 발생마다 값이 달라 눌러 버리면 두 번째부터 소리 없이 사라진다.
- **그 자리에서 고치지 않는다.** 우회하거나 정지하고 무엇을 했는지를 `--action`에 적는다.
- **기록 실패는 본업을 세우지 않는다** — 스크립트는 어떤 실패로도 성공으로 끝난다. 반환을 판정에 쓰지 않고 재시도하지 않는다.
- **토큰·키·대화방 번호를 인자에 담지 않는다** — 스크립트가 흔한 형태 몇 가지를 가리지만 그물은 성기다. 오류 원문을 통째로 넘기기 전에 그 안에 자격증명이 있는지 본다.

> **Do:** 우회한 뒤 한 줄 적고 하던 일을 계속한다
> **Don't:** 결함을 발견한 자리에서 스킬·규약 파일을 고친다 — 여러 세션이 같은 문서를 읽으며 도는 중이라 한 세션의 수정이 남의 절차를 도중에 바꾼다
> **Don't:** 결함 하나마다 사람을 부른다 — 사람 호출은 창구의 닫힌 목록이 정하고, 이 기록은 판이 끝난 뒤 읽히는 자리다

## 함정

- **첫 프롬프트를 셸 명령 문자열에 직접 넣지 않는다** — 대괄호가 glob에 걸려 세션이 즉시 죽고 `tmux ls`에도 남지 않는다. 파일에 쓰고 `"$(cat <파일>)"`로 넘긴다.
- **`--resume`으로 되살리지 않는다** — 컨텍스트를 그대로 복원해 포화를 전혀 덜지 못한다. 재스폰은 새 식별자 + 인수인계다.
- **상태 파일은 UUID로만 찍는다** — 이름 검색 금지(죽은 것과 동명), 존재만으로 생존 판정 금지(사망 후에도 잔존).
- **`git add -A` 금지** — 경로를 지정한다. 커밋 해시를 계획서에 참조로 적지 않는다(경로·브랜치명으로 적는다).
- 기계가 발급한 문자열(해시·세션 식별자)은 보고 전에 조회한다. 날짜는 현재 세션 컨텍스트의 날짜를 쓴다.
