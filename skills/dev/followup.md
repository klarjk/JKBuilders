# /dev — 후속 소진

`/dev --followup`으로 진입했을 때만 읽는다. 계획 세션·노드 실행 회차에서는 로드하지 않는다.

## Phase 3 — 후속 소진 (`--followup`)

계획서에 쌓인 후속·유보 항목을 수확해 묶음 단위로 소진한다. 대상은 `status`와 무관하게 그 프로젝트의 계획서 전부다. 프로젝트를 가로지르지 않는다 — 한 호출은 현재 프로젝트 루트만 다룬다.

`FOLLOWUP.md`가 이미 있으면 수확을 건너뛰고 묶음 표에서 상태가 `대기`·`진행`인 첫 묶음부터 잇는다. 단 대장의 수확일이 7일 이상 지났으면 다시 수확할지 질문 후 답 대기. 재수확하면 **항목 원문으로 대조**해 일치하는 것만 이전 대장의 `보류(미승인)` 표시를 옮겨 적고, 대조되지 않으면 새 항목으로 보아 다시 승인을 묻는다.

### 1. 수확 (서브 1개, 프로젝트 단위)

`docs/dev/plan/`의 계획서 전수를 조사 에이전트 **하나**에 맡긴다. 계획서별로 쪼개지 않는다 — 계획서 간 사본·상태 불일치는 전체를 함께 봐야 잡힌다.

위임 프롬프트에 넣을 것:

- **수집 범위** — `## 후속`·`## 유보`로 시작하는 모든 섹션. 제목 표기가 계획서마다 다르고, 체크박스 없이 서술형 불릿으로만 적힌 계획서도 있다.
- **항목별 판정 5종** — ① **유효성**: 코드·커밋과 대조해 이미 반영됐거나 폐기됐는지 ② **성격**: 기능 추가 / 기능 외 코드 수정 / 결정 대기 / 수동 검증 / 배포·운영 / 문서 / 조사 ③ **착지 파일**: 항목에 없으면 코드에서 찾아 보완 ④ **의존**: 선행 항목과 같은 파일·화면을 건드리는 항목 ⑤ **필수성**: 필수 / 비필수.
- **기능 추가 판정 기준** — 사용자에게 보이는 동작·화면·명령·옵션·설정이 새로 생기거나, 의존성·외부 연동·저장 대상이 늘면 **기능 추가**. 기존 동작을 명세대로 되돌리는 수정이거나 겉동작이 그대로인 개선·리팩터링이면 **기능 외**. 판정이 갈리면 기능 추가로 적는다.
- **필수성 판정 기준** — 결함·오작동 수정, 명세와 다른 동작을 되돌리는 수정, 기능 추가·변경, 그 항목이 막혀 다른 항목·계획서가 진행되지 못하는 것은 **필수**. 겉동작이 그대로인 정돈(리팩터링·네이밍·주석·중복 제거), 취향 수준의 개선, 사용자가 체감하지 못하는 성능 다듬기, 없어도 되는 편의는 **비필수**. 판정이 갈리면 필수로 적는다. `## 유보`에서 수확된 항목도 같은 기준을 탄다 — 유보에 적혀 있어도 결함이면 필수다.
- **계획서 간 불일치** — 같은 항목의 사본, 한쪽만 닫힌 항목, 한쪽만 갱신된 근거.

산출은 `docs/dev/plan/FOLLOWUP.md`에 항목 대장으로 쓴다. 수확일과 항목별 출처 계획서·줄 번호·필수성을 단다.

> **Do:** 체크박스 상태가 아니라 코드 대조로 유효성을 판정하게 한다
> **Don't:** `- [ ]`를 grep해 목록을 만든다 — 형식이 다른 계획서와 유보 섹션이 통째로 빠지고, 이미 끝난 항목이 살아 있는 채로 들어온다

### 2. 정리 게이트 (메인 직접)

1. **무효·사본** — 이미 반영·폐기된 항목과 중복 사본을 1줄씩 보여주고 승인받아 출처 계획서의 항목을 닫는다.
2. **코드 아닌 항목** — 결정 대기·수동 검증·배포·운영·문서·조사 항목을 성격별 목록으로 출력하고 대장에 `보류`로 표시한다. `/impl`에 넘기지 않는다.
3. **비필수 강등** — 필수성이 `비필수`인 항목을 요지 · 판정 사유 · 출처 계획서로 한 줄씩 보여주고 **한 질문으로 묶어 일괄 승인**받는다. 승인분은 출처 계획서의 `## 후속 작업`에 있던 항목을 원문 그대로 `## 유보 작업`으로 옮기고(섹션이 없으면 만든다), 대장에 `유보`로 표시해 편성에서 뺀다. 승인받지 못한 항목은 필수로 되돌린다 — 성격이 `기능 추가`면 4번으로, `기능 외`면 질문 없이 5번의 편성 대상이 된다. **출처가 이미 `## 유보 작업`인 항목은 묻지 않고 대장 표시만 한다** — 옮길 것이 없는데 물으면 수확할 때마다 같은 질문이 되풀이된다.
4. **신규 기능 승인** — 성격이 `기능 추가`인 항목을 한 줄씩(요지 · 착지 파일 · 출처 계획서) 보여주고 **항목 단위로 승인 질문 후 답을 기다린다.** 승인분만 대장 상태를 `대기`로 두고, 나머지는 `보류(미승인)`로 적으며 출처 계획서의 항목은 열린 채로 둔다. 같은 출력에 `기능 외`로 분류된 항목도 요지만 한 줄씩 붙여 오분류를 사용자가 걸러낼 수 있게 한다.
5. 승인된 기능 추가 항목과 필수로 남은 기능 외 코드 수정 항목만 "묶음 편성"의 대상이다.

> **Do:** 결함 수정과 기능에 영향을 주는 항목만 이번 판에 남기고 나머지는 유보로 내린다
> **Don't:** 비필수 항목을 묻지 않고 내리거나, 유보로 내린 항목을 출처 계획서에서 지운다

> **Do:** 기능 추가는 항목별로 물어 승인된 것만 편성에 넘긴다
> **Don't:** 결함 수정과 한데 묶어 일괄 승인받거나, 답을 기다리지 않고 편성·실행으로 넘어간다

### 3. 묶음 편성 (메인 직접)

1. **클러스터** — 같은 파일·모듈·화면을 건드리는 항목끼리 묶는다. 성격이 다른 항목은 한 묶음에 섞지 않는다. 기능 추가와 기능 외 항목은 착지 파일이 같아도 묶음을 나눈다.
2. **크기** — 묶음을 `/impl` 크기 기준에 태워 파일 10개를 넘으면 쪼갠다. 클러스터에 안 붙는 고아 항목은 성격이 같은 것끼리 최대 5건까지 합친다.
3. **순서** — 시한 명시 > 다른 항목·계획서를 차단 > 결함 > 개선. 동률이면 계획서 번호 순.

편성 결과를 대장에 묶음 표(`묶음ID | 구분(기능/기능외) | 항목 | 착지 파일 | 출처 계획서 | 상태(대기/진행/완료/실패/보류(미승인)/보류(파생)) | 위임처 | 워크트리`)로 적고 사용자에 묶음 수와 첫 묶음만 1줄 보고한다.

**이번 소진의 편성 범위는 정리 게이트가 닫히는 이 시점에 고정된다.** 실행 중에 새로 발견된 항목은 이 판에 넣지 않는다.

`위임처`(tmux 세션명)·`워크트리`는 묶음을 별도 세션에 위임할 때만 채운다 — 위임 직전에 적고 회수 직후 비운다. **메인이 직접 `/impl`을 돌리는 단독 실행에서는 두 칸을 `—`로 둔 채 진행한다.**

### 4. 실행·갱신

**첫 묶음을 시작하기 전에 '컨텍스트 임계 판정'을 본다.** 수확·정리 게이트만으로 임계를 넘겼으면 묶음을 하나도 시작하지 않고 아래 정지 절차로 간다.

묶음 하나를 `/impl`에 위임한다 — 전달: 묶음 항목 원문 · 착지 파일 · 출처 계획서 경로 · 출처 계획서의 `## 용어` 절(있으면) · **승인 범위**. 승인 범위 문장은 성격을 가리지 않는다 — **"묶음 항목 밖의 변경은 기능 추가든 기능 외든 구현하지 말고 후속 작업으로 되돌려 보고하라"**고 명시한다. 기능 추가만 되돌리게 하면 기능 외 항목이 `/impl`의 자발로 실려 들어와 범위가 스스로 불어난다. 반환 후 출처 계획서의 해당 항목을 닫고 대장의 묶음 상태를 갱신한다. **`/impl`이 돌려보낸 항목은 대장에 `보류(파생)`로 추가하고 이번 판에 다시 편성하지 않는다** — 보류 계열은 종료를 막지 않으므로 소진은 그 회차에 정상 종료하고, 회수는 다음 소진 개시가 맡는다. 위임이 실패·롤백됐으면 묶음 상태를 `실패`로 둔다.

> **Do:** 되돌아온 파생 항목은 `보류(파생)`로 앉히고, 게이트에서 승인받지 못한 것은 `보류(미승인)`로 둔다 — 두 어휘를 섞지 않는다
> **Don't:** 파생 항목을 이번 소진에 다시 편성한다 — 소진이 스스로 증식해 끝나지 않는다

묶음을 마칠 때마다 아래 둘을 보고 **하나라도 걸리면 정지**한다.

- **컨텍스트 임계 판정** — 약한 임계 초과.
- **묶음 무게** — `/impl`이 크기 중·대로 처리했으면 무거움, 소면 가벼움.

**판정은 방금 마친 묶음만 본다.** 다음 묶음의 무게는 `/impl`이 돌기 전에는 확정되지 않으므로 '세션 경계 규칙'의 다음 실행 단위 선판정은 Phase 3에 적용하지 않는다. 정지할 때는 직전 반환에서 이미 갱신해 둔 출처 계획서·대장을 커밋하고 **이어갈 두 길을 안내한다** — 같은 방식이면 새 세션에서 `/dev --followup`, 자동·병렬로 끝까지 돌리려면 `/dev-loop --followup`. **대장의 묶음 표가 곧 인수인계이므로 별도 인수인계 문서를 쓰지 않는다.**

> **Do:** 묶음을 마칠 때마다 출처 계획서와 대장을 함께 갱신한다
> **Don't:** 여러 묶음을 처리한 뒤 갱신을 몰아서 한다 — 중간에 정지하면 어디까지 닫혔는지 알 수 없다
