# /dev

여러 `/clear` 세션에 걸치는 개발을 지휘한다. 메인은 대화형 계획만 직접 하고, 설계는 `/adr`, 구현은 `/impl`에 위임한다. 세션 간 인수인계는 개발 계획서(DEV_PLAN) 하나로 한다.

## 핵심 개념

- **세션 = 사용자가 `/clear`로 여는 대화 단위.** 메인은 세션을 스스로 열 수 없다. 한 `/dev` 호출은 다음 미완료 세션 단위를 실행하고 '세션 경계 규칙'에 따라 정지·인수인계한다.
- **DEV_PLAN = 세션 간 인수인계 장부.** 매 세션 종료 시 진행을 체크리스트로 표시한다.
- **컨텍스트 예산(200K)은 메인 세션에 쌓이는 양 기준으로 관리한다.**

## 산출 위치

- 개발 계획서: `<프로젝트 루트>/docs/dev/plan/DEV_PLAN-NNN-<slug>.md`
- 사전 조사: `<프로젝트 루트>/docs/dev/research/<slug>.md`
- 태스크 파일: `<프로젝트 루트>/.claude/tasks.md`
- 프로젝트 루트: `git rev-parse --git-common-dir`의 부모. 비-git이면 cwd. `<slug>`는 영문 소문자 kebab-case.

## 진입 분기 (매 호출, 메인 직접)

1. `--resume <경로>`가 있으면 그 계획서를 사용한다. 없으면 `docs/dev/plan/`을 스캔한다.
2. `status: in-progress` 계획서가 있으면 → **재진입(Phase 2)**. 2개 이상이면 제목을 1줄씩 보여주고 어느 것을 이어갈지 질문 후 답 대기.
3. 없으면 → **신규(Phase 1)**.

## Phase 1 — 계획 세션 (신규)

1. **대화형 인테이크.** 사용자와 구현 범위·제약을 확정한다. 모호한 점만 질문하고 명확하면 넘어간다.
2. **사전 조사 판정 (조건부).** "조사 트리거"(아래)에 해당하면 `researcher`를 스폰한다 — 전체 결과는 `docs/dev/research/<slug>.md`에 Write, 메인 회신은 핵심 요약만. 계획서에서는 경로로 참조한다. 해당 없으면 생략.
3. **성공 조건 (선택).** 사용자가 성공 조건을 언급했을 때만 대화로 확정해 기록한다. 언급 없으면 이 단계 생략.
4. **ADR 필요 판정.** 저장소·데이터 모델·API 계약·인증 경계·주요 라이브러리·모듈 경계를 신규 도입·변경하면 설계 세션(→ `/adr`)을 세션 계획에 넣는다. 기존 구조 내 확장·리팩토링뿐이면 생략.
5. **세션 계획 배분.** 전체 작업을 세션 단위로 나누고 각 단위에 예상 무게(가벼움/무거움)를 매긴다("세션 경계 규칙" 참조). 계획·조사가 무거웠으면 설계·구현은 다음 세션으로 민다. 성공 조건이 있고 구현이 여러 세션으로 쪼개지면, 각 성공 조건을 그것을 완성하는 세션에 배분해 계획서에 표기한다.
6. **DEV_PLAN 작성.** 아래 "DEV_PLAN 표준 구조"로 Write한다. NNN은 `docs/dev/plan/` 내 최대 번호 +1(3자리, 없으면 001), status는 `in-progress`.
7. **세션 경계 판단** ("세션 경계 규칙").

## Phase 2 — 세션 실행 (재진입)

1. DEV_PLAN을 Read하고 첫 미완료 세션 단위(`[ ]`가 남은 세션)를 찾는다.
2. 사용자에 1줄 보고 후 진행 ("다음: 세션 3 — 구현 파트1. 진행합니다").
3. 세션 유형별:
   - **설계 세션** → `/adr`을 Skill로 호출. 결정 문제·배경·후보안·(있으면) 조사 참조 경로를 전달. 산출 ADR 경로를 계획서 `## 아키텍처 결정`에 기록.
   - **구현 세션** → `/impl`을 Skill로 호출. 전달: ① 구현 범위 ② (있으면) 확정 ADR 경로 — `/impl`이 설계 단계를 생략하고 이를 채택한다 ③ (있으면) 그 세션에 배분된 성공 조건만 원문 그대로. `/impl`이 성공 조건을 `01_intent.md`에 기록해 planner·evaluator·e2e로 관통시킨다. 이미 시작됐다 중단된 세션이면(계획서에 워크스페이스 경로 기록 또는 `_workspace/impl_*` 잔존) fresh가 아니라 `/impl --resume <워크스페이스 경로>`로 이어간다. `/impl` 반환의 워크스페이스 절대경로를 계획서 해당 세션 줄에 기록한다.
4. 완료 후 해당 세션 체크리스트를 `[x]`로 갱신한다. 전 세션 완료면 `status: done`.
5. **후속·보류 처리** ("후속·보류 작업").
6. **세션 경계 판단** ("세션 경계 규칙").

## 세션 경계 규칙

- 예상 무게:
  - **무거움**: 외부 조사 결과를 메인이 읽음 / `/adr` 직접 작성 경로(Phase 2A) / 대화 인테이크가 왕복 5회 이상
  - **가벼움**: `/impl` 호출(반환 크기=소 제외) / synthesizer 경유 `/adr`(Phase 2B) / 조사 없이 왕복 4회 이하 대화
- Phase 1의 무게 라벨은 계획용 예상치다. 정지·계속 판단은 방금 끝낸 단위의 **실제 진행**으로 한다.
- 한 단위를 마칠 때마다:
  - 방금 마친 단위가 무거움 → **정지**. 계획서 갱신 + "`/clear` 후 `/dev`로 이어가세요" 안내.
  - 방금 마친 단위가 가벼움 + 다음 미완료 단위도 가벼움 → Phase 2 step 1로 돌아가 다음 단위를 이어 실행.
  - 다음 미완료 단위가 무거움 → 정지·안내. 다음 미완료 단위 없음 → 완료 보고.
- **세션 종료 커밋.** 정지·완료로 세션을 끝내기 직전, 계획서 갱신 등 작업 트리의 미커밋 변경이 있으면 커밋한다 — 태그는 생성하지 않는다(전역 커밋·태그 규칙의 사이클 태깅을 `/dev` 세션 종료 커밋에 한해 면제). 미커밋 변경이 없으면 생략.

> **Do:** 무거운 단위 하나로 그 세션을 끝내고, 미커밋 변경은 커밋만 남긴다
> **Don't:** 한 호출에서 무거운 단위 2개(조사 + 직접 ADR 등)를 연달아 처리하거나, 태그를 붙이거나, 커밋 없이 다음 세션으로 넘긴다

## 후속·보류 작업

세션 중 유보·보류·후속 작업이 식별되면(예: `/impl` 반환 요약의 발견 사항, 미완 범위) `<루트>/.claude/tasks.md`에만 체크리스트 항목으로 append한다(파일에 `tags:[task]` frontmatter가 없으면 추가). 일반 세션 작업 진행은 DEV_PLAN 세션 계획에만 기록·갱신한다.

> **Do:** 유보·보류 작업은 tasks.md, 일반 작업 진행은 DEV_PLAN 세션 계획 — 각각 한 곳에만
> **Don't:** 같은 항목을 tasks.md와 DEV_PLAN에 이중으로 기록한다

## 조사 트리거 판정

아래 중 하나라도 해당하면 코드 작성 전에 조사를 선행한다(`researcher` 스폰):

- 학습 컷오프(2026-01) 이후 빠르게 바뀌는 외부 기술 의존 — 특정 라이브러리·프레임워크 버전, LLM/AI API, 클라우드 서비스 기능, 최근 6개월 내 릴리스·변경된 도구
- 사용자가 조사를 명시 요청
- 구현 방향이 외부 사실 확인 없이는 결정 불가

해당 없으면(안정적 도메인·내부 로직·리팩토링·정착된 라이브러리) 조사를 생략한다.

> **Do:** 최신 기술 카테고리는 `researcher`로 외부 조사부터 한다
> **Don't:** 컷오프 이전 지식만으로 최신 API·버전을 단정한다

단순 1줄 사실 조회는 `general-purpose`(haiku)로 갈음한다.

## DEV_PLAN 표준 구조

```markdown
---
title: <제목>
status: in-progress | done
created: YYYY-MM-DD
project: <프로젝트명>
tags: [dev-plan]
---

# DEV_PLAN-NNN: <제목>

## 목표
<무엇을·왜 만드는가>

## 성공 조건          ← 언급 없으면 섹션 생략
- [ ] 1. <사용자 정의 조건>

## 사전 조사 참조      ← 조사 없으면 섹션 생략
- docs/dev/research/<slug>.md — <한 줄 요약>

## 아키텍처 결정
- ADR 필요: 예/아니오
- (예) docs/adr/ADR-NNN-<slug>.md — 예정/작성됨

## 세션 계획
### 세션 1 — 계획·조사 (무게: 무거움) [완료]
- [x] 대화 인테이크
- [x] 사전 조사
- [x] 개발 계획 작성
### 세션 2 — 설계 (무게: 가벼움)
- [ ] /adr — <결정 주제>
### 세션 3 — 구현 파트1 (무게: 가벼움)
- [ ] /impl — <범위> (성공조건: 1 / workspace: —)
```

> 유보·보류·후속 작업은 이 계획서에 넣지 않고 `<루트>/.claude/tasks.md`에만 기록한다("후속·보류 작업" 참조).

## 주의사항

- 날짜는 현재 세션 컨텍스트의 날짜를 쓴다(추측 금지).
- 조사·설계 산출물 본문은 최소한만 읽고 경로로 참조해 하위 스킬·에이전트에 전달한다.
- 본 스킬은 지휘만 한다. 코드 구현·수정은 `/impl`, 설계 문서는 `/adr`이 수행한다.
