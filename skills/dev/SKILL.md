# /dev

여러 `/clear` 세션에 걸치는 개발을 지휘한다. 계획 세션에서 작업을 **노드 흐름도**로 배치하고, 노드 단위로 실행·위임한다.

## 핵심 개념

- **노드 = 작업 단위.** 종류·주체·선행·분기조건·상태를 가진다.
- **세션 = 대화 단위.** 본 스킬은 세션을 스스로 열지 않는다. 한 `/dev` 호출은 실행 가능한 노드를 처리하고 '세션 경계 규칙'에 따라 정지·인수인계한다.
- **DEV_PLAN = 인수인계 장부.** 흐름도(mermaid)와 노드 표를 함께 싣는다. 실행 판단은 **노드 표**로 하고, 흐름도는 사람이 보는 그림이다.
- **컨텍스트 예산은 세션에 쌓인 입력 토큰의 절대량으로 관리한다** — Phase 2 노드 경계와 Phase 3 묶음 경계 두 곳에서 잰다("컨텍스트 임계 판정").
- **인수인계는 세션 끝에 몰아 쓰지 않는다** — 위임 직전·회수 직후·결정 시점 셋에서 DEV_PLAN에 적립하고 각각 커밋한다("인수인계 상시 적립").

## 산출 위치

- 개발 계획서: `<프로젝트 루트>/docs/dev/plan/DEV_PLAN-NNN-<slug>.md`
- 노드 결과: `<프로젝트 루트>/docs/dev/plan/nodes/<노드ID>.md` — **주체를 가리지 않는다.** 서브 위임분도, 메인이 직접 처리한 연구·실행·설계 노드도 여기 쓴다
- 사전 조사: `<프로젝트 루트>/docs/dev/research/<slug>.md`
- 후속 항목 대장: `<프로젝트 루트>/docs/dev/plan/FOLLOWUP.md`
- 선결 답 대장: `<프로젝트 루트>/docs/dev/plan/DECISIONS-NNN.md` — 자동 모드 전용("선결 질문 일괄 수집")
- 프로젝트 루트: `git rev-parse --git-common-dir`의 부모. 비-git이면 cwd. **cwd로 해석하지 않는다** — 워크트리에서 호출해도 메인 워킹트리를 가리킨다.
- `<slug>`는 영문 소문자 kebab-case.

## 노드 ID 규약

노드 ID는 **`NNN-N<번호>`** 형식이다 — `NNN`은 그 노드가 속한 계획서 번호(예: `007-N1`·`007-N2`). 영숫자와 `.`·`_`·`-`만 32자 이내로 쓴다.

노드 결과 문서·브랜치(`node/007-n1`)·워크트리(`<저장소>-nodes/007-n1`)·러너 우편함 이름이 **전부 이 ID에서 파생된다.** 계획서 번호를 빼면 한 저장소에 계획서가 둘 이상 쌓이는 순간 결과 문서가 조용히 덮이고, 남아 있던 동명 브랜치에 새 노드가 이어붙어 앞 계획서의 커밋을 물고 시작한다.

> **Do:** 노드를 추가할 때마다 그 계획서 번호를 앞에 단다
> **Don't:** 이미 진행 중인 계획서의 노드 ID를 소급 개명한다 — 이미 쓰인 결과 문서·브랜치와 어긋난다. 그 계획서에 노드를 더할 때는 그 계획서가 쓰던 형식을 그대로 따른다

## 노드 종류

| 종류 | 기본 주체 | 실행 방법 |
|------|----------|----------|
| 조사 | 서브 | 자료 수집·정리. `researcher`(좁히기 필요) 또는 `Explore`·`general-purpose` |
| 연구 | 메인 | 직접 돌려 결론을 얻는다. 결과가 분기를 만든다 |
| 설계 | 메인 | `/adr` |
| 디자인 | 사용자 | 시안은 사용자가 확정하고 **메인이 구현용 사양서로 정규화한다.** 구현 노드는 시안이 아니라 사양서를 입력으로 받는다 |
| 구현 | 서브 | `/impl` |
| 실행 | 메인 | 1회성 조작 — 병렬 노드 합류(가역), 데이터 보충·이관·배포(비가역). 비가역이면 백업·복구 경로 확인이 통과 조건이고, 무인 진행 중이면 주체를 사용자로 되돌린다(`/dev-loop` `commander.md`의 "비가역 조작 경계"). **단 사전 승인이 있고 하류 노드가 걸려 있으면 "선결 질문 일괄 수집"의 하류 유무 규칙대로 승인 범위 안에서 무인 실행한다** |

**조사와 연구는 실험 포함 여부로 가른다.** 자료를 모아 정리하면 조사, 직접 돌려 봐야 결론이 나면 연구.

**배포는 실행 종류의 끝단 사례다.** 직전 구현 노드가 회귀를 마쳤으므로 테스트 스위트를 다시 돌리지 않는다.

## 주체 판정

노드 종류 표의 `기본 주체`를 쓰되, 아래에 걸리면 그것으로 덮어쓴다(위에서부터 먼저 걸리는 것).

1. 사람만 할 수 있다(육안 대조·실환경 확인·시안 선택·사람만 아는 절차 청취) → **사용자**
2. 다른 프로젝트·타인이 해야 한다 → **외부**
3. 사용자에게 선택지를 물어야 하거나, 서브를 스폰해 판단·종합해야 한다 → **메인**

## 위임 실행 모드

`--resume`으로 호출됐고 args에 처리할 노드 ID와 DEV_PLAN 갱신 금지가 **함께** 명시됐으면 위임 실행이다. **회신할 호출자 주소는 args가 아니라 이 세션을 띄운 위임 메시지에서 얻는다** — 거기 실린 호출자의 고정 세션 이름이 회신처다. 그 이름이 확보되지 않으면 위임 실행으로 보지 않고 평소 진입 분기를 따른다 — 대화 중 비슷한 표현이 나왔다고 전환하면 없는 호출자에게 묻다 멈춘다. 아래를 적용하고, 그 외 절차는 평소대로 따른다.

- **DEV_PLAN을 갱신하지 않는다** — 노드 표·흐름도뿐 아니라 frontmatter `status`·아키텍처 결정·후속·유보 섹션도 건드리지 않는다. 결과·계획 변경 제안·발견한 후속·유보 항목은 모두 `nodes/<노드ID>.md`에 적고, DEV_PLAN 반영은 호출자에게 맡긴다. **설계 노드면 산출 ADR 경로도 여기 적는다** — Phase 2 7번의 `## 아키텍처 결정` 기록은 이 모드에서 적용하지 않는다.
- **지정된 노드 1개만 처리하고 정지한다.** '세션 경계 규칙'의 연속 처리 판정과 `/clear` 재개 안내를 적용하지 않는다.
- **사용자에게 직접 묻지 않는다.** 결정·확인이 필요하면 위임 메시지에 실린 호출자의 **고정 세션 이름**으로 `SendMessage` 회신해 묻고 답을 기다린다 — 화면 출력은 아무에게도 도달하지 않는다. 배달 봉투의 발신자 값은 회신 주소로 쓰지 않는다(재스폰마다 바뀐다). 본문 첫 줄은 위임 메시지가 지정한 표식 문법을 따른다.
- **되돌릴 수 없는 조작은 수행하지 않는다.** 배포·데이터 이관·브랜치 합치기가 필요하면 실행하지 말고 호출자에게 반환한다.

> **Do:** 노드 표·흐름도·`status` 필드는 그대로 두고 `nodes/<노드ID>.md`에만 쓴다
> **Don't:** Phase 2 8·9번의 상태 갱신·`status: done` 전환을 위임 모드에서도 실행한다

### 단일 노드 실행

**같은 세션 안에서 Skill로 호출됐고 args가 처리할 노드 ID 하나를 지목했으면 단일 노드 실행이다.** 위임 실행 모드와 달리 **호출자 주소도 갱신 금지도 없다** — 상위 루프(`/dev-loop`의 지휘 등)가 이미 노드를 골라 놓고 그 하나의 절차만 빌려 쓰는 경우다.

- **지정된 노드 1개만 처리한다.** Phase 2의 1~4번(재진입 처리·노드 선정·분기 정리·보고)을 다시 하지 않는다 — 호출자가 이미 했다. 7번(종류별 실행)부터 시작한다.
- **노드 표의 그 노드 행만 갱신한다.** 다른 노드의 상태, 흐름도, 후속·유보, `status: done` 전환은 건드리지 않는다 — 그 판단은 호출자 몫이다.
- **처리 후 정지한다.** '세션 경계 규칙'의 연속 처리 판정과 `/clear` 재개 안내를 적용하지 않고 호출자에게 반환한다.
- **사용자에게 물어야 하면 호출자의 통로를 쓴다.** 화면 출력이 사람에게 닿지 않는 무인 세션이면 호출자가 지정한 방식(`/dev-loop` `commander.md`의 "되묻기 처분")을 따른다.

> **Do:** 호출자가 고른 노드 하나만 돌리고 그 행만 갱신한 뒤 돌려준다
> **Don't:** 준비된 다른 노드까지 이어서 처리하거나, `status: done`을 스스로 전환한다

## 진입 분기 (매 호출, 메인 직접)

1. '위임 실행 모드' 또는 '단일 노드 실행' 조건에 해당하면 → 그 절의 규칙을 얹고 Phase 2 7번(종류별 실행)으로 곧장 간다. 아래 2~5번을 적용하지 않는다.
2. `--followup`이 있거나 사용자가 밀린 후속 작업 처리를 요청하면 → **후속 소진(Phase 3)**. 아래 3~5번을 적용하지 않는다.
3. `--resume <경로>`가 있으면 그 계획서를 사용한다. 없으면 `docs/dev/plan/`을 스캔한다.
4. `status: in-progress` 계획서가 있으면 → **재진입(Phase 2)**. 2개 이상이면 제목을 1줄씩 보여주고 어느 것을 이어갈지 질문 후 답 대기.
5. 없으면 → **신규(Phase 1)**.
6. 3~5를 마쳤으면 '자동 이어가기 모드'의 켜는 조건을 판정한다. 켜졌으면 '선결 질문 일괄 수집' → '회차 시작 게이트' 순으로 닫고 Phase 2에 들어간다. **5번(신규)으로 갔으면 Phase 1을 끝까지 마쳐 계획서·노드 표가 생긴 뒤에 이 둘을 적용한다** — 노드 표가 없는 자리에서는 물을 것을 뽑을 수 없다.

## Phase 1 — 계획 세션 (신규)

**`<이 스킬 폴더>/planning.md`를 Read해 그 절차를 따른다.** 그 파일이 Phase 1 단계·정보 출처 판정·의도 인터뷰·병렬 배치 규칙·분기 배치 규칙·DEV_PLAN 표준 구조를 갖는다. 신규 계획을 세우는 호출에서만 읽고, 재진입 회차에서는 열지 않는다 — 회차마다 다시 실리면 그만큼이 남은 모든 회차의 비용이 된다.

## 병렬 구현 노드의 격리와 합류

구현 노드를 **병렬로 실행할 때만** 적용한다. 단독 실행이면 워크트리를 만들지 않고 메인 워킹트리에서 `/impl`을 그대로(e2e 포함) 돌린다.

1. 메인이 노드마다 워크트리를 만든다 — `git worktree add <경로> -b node/<노드ID>`.
2. 그 워크트리를 작업 위치로 `/impl`을 실행하고, 위임에 **"evaluator·e2e는 상위 합류 노드에서 수행한다. 통합 code-reviewer 통과 시점에 종료하라"** 를 명시한다. 나머지 단계(계획·단위·리뷰·트랙 머지·통합)는 노드 워크트리 안에서 평소대로 닫힌다.
3. 노드가 끝나면 `node/<노드ID>` 브랜치에 커밋만 남는다.
4. **합류 노드**(종류=실행, 주체=메인, 선행=병합 대상 구현 노드 전체)에서 메인이 순서대로 처리한다.
   1. 노드 브랜치를 하나씩 머지한다. 충돌하면 멈추고 사용자에 보고하며, 해소 후 **그 노드 머지부터** 재개한다.
   2. 전체 테스트 스위트를 1회 돌린다.
   3. `evaluator` 스폰 — 위임에 **노드별 워크스페이스 경로 목록**(각 `03_plan.md`의 E2E 골격을 Read하도록)과 DEV_PLAN의 성공 조건을 전달한다. 산출 경로를 e2e 에이전트에 넘겨 스폰한다(에이전트 선택은 `/impl` 7단계 규약과 동일). e2e가 없는 프로젝트면 3·4를 생략.
   4. e2e 실패 시 실패 시나리오가 닿는 파일을 노드 표의 `담당 파일`과 대조해 원인 노드를 지목하고, 그 노드를 `실패`로 되돌려 재실행한다. **대조로 특정되지 않으면 합류 노드를 `실패`로 두고 사용자에 보고한다** — 임의로 지목하지 않는다.

노드 결과 파일은 **그 노드 워크트리 안의** `docs/dev/plan/nodes/<노드ID>.md`에 쓴다. 메인은 절대경로로 읽고, 머지 시 함께 들어온다.

> **Do:** 병렬 노드는 통합 리뷰까지, e2e는 합쳐진 트리에서 한 번만 돌린다
> **Don't:** 병렬 노드가 각자 e2e를 돌리게 하거나, 서브·러너에게 메인 워킹트리로의 머지를 시킨다

## Phase 2 — 노드 실행 (재진입)

1. DEV_PLAN을 Read한다. **상태가 `진행`인 노드가 있으면 아래 "미회수 노드 재진입 분기"를 먼저 처리한다** — 앞 세션이 보내 놓고 회수하지 못한 노드가 여기 걸린다.
2. **선행이 모두 완료·건너뜀이면서 상태가 대기**인 노드를 모두 찾는다. **`DECISIONS-NNN.md`에 `미답`으로 막힌 노드와 무인 주행에서 실행하지 않기로 한 끝단 비가역 노드는 여기서 뺀다**("선결 질문 일괄 수집").
3. **분기 정리.** 그중 `조건` 칸이 채워진 노드는 선행 노드의 결과로 조건을 판정한다. 충족한 것만 실행 대상으로 남기고, 나머지 갈래는 상태를 `건너뜀`으로 바꾼다.
4. 사용자에 1줄 보고 후 진행 ("실행 가능: 007-N4 구현·서브, 007-N6 조사·서브. 병렬로 진행합니다").
5. **위임 직전 검사·적립.** 노드를 하나라도 시작하기 전에 순서대로 둘을 한다.
   1. **"컨텍스트 임계 판정"** — 약한 임계를 넘었으면 이 노드를 시작하지 않고 10번(세션 경계 판단)의 정지 절차로 간다.
   2. **위임 시점 기록** — 시작할 노드의 상태를 `진행`으로 바꾸고 위임처(서브 스폰이면 그 사실, tmux 위임이면 세션명)와 워크트리 경로를 노드 표에 적은 뒤 곧바로 커밋한다("인수인계 상시 적립" 1번). **기록이 위임에 선행한다** — 위임하고 나서 적으면 그 사이에 세션이 끊길 때 위임처를 아무도 모른다.
6. 주체별 처리:
   - **서브 노드** → **이번 회차에 둘 이상이 함께 도는 구현 노드면 노드마다 tmux 세션을 띄운다**("tmux 세션 위임"). 그 밖은 한 응답에 묶어 서브에이전트로 스폰한다("서브 노드 위임 규칙") — **계획서에 병렬로 배치된 노드라도 이번 회차에 홀로 돌면 여기 해당한다.** 워크트리를 만들지 않고 메인 워킹트리에서 그대로 돌린다("병렬 구현 노드의 격리와 합류"의 단독 실행 조항).
   - **메인 노드** → 하나씩 처리한다.
   - **사용자·외부 노드** → 필요한 것을 안내하고 상태를 `진행`으로 두되 **위임처 칸은 비워 둔다**("미회수 노드 재진입 분기" 1번이 이것으로 사람 대기 노드를 가른다). 다른 실행 가능 노드로 넘어가고, 그것만 남으면 정지·안내.
7. 종류별 실행:
   - **설계** → `/adr`을 Skill로 호출. 결정 문제·배경·후보안·(있으면) 조사 노드 산출 경로를 전달. 산출 ADR 경로를 `## 아키텍처 결정`에 기록. **산출 ADR `## Status`의 개정 회차가 3에 도달하면 결정을 갈라 노드를 쪼갠다** — 흐름도와 노드 표를 확장하고 각 노드가 자기 결정만 산출하게 한다.
   - **구현** → `/impl`을 Skill로 호출. 전달: ① 구현 범위 ② (있으면) 확정 ADR 경로 — `/impl`이 설계 단계를 생략하고 채택한다 ③ (있으면) 그 노드에 배분된 성공 조건 원문. 중단된 노드면(노드 표에 워크스페이스 경로 기록) `/impl --resume <경로>`로 이어간다. 반환된 워크스페이스 절대경로를 노드 표에 기록. **병렬 배치된 노드면 "병렬 구현 노드의 격리와 합류"를 따른다.**
   - **실행** → 되돌릴 수 없는 조작이면 백업·복구 경로를 먼저 확인한다. 확인되지 않으면 사용자에 보고하고 대기. **합류 노드면 "병렬 구현 노드의 격리와 합류" 4번을 따른다.**
8. **회수·갱신.** 서브 노드면 `nodes/<노드ID>.md`를 Read해 `## 계획 변경 제안` 절이 있는지 확인한다. **병렬 노드는 그 노드 워크트리의 절대경로로 읽는다.** 제안과 발견된 후속·유보 항목은 아래 "반영·보고 선택 기준"으로 가른다. 이어서 노드 상태와 판정 근거를 적고, **커밋 직전에 "계획서 덜어내기"를 적용한 뒤** 커밋한다("인수인계 상시 적립" 2번).
9. **후속·유보 처리** ("후속·유보 작업"). 전 노드가 완료·건너뜀이면 `status: done`으로 바꾸고, 후속 작업에 `[ ]` 항목이 남아 있으면 완료 보고에 함께 출력하며 `/dev --followup`으로 소진할 수 있음을 1줄 안내한다.
10. **세션 경계 판단** ("세션 경계 규칙").

### 반영·보고 선택 기준

회수한 제안·발견 항목을 **DEV_PLAN에 반영**할지 **사용자에 1줄 보고**만 할지는 아래로 가른다.

- **반영** — 계획 구조를 바꾸는 것. 노드 추가·삭제·분할, 선행·조건·주체·담당 파일 변경, 흐름도 변경, 후속·유보 섹션에 남길 항목, 뒤 노드의 전제를 뒤집는 실측.
- **보고** — 그 노드 안에서 닫힌 것. 이미 반영돼 있는 내용의 재확인, 산출물 안에 이미 적힌 구현 세부, 다음 노드가 노드 파일을 읽으면 알게 되는 참고사항.
- **가르기 애매하면 반영한다.** 계획서에 적혀야 다음 세션이 본다 — 보고는 이 세션이 끝나면 사라진다.

**반영은 어디에 적느냐까지가 규칙이다.** 계획서 본문에 적는 것은 **뒤 노드의 실행을 바꾸는 것**뿐이다 — 노드 표·흐름도의 칸, 전제·용어·성공 조건, 후속·유보 항목 한 줄, 표 칸에 안 들어가는 지시는 `## 대기 노드 실행 지시`에 노드 ID를 달아 한 문단. **그 노드가 무엇을 했고 무엇을 쟀는지의 서술은 길이를 불문하고 `nodes/<노드ID>.md`에 적고, 계획서에는 표의 `산출` 칸에 경로만 남긴다 — 주체를 가리지 않는다.** 메인이 직접 처리한 노드도 같다. 계획서는 노드를 하나 돌릴 때마다 통째로 다시 읽히므로, 본문에 눌러앉은 서술은 남은 모든 회차의 비용이 된다.

> **Do:** 계획 구조를 건드리는 제안은 계획서에 적고 커밋한다
> **Don't:** 반영할 것을 보고로 갈음하거나, 노드 안에서 닫힌 세부까지 계획서에 옮겨 적는다

### 미회수 노드 재진입 분기

노드 표에서 상태가 `진행`인 노드를 만나면, 새 노드를 시작하기 전에 노드마다 아래를 수행한다.

1. **위임처 칸을 먼저 본다.** 비어 있으면 **사람을 기다리는 노드다**(주체가 사용자·외부이거나 안내만 하고 넘긴 노드). 재위임 대상이 아니므로 안내가 이미 나갔는지 확인하고, 안 나갔으면 다시 안내한 뒤 그대로 `진행`에 두고 다음 노드로 넘어간다. 위임처가 적혀 있으면 2번으로 간다.
2. 적힌 tmux 세션명으로 `tmux has-session -t <세션명>`을 확인한다. 위임처가 서브에이전트로 적혀 있으면(같은 세션 안의 스폰) 그 세션은 이미 사라진 것이므로 4번으로 간다.
3. **살아 있으면 회수부터** — 진행 보고 요청을 보내고(변별자 규칙은 `/dev-loop` `protocol.md`의 "메시지 첫 줄 문법") 응답과 산출을 회수한 뒤 Phase 2 8번(회수·갱신)으로 합류한다. 새 노드를 먼저 시작하지 않는다.
4. **죽었으면 워크트리와 브랜치를 본다** — `node/<노드ID>` 브랜치에 커밋이 있거나 `nodes/<노드ID>.md`가 있으면 그것을 산출로 보고 회수·검증부터 재개한다. 둘 다 없으면 같은 워크트리를 재사용해 재위임한다(워크트리도 없으면 새로 만든다).

> **Do:** 위임처 유무로 먼저 갈라 사람 대기 노드를 재위임 경로에서 빼고, 살아 있는 위임처는 회수를 새 위임보다 앞에 둔다
> **Don't:** 위임처가 비었다고 죽은 작업 노드로 보아 재위임하거나, `진행` 표시를 무시하고 같은 노드를 두 번 위임한다

## 서브 노드 위임 규칙

- 위임 프롬프트에 **노드 ID·작업 범위·산출 경로·(구현이면) 담당 파일 집합**만 준다. DEV_PLAN 본문을 발췌해 넣지 않고 경로 Read를 지시한다.
- 계획서에 `## 용어` 절이 있으면 **그 절을 읽고 산출·보고에 그 낱말을 쓰라**고 위임 프롬프트에 명시한다.
- 계획서에 `## 조작 절차` 절이 있고 그 노드가 그 절차를 건드리면 **그 절을 읽고 표대로 조작하라**고 명시한다. 표와 어긋나면 스스로 고치지 말고 되묻도록 지시한다.
- 계획서에 `## 의도` 절이 있으면 구현 노드 위임 프롬프트에 **`## 의도`·`## 사용자 여정`·`## 성공 조건` 절을 읽으라**고 지시하고, **그 노드에서는 `/impl`의 PRD 게이트를 수행하지 않는다**고 명시한다.
- 서브는 **노드 실행 결과와 계획 변경 제안**을 `docs/dev/plan/nodes/<노드ID>.md`에 쓴다. 하위 스킬(`/impl`·`/adr`)의 고유 산출물은 그 스킬 규약의 경로를 따른다.
- **DEV_PLAN은 읽기만 한다.** 계획을 바꿔야 한다고 판단하면 노드 파일의 `## 계획 변경 제안` 절에 사유를 적고 보고만 한다.

> **Do:** 서브는 자기 노드 파일만 쓰고, 계획 변경은 제안으로 올린다
> **Don't:** 서브가 DEV_PLAN의 노드 표·흐름도를 직접 고치거나, 위임 범위 밖 노드의 결과를 적는다

## tmux 세션 위임

**병렬 구현 노드에만 쓴다.** 노드를 워크트리에 격리하고 그 안에서 새 Claude 세션을 띄워 `SendMessage`로 주고받는다. 서브에이전트 스폰과 달리 **전역·프로젝트 지시문이 새로 실리고 완료 보고가 명시 발신으로 온다.** 대가로 세션마다 기동 비용이 다시 드니 **단독 노드·조사 노드는 서브에이전트가 싸다.**

1. **세션명과 자기 주소.** 작업 세션명은 `~/.claude/scripts/dev-view.sh --name <노드ID>`로 노드마다 한 번 얻어 그 노드의 모든 tmux 명령에 쓴다. 손으로 짓지 않는다 — 슬러그 산출식을 뷰어·잔재 정리와 공유한다. **이어서 자기 이름을 확보한다** — `ListAgents`가 첫 줄에 이 세션의 이름을 `This session is <이름> [<ref>]` 형태로 알려준다. **그 `<이름>`이 위임 메시지 [통신]의 `<호출자 고정 이름>`에 그대로 들어간다** — 작업 세션이 보고·질문을 되돌려 보낼 유일한 주소이므로 위임 전에 반드시 확보한다. 이 이름은 `/clear`를 건너 유지되므로 회차가 바뀌어도 같다(2026-09-05 실측).
2. **워크트리.** "병렬 구현 노드의 격리와 합류" 1번. 동시 실행이어도 **하나씩 순차로** 만든다.
3. **적립.** 노드 상태를 `진행`으로 바꾸고 위임처(세션명)·워크트리 경로를 노드 표에 적어 커밋한다(Phase 2 5번). **기록이 위임에 선행한다.**
4. **세션 생성.**

```bash
uuid=$(uuidgen | tr 'A-Z' 'a-z')
printf '%s' "<위임 메시지>" > <프롬프트 파일>
tmux new-session -d -s <세션명> -c <워크트리 절대경로> -x 180 -y 48 \
  "env -u CLAUDE_JOB_DIR CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false \
   claude --session-id $uuid --name <세션명> <승인 인자> \"\$(cat <프롬프트 파일>)\""
```

- **첫 프롬프트를 셸 명령 문자열에 직접 넣지 않는다** — 대괄호가 glob에 걸려 세션이 즉시 죽고 `tmux ls`에도 남지 않는다. 파일에 쓰고 `"$(cat <파일>)"`로 넘긴다.
- **`-x 180 -y 48`을 생략하지 않는다.** 기본 크기로 띄우면 뒤에 사람이 붙는 창을 열 때 화면이 그 창 크기로 바뀌고 **떼어내도 돌아오지 않는다**(2026-09-05 실측). 처음부터 붙는 창과 같은 크기면 변동이 없다.
- **`CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false`는 보험이 아니라 필수다** — 입력줄의 추천 문구는 사람이 보낸 것처럼 보이는 유령이라 화면으로 상태를 판정하는 자리를 흔든다.
- **`<승인 인자>`는 모드로 갈린다.** 사람이 앞에 있는 평소 호출이면 **비워 둔다** — 승인·선택지는 사람이 아래 "붙는 창"에서 답한다. '자동 이어가기 모드'로 도는 중이면 `--dangerously-skip-permissions`를 넣는다. 무인이라 승인 창을 누를 사람이 없고, 그대로 두면 그 노드가 영영 멎는다.
- **워크트리는 메인 저장소의 신뢰를 물려받아 폴더 신뢰 확인 창이 뜨지 않는다**(2026-09-05 실측). 저장소 밖 경로에서 띄우면 그 창에서 멎으므로 **작업 위치는 반드시 워크트리로 한다.**

5. **주소 확보.** `ListAgents`로 `tmux <세션명>:`을 포함한 행을 찾아 이름을 얻는다. 등록에 몇 초 걸리므로 첫 조회에 없으면 1회 더 조회하고, 그래도 없으면 "폴백"으로 간다. 얻은 이름은 그 노드가 끝날 때까지 재사용한다. **배달 봉투의 발신자 값은 회신 주소로 쓰지 않는다** — 소켓 경로라 매번 바뀐다.
6. **화면 비추기.** `~/.claude/scripts/dev-view.sh`를 인자 없이 실행해 작업 세션들을 한 창에 비춘다. **뷰어 호출이 실패해도 위임은 그대로 진행한다** — 읽기 전용 미러라 노드 처리와 무관하다. 반면 `tmux new-session` 자체가 실패했으면 "폴백"으로 간다.
7. **위임은 4번에서 이미 끝났다.** 첫 프롬프트가 위임 메시지 전문을 전달한다 — **같은 것을 `SendMessage`로 다시 보내지 않는다.** 두 번 받은 세션은 같은 지시에 두 번 착수한다. 5번의 주소는 회신 수신·재촉·질의 응답에만 쓴다.
8. **대기·회수.** 회신 첫 줄로 노드를 판별한다(`[<노드ID>] 완료|실패|질문|진행 — <한 줄 요지>`). 워크트리에서 `git log -1 --format=%H`로 커밋을, 보고에 산출 경로가 있으면 파일 실재를 확인한다. 보고의 `검증:` 값이 실패·중단이면 커밋과 산출이 있어도 완료로 처리하지 않고 노드를 `실패`로 둔다. **위임하고 나면 유휴로 멎어 회신을 기다린다** — 살아 있음을 보이려 주기적으로 깨어나지 않는다. **단 '자동 이어가기 모드'로 도는 중이면 이 자리에서 곧바로 아래 "무응답 처분"으로 넘어간다** — 무인 세션에는 이상을 눈치채고 깨울 사람이 없어, 여기서 무기한 멎으면 회차 전환에 영영 닿지 못한다. 무기한 유휴는 사람이 앞에 있는 세션에서만 허용된다.
9. **정리.** 회수·머지가 끝나면 `tmux kill-session -t <세션명>`과 `git worktree remove`로 치우고 `~/.claude/scripts/dev-view.sh --sync`를 실행한다.

**붙는 창 — 사람이 답해야 할 때.** 작업 세션에 승인 창이나 선택지가 뜨면 뷰어 창의 그 칸을 **더블클릭**해 단독 창을 연다. 뷰어 창이 없거나 다른 환경이면 `tmux attach -t <세션명>`으로 직접 붙는다. 미러와 달리 attach이므로 입력이 들어가고, 답한 뒤 창을 닫으면 자동으로 떨어진다. 무인 진행 중에는 이 길이 없으므로 4번의 승인 인자로 미리 막는다.

**폴백.** 위임의 어느 단계든 실패하면 **1회 재시도**하고, 그래도 실패하면 그 노드에 한해 메인이 직접 처리한다(구현이면 `/impl`). 넘어가기 전에 그 노드의 tmux 세션을 종료하고 커밋 없는 워크트리를 제거한다.

> **Do:** 위임처를 적어 커밋한 뒤에 세션을 띄우고, 회신을 기다리며 유휴로 멎는다
> **Don't:** 첫 프롬프트로 보낸 위임을 `SendMessage`로 한 번 더 보내거나, 봉투의 발신자 값을 회신 주소로 쓴다

### 무응답 처분

**회신이 오지 않는 노드는 재촉 1회로 닫는다.** 사람이 앞에 있으면 기다림의 시계를 사람이 재지만, '자동 이어가기 모드'로 도는 중에는 잴 주체가 없어 이 절차가 없으면 회차가 통째로 멎는다.

1. 진행 보고를 1회 요청한다 — 본문 첫 줄은 위 8번의 표식 문법을 따른다.
2. **10분짜리 유한 블로킹 대기 한 번**으로 자기 턴에서 재고, 호출이 끝난 자리에 배달된 회신 유무로 판정한다. 기다리던 회신이 이미 와 있으면 대기를 생략한다. **외부 타이머·"10분 뒤에 다시 본다"는 약속에 기대지 않는다** — 턴을 끝내면 유휴로 멎어 그 약속을 지킬 주체가 없다.
3. 그래도 무응답이면 노드를 `실패`로 두고 세션을 종료하되 **워크트리는 남긴다.** 다음 회차의 "미회수 노드 재진입 분기" 4번이 브랜치 커밋을 산출로 주워 간다.

**사람 대기 노드는 이 감시에서 제외한다** — 사람의 침묵에는 상한을 걸지 않는다.

## 세션 경계 규칙

- **무게 판정은 메인이 직접 실행한 노드에만 적용한다.** 서브 노드는 요약만 회수하므로 무게에 세지 않는다.
  - **무거움**: 연구 노드 / 실행 노드 / 디자인 노드 / 메인 직접 작성 경로의 설계 노드 / 대화 인테이크 왕복 5회 이상
  - **가벼움**: 서브 노드 회수 / synthesizer 경유 설계 노드 / 왕복 4회 이하 대화
- 정지·계속 판단은 방금 끝낸 노드의 **실제 진행**으로 한다.
- 한 노드를 마칠 때마다:
  - 방금 마친 것이 무거움 → **정지**. 계획서 갱신 + "`/clear` 후 `/dev`로 이어가세요" 안내.
  - 방금 마친 것이 가벼움 + 다음 실행 가능 노드도 가벼움 → Phase 2 1번으로 돌아가 이어 실행.
  - 다음 실행 가능 노드가 무거움 → 정지·안내. 실행 가능 노드 없음 → 대기 중인 사용자·외부 노드를 안내하거나 완료 보고.
- **'자동 이어가기 모드'가 켜져 있으면 정지 자리에서 그 절을 따른다.** 무게 판정과 노드 선정은 그대로다.
- **세션 종료 커밋.** 정지·완료로 세션을 끝내기 직전, 작업 트리에 미커밋 변경이 있으면 커밋한다 — 태그는 생성하지 않는다(전역 커밋·태그 규칙의 사이클 태깅을 `/dev` 세션 종료 커밋과 "인수인계 상시 적립"의 적립 커밋에 한해 면제). "인수인계 상시 적립"을 지켰으면 여기서 새로 쓸 것은 거의 없다 — 남은 미커밋 변경만 담는다. 없으면 생략.

> **Do:** 무거운 노드 하나로 그 세션을 끝내고, 미커밋 변경은 커밋만 남긴다
> **Don't:** 한 호출에서 무거운 노드 2개를 연달아 처리하거나, 태그를 붙이거나, 커밋 없이 다음 세션으로 넘긴다

## 자동 이어가기 모드

'세션 경계 규칙'의 정지 자리에서 사람 대신 `/clear` + `/dev` 재호출을 예약해 다음 회차로 잇는다.

**켜는 조건 셋이 모두 필요하다** — **`$TMUX_PANE`이 비어 있지 않음**(`$TMUX`가 아니다 — 예약이 판을 그 값으로 지목하므로, 세션을 이어받아 들어와 그 값을 잃은 세션은 자기 판을 못 집는다) · `--auto` · 종료조건(`--until <시각>`·`--until-node <노드ID>` 중 최소 하나). tmux 안인데 종료조건이 없으면 켜지 않는다. 자동 모드를 쓸 수 있다는 사실만 1줄 알리고 평소대로 정지한다. '위임 실행 모드'·'단일 노드 실행'에는 적용하지 않는다.

**명령줄이 유일한 인수인계다.** 다음 회차 호출에 `--resume <계획서 경로>`·`--auto`·종료조건·(있으면) `--judge-said`를 **글자 그대로 복사**해 싣는다. 계획서 경로는 반드시 명시한다 — 인자 없이 부르면 진행 중 계획서가 둘 이상일 때 '진입 분기' 4번이 질문하고 멎는다.

> **Do:** 종료조건 문자열을 회차마다 그대로 복사해 넘긴다
> **Don't:** 회차 번호처럼 매번 값을 계산해야 하는 것을 명령줄에 싣는다

### 선결 질문 일괄 수집

**켜는 조건을 통과한 첫 회차에서 1회만 한다.** 사람은 이 자리에만 있다 — 다음 회차부터 화면 앞이 비어, 사람만 답할 수 있는 것을 만나면 그 노드가 멎거나 주행이 그 자리에서 끝난다. 그래서 착수 전에 남은 노드 전체를 훑어 **사람 몫을 한 번에 모아 묻고 답을 파일에 적립한다.**

**수집 여부는 파일 존재로 가른다** — `docs/dev/plan/DECISIONS-NNN.md`(NNN은 계획서 번호)가 있으면 이미 수집한 것이므로 건너뛰고 곧장 '회차 시작 게이트'로 간다. 명령줄 플래그로 가르지 않는다 — 회차마다 복사해 넘길 값이 하나 늘고, 한 번 빠지면 무인 회차가 사람에게 묻다 멎는다.

**묻는 것은 넷이다.** 상태가 `대기`·`진행`인 노드 전부를 대상으로 훑는다.

1. 계획서에 `미확인 —`으로 남은 칸과 사용자만 닿는 미지수 — 사람이 하는 화면 조작 절차·업무 관행·자격·물리 접근(`planning.md` "정보 출처 판정"의 ⓒ). **정의를 여기 되풀이하는 것은 이 절이 그 파일을 읽지 않는 재진입 회차에서도 도는 자리이기 때문이다.**
2. 주체가 `사용자`인 노드가 요구하는 것 중 **글로 답해 닫히는 것** — 절차 청취·시안 선택. 사람이 그 자리에서 눈으로 봐야 하는 실환경 확인은 묻지 않고 `미답`으로 적는다
3. 되돌릴 수 없는 실행 노드(배포·데이터 이관·외부 전송)의 사전 승인과 그 범위 — 승인 표의 `물은 것` 칸에 **대상을 이름으로** 적는다("사내 VM으로 파일 전송"이지 "배포 승인"이 아니다)
4. 갈래를 사람의 정책·취향이 가르는 노드 — 설계 노드의 후보안 선택, 기술 실측으로 판정되지 않는 `조건` 칸

**묻지 않는 것.** 코드·문서·웹으로 확인되는 것(ⓐ)과 돌려 보면 나오는 것(ⓑ), 기술 판단으로 갈리는 선택지. 마지막 것은 주행 중 "선택지 처분"이 `dev-choice-judge`에 맡긴다. **답이 필요해질지도 모르는 것까지 모으지 않는다** — 주행 앞에 인터뷰가 서고 그 답의 대부분은 쓰이지 않는다.

**한 묶음으로 내보내고 답을 다 받기 전에는 진행하지 않는다.** 선택지가 뚜렷하면 `AskUserQuestion`으로 묻고(한 호출에 4개까지, 남으면 이어 호출), 서술형이면 번호를 달아 화면에 함께 묻는다. 사용자가 "모른다"·"그때 정하자"로 답한 항목은 `미답`으로 적고 **그 항목에 걸린 노드를 이번 주행의 실행 대상에서 뺀다** — 상태는 `대기`로 두되 **Phase 2 2번의 실행 가능 노드 검색과 "종료 판단과 심판"의 계산 양쪽에서 제외한다.** 한쪽만 빼면 노드는 그대로 선정돼 사람 몫 앞에서 멎는다.

**되돌릴 수 없는 노드의 승인은 하류 유무로 갈린다.** 사전 승인을 받았어도 그 노드가 계획의 **끝단이면**(그 노드를 선행으로 삼는 노드가 없음) 무인으로 실행하지 않는다 — 나머지 노드를 모두 완주한 뒤 그 노드만 `대기`로 남기고 정지하며, 정지 사유에 "사람 확인 후 실행할 노드"로 한 줄 남긴다. **하류 노드가 걸려 있으면 승인 범위 안에서 무인 실행한다** — 여기서 멈추면 승인해 둔 의미가 없고 뒤 노드가 통째로 묶인다. 승인이 없는 비가역 노드는 하류 유무와 무관하게 "노드 종류" 표대로 주체를 사용자로 되돌린다.

> **Do:** 뒤가 막히는 전송·반영은 승인 범위 안에서 돌리고, 마지막 공개 배포는 남겨 둔 채 주행을 닫는다
> **Don't:** 끝단 배포를 사전 승인만 믿고 무인으로 밀거나, 승인받은 중간 전송에서 멈춰 하류를 묶는다

**적립 형식.**

```markdown
---
plan: <DEV_PLAN 파일명>
collected: YYYY-MM-DD HH:MM
---

| # | 노드 | 물은 것 | 답 | 적용 |
|---|------|--------|----|------|
| 1 | 007-N4 | 배포 대상 서버 | 스테이징만 | 그 노드 |
| 2 | — | 스키마 변경 시 허용 다운타임 | 5분까지 | 계획서 전체 |
```

`적용`이 `계획서 전체`면 뒤 노드가 같은 종류의 선택을 만날 때도 이 답을 쓴다. 수집을 마치면 이 파일을 계획서와 함께 커밋한 뒤 게이트로 간다("인수인계 상시 적립" 3번).

> **Do:** 사람이 있는 첫 회차에서 남은 노드 전체의 사람 몫을 모아 묻고 파일로 남긴다
> **Don't:** 회차마다 다시 묻거나, 기술 판단으로 갈리는 선택지까지 미리 묻는다

### 회차 시작 게이트

Phase 2 진입 전에 본다. 하나라도 걸리면 예약하지 않고 사유를 화면에 1줄 남긴 뒤 정지한다.

| 문 | 통과 조건 |
|---|---|
| 판 점유 | `~/.claude/dev-loop/<경로 슬러그>/runner.json`이 없거나 `state`가 `종료`·`중단` |
| 사용량 | 5시간 사용률 90% 미만 **그리고** 7일 사용률 80% 미만 |
| 종료조건 | `--until` 시각 이전이고, `--until-node` 노드가 아직 완료 전 |

**경로 슬러그**는 프로젝트 루트 절대경로의 `/`를 `-`로 치환한 값이다.

**사용량은 자기 상태 파일에서 읽는다.** 파일 지목 방법은 '컨텍스트 임계 판정'과 같다.

```bash
jq -r '.rate_limits | [.five_hour.used_percentage, .seven_day.used_percentage, .five_hour.resets_at] | @tsv' ~/.claude/status/<자기 세션 UUID>.json
```

값을 확실히 못 읽으면 정지한다 — 파일 수정 시각이 5분 이상 지남 / `resets_at`이 현재 시각 이전 / `rate_limits` 필드 없음 셋이 여기 해당한다. **`rate_limits` 필드 없음만 5초 후 1회 재시도한다** — 회차 시작 직후 아직 채워지지 않은 자리다.

> **Do:** 못 읽으면 그 자리에서 정지한다
> **Don't:** 못 읽은 값을 0으로 보거나, 다른 세션의 상태 파일로 대신한다

### 선택지 처분

**먼저 이미 받아 둔 답이 있는지 본다** — `DECISIONS-NNN.md`에서 그 노드 행 또는 `적용`이 `계획서 전체`인 행이 이 선택지를 덮으면 그대로 처리하고 스폰하지 않는다("선결 질문 일괄 수집"). 덮는 행이 `미답`이면 스폰 없이 아래 `판정: 사람 호출`과 같이 처분한다 — 사람이 이미 답을 미룬 자리다. **덮는지 애매하면 덮지 않은 것으로 보고 평소대로 스폰한다** — 남의 답을 끌어다 쓴 결정은 판정관을 건너뛰므로 아무 데도 걸리지 않고 조용히 진행된다.

덮는 답이 없으면, 승인·선택지를 만나 멈추게 될 때 **멈추기 전에 `dev-choice-judge`를 스폰해 결정을 위임한다.** 무엇을 스스로 정하고 무엇을 사람에게 올릴지는 그 에이전트가 정하므로, 여기서 미리 가르지 않는다.

전달할 것은 여섯이다 — 계획서 절대경로 · 노드 ID · 선택지 원문 전부 · 각 선택지를 실행하면 무엇이 바뀌는지 · 이미 시도해 실패한 것 · 계획서·ADR에 적힌 관련 제약.

- **`판정: 결정`** → 반환된 선택대로 절차를 계속한다.
- **`판정: 사람 호출`** → 「다음 회차 예약」을 걸지 않고 정지하고, 정지 사유에 노드 ID와 반환된 질문을 한 줄 남긴다.
- **스폰이 실패하거나 어느 쪽을 택했는지 특정되지 않는 반환** → 사람 호출과 같이 처분한다.

**한 선택지에 스폰은 1회다.** 반환이 미흡해도 다시 묻지 않는다.

**결정은 `nodes/<노드ID>.md`에 `선택지 결정: <선택> | <사유> | <시각>` 한 줄로 적립한다.** 스폰 전에 그 노드 파일에 같은 선택지의 줄이 이미 있는지 먼저 본다 — 있으면 그 값대로 처리하고 스폰하지 않는다. 회차가 바뀌면 기억이 지워져, 조회가 없으면 같은 선택지를 회차마다 다시 판정하고 답이 그때그때 달라진다.

> **Do:** 멈출 자리를 만나면 먼저 스폰하고 반환된 결정대로 계속한다
> **Don't:** 사람이 앞에 있는 평소 호출에서 스폰한다 — 직접 묻는 편이 싸다

### 종료 판단과 심판

| 종류 | 사유 | 처리 |
|---|---|---|
| 기계적 | '회차 시작 게이트'에 걸림 | 즉시 정지. 심판을 부르지 않는다 |
| 판단 | 실행 가능 노드 없음 / 사람 대기 노드만 남음 / 그 밖에 더 잇지 못한다고 본 경우 | `dev-halt-judge`를 스폰해 심사 |

심판에 넘길 것은 다섯이다 — 계획서 절대경로 · 이번 종료 사유 · 종료조건 원문 · 직전 회차의 `--judge-said` 값(있을 때만) · `DECISIONS-NNN.md`에서 `미답`으로 막힌 노드 ID 목록(있을 때만, "이 노드는 지목 대상이 아니다"를 함께 적는다).

심판은 판결에 따라 둘 중 하나를 돌려준다 — 종료면 두 줄, 계속이면 `지목 노드:`가 낀 세 줄이다.

```
판결: 종료
사유: <한 줄>
```

```
판결: 계속
지목 노드: <노드ID>
사유: <한 줄>
```

- **`판결: 종료`** → 정지한다.
- **`판결: 계속`** → `지목 노드:`가 가리킨 노드부터 이어 실행하고, 다음 회차 명령줄에 `--judge-said "<지목 노드ID>: <사유>"`로 싣는다. **`지목 노드:` 줄이 없으면 정지한다** — 지목 없는 계속은 판결로 치지 않는다.
- **`지목 노드:`가 미답 목록의 노드를 가리키면 판결을 버리고 정지한다** — 넘기며 지목 대상이 아니라고 적은 노드다.
- **같은 노드에서 두 번째 판단 종료가 나오면 심판을 부르지 않고 정지한다** — 이번 종료 사유가 직전 `--judge-said`의 **노드 ID**를 다시 가리키면 여기 해당한다. 문구가 아니라 노드 ID로 가른다.
- 심판 스폰이 실패하면 원래 판단대로 정지한다.

### 다음 회차 예약

**열린 위임이 남아 있으면 예약하지 않는다.** 노드 표에 위임처가 적힌 `진행` 노드가 하나라도 있으면 먼저 "tmux 세션 위임" 8번(회수)과 "무응답 처분"으로 닫는다. **회신이 `[질문]`으로 온 채 열린 노드는 "무응답 처분" 대상이 아니다** — 답할 사람이 없어 재촉해도 닫히지 않는다. 이런 노드가 남으면 예약하지 않고 정지하되 **정지 사유에 그 노드 ID와 질문 요지를 한 줄 남긴다** — 남기지 않으면 왜 멈췄는지 어디에도 없어 사람이 재개 시점을 알 수 없다. 그러고도 닫히지 않은 것이 남으면 예약을 걸지 않고 그 자리에 정지한다 — 기억을 지운 다음 회차는 그 세션이 도는 줄 모른 채 새 노드를 시작하고, 작업 세션은 아무도 읽지 않는 주소로 회신하다 5회 만에 멎는다. **금지가 아니라 회수를 앞세우는 것이다** — 무조건 막으면 회수되지 않는 노드 하나가 자동 모드를 영영 붙잡는다. 위임처 칸이 빈 `진행` 노드(사람·외부 대기)는 여기 세지 않는다.

**계획서 갱신 커밋이 성공한 것을 확인한 뒤에 예약한다.** 커밋이 실패했으면 예약하지 않고 정지한다 — 상태가 남지 않은 채로 기억을 지우면 다음 회차가 같은 일을 처음부터 다시 한다.

```bash
TP="$TMUX_PANE" TX="$(command -v tmux)" NEXT='<다음 회차 호출 전문>' \
LOGF="$HOME/.claude/dev-loop/<경로 슬러그>/next-round.log" \
nohup zsh -c '
  mkdir -p "$(dirname "$LOGF")"
  give_up() { echo "$(date "+%F %T") 예약 포기: $1" >> $LOGF; exit 0; }
  [ -z "$TP" ] && give_up "판 식별자 없음 — 빈 값은 남의 판을 집는다"
  still() {
    local i prev cur
    prev=""
    for i in $(seq 1 150); do
      cur=$($TX capture-pane -t "$TP" -p)
      if [ -n "$prev" ] && [ "$prev" = "$cur" ]; then return 0; fi
      prev=$cur
      sleep 2
    done
    return 1
  }
  ok_input() {
    local x
    x=$($TX display-message -p -t "$TP" "#{cursor_x}")
    [ "$x" = "2" ] && return 0
    echo "$(date "+%F %T") 입력줄 판정 실패 — cursor_x=$x" >> $LOGF
    return 1
  }
  still || give_up "화면이 5분간 멎지 않음"
  ok_input || give_up "입력줄에 글자 있음"
  $TX send-keys -t "$TP" -l "/clear"; sleep 2; $TX send-keys -t "$TP" Enter
  sleep 3
  still || give_up "/clear 후 화면이 5분간 멎지 않음"
  ok_input || give_up "/clear 후 입력줄에 글자 있음"
  $TX send-keys -t "$TP" -l "$NEXT"; sleep 2; $TX send-keys -t "$TP" Enter
  echo "$(date "+%F %T") 예약 성공 — 다음 회차 전송" >> $LOGF
' >/dev/null 2>&1 &
echo "예약 PID: $!"
```

- **글자와 Enter를 나눠 보낸다** — 명령 목록이 자리 잡을 틈이 필요하다.
- **판은 `$TMUX_PANE`으로 지목하고 `-t "$TP"`처럼 인용한다** — 세션 이름만 주면 그 사이 활성화된 다른 판에 들어간다. **인용을 빼면 그 값이 빈 세션에서 `-t $TP -p`가 `-t -p`로 무너져** 뒤 인자가 타겟 자리로 밀리고, tmux는 기본값인 「가장 최근 활성 판」을 집는다 — 남의 프로젝트 판에 `/clear`를 보낸다.
- **화면이 멎을 때까지 기다렸다 보낸다** — 2초 간격으로 떠서 직전과 같으면 조용해진 것으로 본다. 5분(150회) 동안 안 멎으면 사람이 붙어 있다고 보고 아무것도 보내지 않는다. **고정 대기(`sleep 5`)를 쓰지 않는다** — 예약을 건 그 응답의 마무리 발언이 그 창에 걸려, 자기 말소리를 사람 개입으로 오인하고 매번 물러난다(2026-09-04 실측: 5초 시점 diff가 자기 출력).
- **화면이 멎었어도 입력줄에 사람이 친 글자가 있으면 보내지 않는다** — 그 위에 `/clear`를 얹으면 쓰던 것이 사라진다. 판정은 **화면 글자가 아니라 커서 자리(`cursor_x`)로 한다.** 빈 입력줄은 프롬프트 두 칸 뒤인 `2`이고, 사람이 친 글자만 커서를 민다. **화면 글자로 재면 명령어 추천을 사람 입력으로 오인해 매 회차 물러난다** — 추천은 직전 대화에 맞춰 거의 늘 떠 있고 커서 뒤에 그려져 커서를 밀지 않는다. 이 `2`는 프롬프트 표기에 매인 상수다 — 표기가 바뀌면 어긋나 매번 물러설 뿐 오통과는 없으므로, **이어가기가 이유 없이 멈추면 로그의 `cursor_x` 값으로 상수를 갱신한다.**
- **두 검사는 `/clear` 직전과 다음 호출 직전 두 번 다** 통과해야 보낸다.
- **포기와 성공을 다 로그에 남긴다** — 여섯 갈래(판 식별자 없음 1회, 정지 실패·입력줄 점유 각 2회, 성공 1회) 모두 `next-round.log`에 시각과 함께 적고, 입력줄 점유는 **잰 `cursor_x` 값까지 적는다.** 무통보로 끝내면 이어가기가 끊긴 사실을 아무도 모른 채 다음 회차를 기다리고, 잰 값을 안 남기면 스크립트 결함이 사람 탓으로 오진된다.
- **다음 회차 호출은 인자를 붙인 형태로 보낸다** — 맨 `/dev`는 명령 목록에서 `/dev-loop`가 선택될 수 있다.
- 코드 마지막 줄의 `echo`가 낸 예약 프로세스 번호를 화면에 1줄 남긴다.

## 컨텍스트 임계 판정

세션에 쌓인 **입력 토큰 절대량**으로 판정한다. 임계는 **상수가 아니라 창 크기에서 계산한다** — 창 크기는 포화도와 **같은 상태 파일**이 준다.

**자기 상태 파일 지목.** 1차 수단은 이 세션의 스크래치패드 경로에 박힌 UUID이고, 보조가 `CLAUDE_CODE_SESSION_ID` 환경 변수다. **같은 디렉토리에서 수정 시각이 가장 최신인 파일을 자기 것으로 삼지 않는다** — 거기에는 수십 개 세션의 파일이 함께 쌓여 남의 포화도를 자기 것으로 읽는다.

```bash
jq -r '[.context_window.total_input_tokens, .context_window.context_window_size] | @tsv' ~/.claude/status/<자기 세션 UUID>.json
```

| 임계 | 산출 | 행동 |
|---|---|---|
| 약함 | `min(300000, 창 × 0.75)` | 새 작업 단위를 시작하지 않는다. 이미 시작한 것은 끝까지 회수·갱신한 뒤 정지·인수인계 |
| 강함 | `min(400000, 창 × 0.9)` | 진행 중인 것을 두고 나간다. 진행 상태 한 줄만 적립하고 즉시 정지 |

- **절대 토큰으로 계산하고 퍼센트를 쓰지 않는다.** 같은 상태 파일이 창 크기를 주므로 절대 토큰으로 직접 계산하는 편이 정확하다.
- **상한을 그대로 상수로 박지 않는다.** 창이 200K로 내려오면 고정 상한은 창 전체에 가까워져 닿는 순간 이미 자연사한 뒤이고 강한 임계는 영영 울리지 않는다 — 값도 코드도 정상으로 보여 판정이 죽었다는 사실조차 드러나지 않는다. **창 200K~400K는 상한이 걸리지 않아 계수만으로 값이 정해진다.**
- **약한 상한 300,000은 주행거리를 버는 값이다.** 상한이 200,000이면 한 세션이 기동 바닥 위에서 11만 남짓 일하는데 300,000이면 21만 안팎이 되어, 정지·인수인계 횟수와 회차마다 새로 까는 바닥이 줄어든다. 약한↔강한 간격은 창 1M에서 100,000으로 실측 소진폭 30,000의 3.3배가 남고, 인수인계를 상시 적립하므로 강한 임계를 넘어도 유실은 없다.
- **검사 자리는 작업 단위 경계다** — Phase 2는 노드 위임 직전(두 값 다), Phase 3은 묶음 시작 직전(약한 임계). 완료 직후와 다음 시작 직전은 같은 시점이므로 두 번 재지 않고, 작업 단위가 도는 중에는 재지 않는다.
- **판정은 숫자 비교다. LLM 판단이 아니다.** 방금 사이클 하나의 체감으로 일반화하지 않는다.
- **강한 임계는 정상 경로에서 울리지 않는다.** 울렸으면 DEV_PLAN에 한 줄 남긴다 — 약한 임계의 전제가 깨졌다는 재조정 신호다.
- **계측 실패의 처분은 세션 성격으로 갈린다.** 상태 파일을 못 읽으면 어느 쪽이든 2초 후 1회 재시도한다.
  - **사용자 대면 세션** — 재시도도 실패하면 임계 판정을 건너뛰고 '세션 경계 규칙'의 무게 판정만 쓴다. 옆에 사람이 있으므로 포화는 사람이 잡는다.
  - **무인 세션**(`/dev-loop`의 지휘 세션, '자동 이어가기 모드'로 도는 세션 등 사용자가 화면을 보지 않는 세션) — 작업 단위 경계에서 **연속 2회 실패하면 약한 임계 도달로 간주**한다. 새 작업 단위를 시작하지 않고 계측 불능을 호출자에 보고한 뒤 정지·인수인계로 간다. 계측이 죽은 채 무한히 도는 것은 금지다.

## 인수인계 상시 적립

인수인계를 세션 끝에 몰아 쓰지 않는다. **DEV_PLAN을 상시 적립해 어느 순간 끊겨도 최신이게 한다.** 적는 시점은 셋이고 **각각 커밋한다.**

| 시점 | 적는 것 |
|---|---|
| 1. **위임 직전** | 노드 상태를 `진행`으로 + 위임처(tmux 세션명) + 워크트리 경로 ("미회수 노드 재진입 분기"의 입력) |
| 2. **회수 직후** | 결과와 판정 근거. 분기 노드면 고른 갈래와 그 이유 |
| 3. **결정이 오갈 때마다** | 사용자·호출자와 정한 것을 한 줄 |

이렇게 하면 포화로 세션이 끊길 때 새로 쓸 인수인계가 남지 않는다 — 임계의 차이가 "인수인계를 쓰느냐"가 아니라 **"진행 중인 것을 회수하고 나가느냐 두고 나가느냐"**가 된다.

- **적립 커밋에는 태그를 붙이지 않는다.** 볼트처럼 "모든 커밋에 태그"를 요구하는 저장소에서도 중간 과정 커밋은 면제한다(2026-08-22 사용자 승인).
- **경로를 지정해 커밋한다** — `git add <DEV_PLAN 경로> <nodes/…>`. **`git add -A`·`git add -u`는 쓰지 않는다** — 같은 저장소에서 도는 동기화 잡이나 다른 세션의 변경을 함께 실어 보낸다.
- **쓰기와 커밋 사이를 벌리지 않는다.** 갱신은 임시 파일에 쓴 뒤 rename하는 원자 쓰기로 하고 곧바로 커밋한다. 반쯤 쓰인 파일이 남의 스테이징에 실려 가는 창을 줄인다.
- **커밋 SHA를 참조로 저장하지 않는다** — 동기화 잡의 `pull --rebase`가 커밋을 다시 쓴다. 노드 표의 `산출` 칸에는 경로·브랜치명을 적는다.
- **push·pull은 하지 않는다.** 커밋이 `index.lock` 경합으로 실패하면 2초 후 1회 재시도하고, 재실패하면 다음 적립 시점에 합쳐 커밋한다(파일은 이미 써 있다).

> **Do:** 위임 직전·회수 직후·결정 시점마다 경로를 지정해 태그 없이 커밋한다
> **Don't:** 인수인계를 세션 끝에 몰아 쓰거나, `git add -A`로 담거나, SHA를 계획서에 적어 둔다

## 계획서 덜어내기

계획서는 노드마다 통째로 다시 읽힌다 — **부피가 곧 남은 모든 회차의 비용이다.** 「반영·보고 선택 기준」의 기록 자리 규칙을 지켜도 긴 계획은 자란다. 그래서 회수 때마다 한 번 재고, 넘으면 그 자리에서 덜어낸다.

**재는 때와 값.** "인수인계 상시 적립" 2번(회수 직후) 커밋 **직전**에 `wc -l <DEV_PLAN 경로>`를 본다. **800줄을 넘고 아래 이관 대상이 하나라도 있으면** 덜어낸 결과를 같은 커밋에 담는다. 대상이 없으면 재기만 하고 넘어간다 — 살아 있는 내용만으로 800줄을 넘는 계획서를 매 회차 붙잡지 않는다.

**단 하나는 줄 수와 무관하게 매 회수마다 한다** — 방금 `완료`·`건너뜀`이 된 노드의 문단(`## 대기 노드 실행 지시` 절의 그 노드 항목과 표 밖에 남은 그 노드 서술)을 그 자리에서 `nodes/<노드ID>.md`로 내린다. **800줄은 쌓인 것을 치우라는 상한이지 그 아래에서 쌓아도 된다는 허가가 아니다.**

> **Do:** 노드를 완료로 넘기는 그 커밋에서 그 노드의 지시 문단을 함께 내린다
> **Don't:** 800줄에 닿을 때까지 끝난 노드의 지시를 계획서에 쌓아 둔다

**옮기는 것은 셋뿐이다.**

1. 상태가 `완료`·`건너뜀`인 노드를 다루면서 **노드 표 밖에 남아 있는** 서술 전부 — 표준 구조를 벗어나 붙은 절이든 표 아래 딸린 자유 서술이든 자리를 가리지 않는다
2. 상태가 `진행`인 노드의 회차 기록 중 **직전 회차보다 오래된 것** — 진행 중인 노드도 지난 회차는 이관 대상이다. 다음 세션이 필요로 하는 것은 "지금 어디까지 왔나"이지 "몇 회차 전에 무엇을 했나"가 아니다. **회차는 노드 ID와 회차 번호를 함께 단 머리 문단**(`002-N8 21차` 등)**을 경계로 가른다. 그런 표시가 없으면 회차로 세지 말고 노드 단위로 판정한다** — 진행 중이면 통째로 남긴다
3. `- [x]`이거나 취소선·완료 표시로 닫힌 후속·유보 항목 — 체크박스만 보지 않는다

**남기는 것.** 프론트매터, `## 목표`·`## 의도`·`## 사용자 여정`·`## 용어`·`## 성공 조건`·전제 절·`## 아키텍처 결정`, 흐름도, **노드 표는 한 행도 빼지 않는다**, 열린 후속·유보 항목, `## 대기 노드 실행 지시`의 대기·진행 노드 항목, 진행 노드의 직전 회차.

**목적지.** 1·2는 `nodes/<노드ID>.md`로 옮긴다. 한 노드에 회차가 여럿이면 `nodes/<노드ID>-run<회차>-<YYYYMMDD>.md`로 나눈다. 옮긴 자리에는 아무것도 남기지 않는다 — 노드 표의 `산출` 칸이 링크이고, 비어 있으면 거기에 경로를 적는다. 3은 옮기지 않고 지운 뒤 그 자리에 `<!-- YYYY-MM-DD 닫힌 항목 N건 제거 -->` 한 줄만 남긴다(이력은 git이 갖는다).

**방식은 오려 붙이기다 — 요약이 아니다.** 원문을 글자 하나 고치지 않고 그대로 옮긴다. 무엇이 중요한지 골라 줄이면 다음 세션이 필요로 할 근거가 소리 없이 사라지고, 사라졌다는 사실조차 남지 않는다. 부피는 옮기기만 해도 똑같이 줄어든다.

**옮긴 뒤 검산한다.** ① `git diff --stat`으로 계획서에서 지운 줄 수와 노드 파일에 붙은 줄 수를 대조한다(닫힌 항목 삭제분은 따로 센다). ② 옮긴 덩어리마다 **첫 줄과 마지막 줄을 목적지 파일에서 `grep`으로 확인**한다. 둘 중 하나라도 어긋나면 커밋하지 않고 되돌린다.

**이관 대상이 셋을 넘거나 표준 구조 밖의 절이 있으면 `plan-slimmer`를 스폰해 맡긴다** — 계획서 절대경로만 전달한다. 반환의 `승인 필요` 칸이 채워져 있으면 그 내용을 사용자에게 그대로 묻고, 답을 받아 같은 에이전트에 이어 보낸다. 이관이 한두 건이면 직접 처리하는 편이 싸다.

> **Do:** 끝난 노드와 지난 회차의 서술을 원문 그대로 노드 파일로 옮기고, 표의 `산출` 칸으로 잇는다
> **Don't:** 옮기는 대신 요약해 줄이거나, 노드 표의 행·열린 후속 항목·전제 절을 함께 덜어낸다

## 용어 통일

계획서·노드 파일·보고에 쓰는 **도메인 낱말을 계획서 `## 용어` 절 한 곳에 고정한다.** 지휘는 포화 때마다 교체되고 작업 세션은 노드마다 새로 나므로, 여기 없는 낱말은 세션마다 새로 지어진다.

**등재하는 것은 셋뿐이다.**

- 같은 대상이 이미 두 이름으로 불린 낱말
- 사용자의 업무 용어·조어 — 코드나 일반 지식으로 유추되지 않는 것
- 코드 식별자와 한국어 호칭이 짝인 것

**등재하지 않는 것.** 일반 기술 용어, 이 스킬 계열의 기계 어휘(노드·묶음·창구·지휘와 그 상태값 — 원본은 `/dev-loop` `protocol.md`의 "상태 어휘"다), 계획서에 한 번만 나오는 낱말. **등재할 것이 없으면 절을 만들지 않는다.**

적는 시점은 "인수인계 상시 적립" 3번(결정이 오갈 때마다)에 붙인다. **계획 세션에서 미리 채우지 않는다** — 노드가 돌면서 실제로 충돌한 낱말만 쌓인다.

**사용자 낱말이 이긴다 — 묻지 않는다.** 사용자가 같은 대상을 다른 낱말로 부르면 그것을 표제어로 올리고 쓰던 것은 별칭 칸으로 내린 뒤 계속 진행한다. 승인을 받지 않는다 — 이름 붙일 권한이 사용자에게 있어 답이 정해진 질문이고, 무인 세션에서는 그 질문 하나가 사람 대기를 세워 루프를 멈춘다. 갈아탄 사실은 그 세션의 보고에 한 줄 남긴다.

**묻는 경우는 하나다** — 두 낱말이 같은 대상인지 가릴 근거가 계획서·노드 파일 어디에도 없을 때. 근거가 하나라도 있으면 그것으로 판정하고 묻지 않는다. 별개 개념 둘을 한 표제어로 합치면 계획이 틀어지고 되돌리기 비싸다. 이때만 "되묻기 처분"의 근거 없는 결정으로 다뤄 사람에게 올린다.

**바꾸는 것은 문장뿐이다.** 코드 식별자·파일명·브랜치명·노드 ID·이미 커밋된 노드 파일 본문은 따라 고치지 않는다 — 돌고 있는 워크트리와 브랜치가 어긋난다. 개명이 필요하면 후속 작업 항목으로 적는다.

> **Do:** 사용자 낱말로 표제어를 갈아끼우고 옛 이름을 별칭에 남긴 뒤 계속 진행한다
> **Don't:** 낱말을 바꿔도 되는지 묻거나, 바꾼 김에 코드 식별자·브랜치명까지 따라 고친다

## 후속·유보 작업

노드 실행 중 작업이 식별되면 DEV_PLAN의 전용 섹션에 성격별로 나눠 append한다.

- **후속 작업** — 해야 하지만 이번 계획서 범위 밖으로 미루는 작업. 계획 완료를 막지 않는다.
- **유보 작업** — 중요도가 낮고 현재 사용자 경험에 영향이 없으나 개선 여지가 있는 항목(코드 리뷰 minor 등급 상당).

노드 진행 자체는 노드 표에만 기록·갱신한다.

> **Do:** "해야 하는데 이번엔 안 함"은 후속, "안 해도 되지만 하면 나아짐"은 유보로 나눠 적는다
> **Don't:** 후속·유보를 한 목록에 섞거나 노드 표에 끼워 넣거나, 계획서 밖 파일에 기록한다

## 조사·연구 노드 판정

아래 중 하나라도 해당하면 코드 작성 전에 노드를 세운다.

- 학습 컷오프(2026-01) 이후 빠르게 바뀌는 외부 기술 의존 — 라이브러리·프레임워크 버전, LLM/AI API, 클라우드 서비스 기능, 최근 6개월 내 릴리스·변경된 도구 → **조사**
- 외부 시스템과의 계약(필드명·형식·응답 구조)에 구현이 의존 → **조사**, 실값 대조가 필요하면 **연구**
- 실측·시행 결과에 따라 구현 방향이 갈림 → **연구**
- 사용자가 조사를 명시 요청

**사용자만 닿는 미지수는 여기 해당하지 않는다** — 사람이 하는 화면 조작 절차·업무 관행·자격·물리 접근이 여기 든다. 계획 세션에서는 캐물어 닫고(`planning.md` "정보 출처 판정"), **계획 이후 새로 드러나면 주체=사용자 청취 노드를 세운다**(종류=연구·주체=사용자). 답을 받기 전에는 그 노드에 걸린 하류를 착수하지 않는다. 답은 회수 시점에 계획서 `## 조작 절차` 표에 올린다(절이 없으면 새로 만든다) — 하류가 읽는 계약은 그 표뿐이다. **사람만 아는 절차를 실측 노드로 내리지 않는다** — 회차를 태우고도 "확인하지 못했다"로 닫힌다.

해당 없으면(안정적 도메인·내부 로직·리팩토링·정착된 라이브러리) 생략한다. 단순 1줄 사실 조회는 노드로 세우지 않고 `general-purpose`(haiku)로 갈음한다.

> **Do:** 최신 기술·외부 계약은 노드로 세워 구현 앞에 놓는다
> **Don't:** 컷오프 이전 지식이나 문서상 기재만으로 외부 계약을 단정한다

## DEV_PLAN 표준 구조

**양식 전문은 `planning.md`가 갖는다.** 계획서를 새로 쓸 때만 필요하므로 여기서 되풀이하지 않는다. 노드 표의 칸·상태 어휘는 진행 중인 계획서 실물이 보여 준다.

**그 양식에 없는 절은 뒤 노드의 실행을 바꾸는 것만 만든다** — 사용자가 확정한 전제, 판정 기준처럼 다음 노드가 읽어야 할 것. **실행 기록을 담는 절(「노드 상세」·「진행」·「경과」 등)은 만들지 않는다**("반영·보고 선택 기준").
