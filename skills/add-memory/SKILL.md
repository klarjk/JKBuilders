스킬·에이전트 지시문에 오토 메모리 블록을 삽입하는 메타 스킬이다. 대상 파일을 한 번 개조해두면, 이후 해당 스킬·에이전트가 실행될 때마다 "탐색·시행착오 끝에 찾은 방법"이나 "다음번 유사 작업에서 바로 재사용할 시퀀스"를 스스로 누적 기록하게 된다.

## 왜 필요한가

Claude Code의 auto memory는 메인 에이전트와 일부 서브에이전트(`memory:` frontmatter 지정)에만 자동 적용된다. 스킬과 커스텀 에이전트는 자체적으로 메모리 블록을 지시문에 포함하지 않으면 매 실행이 **콜드 스타트**가 된다. 같은 API quirk를 매번 다시 발견하고, 같은 우회 경로를 매번 다시 탐색한다. 이 스킬은 그 누락된 레이어를 표준화된 방식으로 채운다.

## 동작 흐름

```
[1] 대상 파일 식별 및 타입 판정
  ↓
[2] 기존 메모리 블록 존재 여부 확인 → (있으면) 비교·안내
  ↓
[3] 지시문 본문에서 메모리로 이관할 후보 탐색 (첫 적용 시)
  ↓
[3-P] 패턴 학습 트랙 적합성 판정 (--pattern 또는 자동 추천)
  ↓
[4] 사용자 확인
  ↓
[5] 블록 삽입 + 저장 디렉토리 준비
  ↓
[6] 결과 보고
```

## 인자

```
/add-memory <대상 경로>              기본 — 메모리 블록만 삽입
/add-memory <대상 경로> --pattern    메모리 블록 + 패턴 학습 트랙 함께 삽입
/add-memory <대상 경로> --no-pattern 자동 추천도 끄고 메모리 블록만
```

`--pattern`은 명시 호출, `--no-pattern`은 명시 거절. 둘 다 없으면 3-P 단계의 자동 추천 결과에 따른다.

## 1단계: 대상 파일 식별 및 타입 판정

사용자가 경로를 명시했으면 그걸 사용한다. 명시하지 않았으면 "어떤 스킬/에이전트에 적용할까요?"라고 물어 결정한다.

경로 패턴으로 타입을 판정한다:

| 경로 패턴 | 타입 | 메모리 저장 경로 |
|---------|------|---------------|
| `**/skills/<name>/SKILL.md` | skill | `~/.claude/skill-memory/<name>/` |
| `**/agents/<name>.md` | agent | `~/.claude/agent-memory/<name>/` |

둘 다 해당하지 않으면 사용자에게 "이 파일은 스킬·에이전트로 판정되지 않습니다. 계속할까요?"라고 확인한다.

## 2단계: 기존 메모리 블록 확인

대상 파일에서 아래 **헤더 라인의 정확 일치**(줄 시작부터 끝까지, 공백·주변 텍스트 무시)로 블록 존재를 판정한다. 본문 중 일반 문장에 등장하는 "memory" 같은 단어는 마커로 취급하지 않는다.

| 판정 대상 | 매칭 패턴 (정규식) |
|----------|-----------------|
| skill 블록 헤더 | `^# Persistent Skill Memory\s*$` |
| agent 블록 헤더 | `^# Persistent Agent Memory\s*$` |
| 과거 버전 호환 | `^# Persistent Memory\s*$` |

보조 신호(블록 **내부 구조** 확인용, 블록 존재 판정 자체에는 사용하지 않음): 블록 헤더 이후 구간에 `~/.claude/(skill|agent)-memory/` 경로 언급, `MEMORY.md` 파일명 언급.

### "비어 있는" 판정

헤더 라인이 존재해도 아래 중 하나라도 해당하면 "비어 있는 블록"으로 간주하여 3단계 이관 탐색을 수행한다:

- 헤더 이후 본문 라인이 3줄 미만
- 저장 경로·MEMORY.md·저장 타이밍 중 어느 하나도 언급되지 않음
- TODO·placeholder (`{{...}}`, `<...>`) 만 남아 있고 실제 지시가 없음

### 블록이 있고 비어있지 않으면

기존 블록을 읽고 표준 템플릿(`references/memory-template-{skill,agent}.md`)과 아래 **5항목 체크리스트**로 비교한다:

| 항목 | 확인 방법 |
|------|---------|
| 저장 경로 | `~/.claude/(skill\|agent)-memory/<name>/` 문자열이 블록에 명시되어 있는가 |
| 저장 타이밍 | "결과 보고 직후" 또는 "반환 직전" 시점이 지정되어 있는가 |
| MEMORY.md 인덱스 구조 | 본문 저장 금지·한 줄 요약 규칙·200줄 제한 중 최소 1개 이상 언급 |
| 검증 의무 | "추천·실행 전 현재 상태 확인" 또는 동등 지시 존재 |
| 인용 표시 | `<!-- mem: (skill\|agent)-memory/<name>/... -->` 를 남기라는 지시 존재 |

각 항목에 대해 **누락/일치/확장**으로 분류한다.

- **누락** = 표준 템플릿에 있고 기존 블록에 없음 → 병합 후보
- **확장** = 기존 블록에만 있고 표준에 없음 → 보존 후보 (사용자가 의도적으로 추가한 것)

다음 3가지 구간을 나누어 **사용자에게 요약 보고** 후 작업 방향을 추천한다:

1. **구조적 차이**: 위 5항목 중 어떤 것이 누락·확장인가?
2. **누락된 지시**: 표준 템플릿에만 있는 항목 목록
3. **커스텀 확장**: 기존 블록에만 있는 항목 목록

추천 옵션:
- **스킵**: 5항목이 모두 일치·확장이면 "이미 메모리 기능이 있어 삽입을 스킵합니다" 보고
- **병합**: 누락 항목만 기존 블록에 추가 (확장은 보존)
- **교체**: 기존 블록을 표준 템플릿으로 완전 교체 (커스텀 확장은 "주의사항" 서브섹션으로 이동해 보존)

사용자가 명시적으로 선택한 다음에만 수정한다. 자동 교체 금지.

## 3단계: 이관 후보 탐색 (첫 적용 시만)

기존 메모리 블록이 없거나 비어 있는 경우, 지시문 본문을 훑어 **메모리로 이관하면 더 적절한 내용**이 있는지 살핀다.

### 설계 원칙: 완전 이관

**스킬 본문 = 뼈대, 메모리 = 경험 축적**. 스킬 본문에는 라우팅·저장·입력 파싱·오류 처리 등 "무엇을 어떤 순서로 하는가"의 구조만 남긴다. 사이트·API의 **특이 동작(quirk)**은 전부 메모리로 이관한다. 매 호출 시 본문 토큰이 감소하고, 관련 quirk만 lazy load된다.

- **Do:** 본문에는 "상품 목록 페이지로 이동 → 선택자로 데이터 추출 → 결과 저장"만 두고, "선택자 `.product-card`가 2026-04 이후 `.item-box`로 변경됐고 구 선택자는 SSR 응답에만 남음" 같은 세부는 메모리로 이관
- **Don't:** 본문에 특정 사이트 DOM 변경 이력이나 API 응답 예시를 박제

### 이관 후보 신호

아래 4개 카테고리에 해당하는 내용은 후보로 올린다. 애매한 경우 아래 Do/Don't로 판정한다.

- **Do:** "2026-04부터 API가 429 대신 403을 반환" 같은 **시점·버전·환경에 종속된 사실**은 후보로 올린다
- **Don't:** "입력 검증은 실행 전에 수행한다", "Edit로만 수정한다" 같은 **모든 호출에 공통 적용되는 규범적 Do/Don't**는 본문에 남기고 후보에서 제외한다
- **Don't:** 아직 재사용 가능성이 확인되지 않은 **한 번만 관찰된 현상**을 카테고리 1~4 매칭 없이 후보로 올리지 않는다

1. **사이트·API 특이 동작 전반**
   - HTML 구조·DOM 선택자·XPath·URL 패턴
   - 응답 포맷·필드 네이밍·인코딩 quirk (한글 깨짐, 날짜 포맷, 숫자 표기, 천단위 구분자)
   - 인증 흐름, 쿠키·세션 요구사항, CSRF 토큰 취급
   - 레이트 리밋·차단 임계값, 재시도 간격
   - 에러 코드·메시지 해석 (문서화되지 않은 코드 포함)
   - 페이지네이션 패턴, 무한 스크롤 트리거 조건

2. **우회 경로·워크어라운드**
   - 공식 기능이 막혀 있을 때의 대안 루트
   - 라이브러리 버그를 피하기 위한 특수 호출 순서
   - 버전·날짜가 박힌 일시적 대응

3. **환경·프로젝트 종속 분기**
   - "프로젝트 A에서는 B, 프로젝트 C에서는 D" 형태
   - 사용자 로컬 경로·계정·디렉토리 구조 의존 정보

4. **경험담 내러티브**
   - "이전에 X했을 때 Y가 발생해서 Z로 처리한다" 형태
   - Do/Don't 주의사항으로 박제된 개별 사례

### 본문에 남겨야 할 것

- 스킬·에이전트의 **실행 골격**: 어떤 입력을 받아 어떤 순서로 처리하고 어디에 저장하는가
- **라우팅 규칙**: 입력 유형별 분기, 인자 해석표
- **입력 파싱·저장 포맷**: 파일 경로 규칙, 출력 스키마
- **오류 처리 정책**: 어떤 실패가 중단 사유이고 어떤 실패가 재시도 사유인가
- 모든 사용자·모든 프로젝트에 **공통 적용되는 규범적 Do/Don't**

> 판정이 애매하면 이 질문으로 판가름: "이 지시가 다른 사용자/다른 사이트 버전에도 그대로 유효한가?" Yes면 본문, No면 메모리.

### 사용자 확인

발견한 후보를 **번호 매겨 목록으로 제시**하고, 각 항목에 대해 (a) 이관, (b) 본문 유지, (c) 삭제 중 선택받는다. 본문이 비어질 정도로 대폭 이관되는 경우에도 다음 골격은 반드시 유지한다: 단계 헤더(`## N단계: ...`), 입력 파싱 절, 라우팅 절, 결과 보고 절. quirk가 빠진 자리는 "상세는 메모리 참조" 한 줄로 대체한다.

## 3-P단계: 패턴 학습 트랙 적합성 판정

quirk 누적과는 별개로 "여러 시도 슬롯 중 어느 것부터 시도해야 빠르게 성공하는가"를 통계로 누적하는 트랙이 패턴 학습이다. 본문 우선순위를 갈아치우지 않고 재정렬만 한다. 적합한 스킬에만 추가하고, 적합하지 않으면 빈 카운트만 쌓이고 운영 비용만 늘어난다.

### 판정 기준

`--pattern` 명시 호출이면 무조건 추가. `--no-pattern`이면 무조건 스킵. 둘 다 없으면 아래 3가지를 모두 만족할 때만 사용자에게 추천한다:

1. **여러 시도 슬롯의 우선순위가 본문에 박혀 있다** — 자막 언어 우선순위, API 엔드포인트 폴백 체인, 인증 방식 시도 순서, 셀렉터 폴백 등
2. **외부 API·사이트가 슬롯별로 간헐적·환경별 차단·실패를 일으킨다** — 아래 (a)·(b) 중 **하나라도** 해당하면 신호 충족으로 판정한다.
   - (a) 대상 스킬의 메모리 디렉토리에 `quirk` 타입 파일이 1개 이상 존재
   - (b) 본문에 다음 키워드 중 하나가 명시적으로 등장: `429`, `Too Many Requests`, `block`, `차단`, `HTML 오류 페이지`, `Sorry`, `재시도`, `fallback`

   (a)·(b) 모두 부재면 신호 부족으로 판정한다.
3. **입력 메타에서 카테고리 라벨을 자동 도출할 수 있다** — 자유 텍스트 분류 불필요. 가능 슬롯이 4~8개 이내로 통제 가능해야 한다

이 신호를 본문·quirk 파일 목록에서 정적으로 탐지한다. 신호가 약하면 추천하지 않는다 (단순 단일 API 호출 + 단발 retry는 패턴 학습 부적합).

### 판정 결과

- **신호 충족**: "패턴 학습 트랙도 함께 추가할까요? (이 스킬은 [감지된 신호]를 가져 적합해 보입니다)" 사용자에게 묻고 yes일 때 5단계에 패턴 템플릿 함께 삽입
- **신호 부족**: 추천하지 않고 5단계로 진행 (메모리 블록만)
- **명시 거절** (`--no-pattern`): 신호와 무관하게 스킵

### 패턴 트랙 적용 시 사용자 입력

신호 충족·yes 응답을 받으면 다음 2가지를 사용자와 합의한다 (4단계 사용자 확인에 흡수):

1. **카테고리 슬롯 후보**: 본문·quirk를 분석해 슬롯 후보를 제시한다. 사용자가 슬롯 종류·enum 값을 확정한다
2. **본문 우선순위 hash**: 현재 본문에 박힌 우선순위 슬롯 집합을 정규화된 문자열로 직렬화한 뒤 SHA-256을 계산하고 앞 12자리 hex를 PATTERNS.md `priority_version` 필드에 기록한다. 정규화 규칙은 다음과 같다.
   - 슬롯을 본문에 등장한 순서대로 나열
   - 각 슬롯은 `<section>:<key>` 또는 본문이 정의한 단일 식별자 형식을 그대로 사용
   - 슬롯 사이를 ` | ` (공백·파이프·공백)로 구분
   - 예: yt-summary는 `automatic_captions:ko | automatic_captions:en-orig | automatic_captions:en | subtitles:ko | subtitles:en` → SHA-256 앞 12자리 = `b63a382ed7b5`

   이 슬롯 집합·순서가 바뀌면 hash가 달라지고, 0단계에서 `## active` 전체를 `## archive`로 자동 이동한다.

## 4단계: 사용자 확인

다음을 한 메시지로 요약해 최종 확인받는다:

1. 대상 파일 경로와 타입(skill/agent)
2. 삽입 위치(파일 끝)
3. 메모리 저장 경로
4. 2단계 판정 결과 (신규 삽입 / 병합 / 교체 / 스킵)
5. 3단계 이관 후보 처리 방향
6. 3-P단계 결과 (패턴 트랙 추가 여부, 추가 시 카테고리 슬롯·priority_version)

확인 후 5단계 진행.

## 5단계: 블록 삽입 + 디렉토리 준비

### 블록 본문

- **skill**: `references/memory-template-skill.md` 내용을 그대로 파일 끝에 append
- **agent**: `references/memory-template-agent.md` 내용을 그대로 파일 끝에 append
- **패턴 트랙 추가** (3-P 결과): skill 템플릿 뒤에 `references/memory-template-pattern.md` 내용을 이어 붙임. 단, 해당 템플릿은 일반 가이드 형태이므로 그대로 append하지 않고 다음 3개 섹션을 대상 스킬용으로 **구체화한 사본**을 작성해 append한다.
  - **본문 우선순위 hash**: `priority_version: <합의된 hash>` (3-P단계에서 산출)
  - **카테고리 슬롯**: 합의된 슬롯 enum 표 (예: `caption_ko: yes/no`, `caption_en: yes/no`)
  - **reason enum**: 대상 스킬의 quirk 파일 목록과 1:1 매핑되는 enum 표 (매핑 없는 케이스는 `unknown`)

  템플릿의 "적용 조건"·"Decay·Archive 정책" 등 일반 절차 섹션은 그대로 복사해도 되고, "상세 절차는 본문의 0단계·N-P단계·M단계에 통합되어 있다" 한 줄로 대체해도 된다 — yt-summary 적용 사례 참조.

  - **Do:** yt-summary처럼 본문 끝에 "패턴 학습 트랙" 섹션을 직접 작성, 슬롯·hash·enum을 명시값으로 박음
  - **Don't:** `memory-template-pattern.md` 원문을 그대로 append하여 `<slot1>=<value>` 같은 자리표시자가 그대로 노출

템플릿 내의 `{{SKILL_NAME}}` / `{{AGENT_NAME}}` 플레이스홀더 치환 소스는 다음 우선순위로 결정한다:

1. **경로 기반** (우선): `skills/<name>/SKILL.md` 또는 `agents/<name>.md`에서 추출한 `<name>` — 디렉토리·파일명을 그대로 사용
2. **frontmatter 폴백**: 경로에서 추출 불가한 경우(비표준 위치에 있는 파일), frontmatter의 `name` 필드 사용

경로 기반과 frontmatter `name`이 **불일치**하는 경우, 저장 디렉토리는 **경로 기반**을 사용하고 사용자에게 불일치 사실을 보고한다. 저장 경로와 frontmatter가 어긋나면 다음 실행 시 메모리를 찾지 못한다.

### 디렉토리 준비

```bash
mkdir -p ~/.claude/skill-memory/<name>      # skill일 때
mkdir -p ~/.claude/agent-memory/<name>      # agent일 때
```

빈 `MEMORY.md`를 생성한다. **헤더는 반드시 템플릿 포맷(`# <NAME> MEMORY`)을 따른다** — 헤더가 템플릿과 다르면 다음 실행 시 인덱스 매칭이 실패한다.

패턴 트랙이 추가된 경우, 같은 디렉토리에 빈 `PATTERNS.md`도 생성한다:

```markdown
priority_version: <합의된 hash>

## active

## archive
```

MEMORY.md 인덱스 마지막에 `- [패턴 학습 로그](PATTERNS.md) — 첫 시도 경로 결정용` 한 줄을 추가한다.

```markdown
# <SKILL_NAME 또는 AGENT_NAME> MEMORY

<!-- 메모리 파일이 추가되면 이 아래에 인덱스 라인이 생성됩니다 -->
```

### 이관 후보 반영

3단계에서 이관이 확정된 항목이 있으면, 아래 **타입 매핑 규칙**에 따라 타입을 결정하여 개별 메모리 파일을 생성하고 `MEMORY.md` 인덱스에 등록한다. 각 파일의 frontmatter는 템플릿의 형식을 따른다.

**타입 풀은 대상 파일 타입에 따라 다르다** (템플릿과 1:1 일치):

| 대상 | 가용 타입 |
|------|---------|
| skill | `pattern`, `quirk`, `reference` |
| agent | `user`, `feedback`, `project`, `reference` |

**매핑 규칙:**

| 이관 후보 성격 | skill 타입 | agent 타입 |
|------------|---------|---------|
| API·라이브러리·사이트 특이 동작 (quirk) | `quirk` | `feedback` (근거/재발 조건 포함) |
| 재사용 가능한 작업 시퀀스·레시피 | `pattern` | `feedback` |
| 외부 리소스·URL·대시보드 포인터 | `reference` | `reference` |
| 사용자 역할·선호 | (해당 없음 — 스킬 메모리는 user 타입 없음) | `user` |
| 프로젝트 진행·담당자·기한 | (해당 없음) | `project` |

skill 메모리로 이관되는 항목이 `user`/`project` 성격이라면 스킬 대신 관련 에이전트의 메모리로 보내거나, 프로젝트 CLAUDE.md로 올리는 것을 사용자에게 제안한다.

## 6단계: 결과 보고

다음 포맷으로 사용자에게 보고한다:

```
## add-memory 적용 완료

- **대상**: <파일 경로> (<skill|agent>)
- **삽입 블록**: <신규 / 병합 / 교체 / 스킵>
- **저장 경로**: <~/.claude/xxx-memory/<name>/>
- **이관된 항목**: (있으면 목록, 없으면 "없음")
- **다음 실행 시 동작**: 이 <스킬|에이전트>가 다음에 실행되면 완료 직전에 메모리 저장을 판단합니다.
```

## 주의사항

- **파일은 Edit로 수정한다**. Write로 덮어쓰면 의도치 않은 내용 손실이 발생할 수 있다.
- **중복 삽입 방지**: 2단계에서 기존 블록을 반드시 확인한다. 마커 체크 생략 금지.
- **템플릿 버전**: `references/memory-template-*.md`가 이 스킬의 정본 블록이다. 이 파일을 수정하면 이후 적용분에만 반영되며, 기존 적용분은 병합/교체 흐름에서 사용자 선택으로 업데이트된다.
- **저장 조건 완화의 의미**: 기본 에이전트 메모리는 "3회 이상 반복 가능성" 기준으로 저장했지만, 이 스킬이 삽입하는 템플릿은 **1회라도 탐색 비용이 컸던 패턴**을 저장하도록 완화했다. 목적은 "다음번 같은/비슷한 작업 시 바로 참조". 단, 제외 조건(CLAUDE.md에 이미 있음, 일회성 오타·버그, 코드로 파악 가능한 구조)은 유지한다.
