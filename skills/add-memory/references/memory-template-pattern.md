## 패턴 학습 트랙 (선택 적용)

이 트랙은 quirk 누적과는 **별개의 레이어**다. quirk가 "실패했을 때 어떻게 우회하는가"를 본문으로 담는다면, 패턴 학습은 "여러 시도 슬롯 중 어느 것부터 시도해야 빠르게 성공하는가"를 통계로 누적한다. 본문 우선순위를 갈아치우지 않고 **재정렬**만 한다.

### 적용 조건

이 트랙은 다음을 모두 만족할 때만 의미가 있다. 하나라도 빠지면 PATTERNS.md를 추가하지 말 것 — 빈 카운트만 쌓이고 운영 비용만 늘어난다.

- 본문에 **여러 시도 슬롯의 우선순위**가 박혀 있다 (예: ko→en-orig→en 같은 순서)
- 외부 API·사이트가 슬롯별로 **간헐적 또는 환경별 차단·실패**를 일으킨다
- 입력 메타데이터에서 **카테고리 라벨**을 자동 도출할 수 있다 (자유 텍스트 라벨 금지)

### 저장 구조

같은 디렉토리에 단일 파일 `PATTERNS.md`를 둔다. quirk 인덱스인 `MEMORY.md`와 평행 배치하되, MEMORY.md 인덱스에는 `- [패턴 학습 로그](PATTERNS.md) — 첫 시도 경로 결정용` 한 줄만 추가한다.

```
priority_version: <본문 우선순위 hash>

## active
YYYY-MM-DD | <slot1>=<value> | <slot2>=<value> | first_try=<slot>:<result> | success=<slot>

## archive
(90일 초과 또는 priority_version 변경분, 가중 0.3)
```

### 카테고리 라벨 슬롯

라벨은 **고정 슬롯의 enum 값**이다. 자유 텍스트 금지. 슬롯은 다음 기준으로 선정한다:

- **결정적 변별력**: 슬롯 값이 바뀌면 성공 슬롯도 실제로 바뀐다는 가설이 본문 또는 누적된 quirk 파일에 정성적 근거로 진술 가능한가 (도입 시점에는 통계가 없으므로 사전 가설로 충분). 도입 후 90일 시점에 active 라인을 슬롯 값별로 그룹화해 success 분포가 실제로 다른지 검증한다.
- **메타에서 자동 추출 가능**: 사용자 판단·자유 텍스트 분류 불필요
- **카디널리티 통제**: 모든 슬롯의 가능한 조합이 카테고리 총수. 호출 빈도 대비 카테고리당 카운트가 임계치 도달 가능한 수준이어야 한다 (대략 4~8개 이내 권장)

휴리스틱 슬롯(예: 채널명에 한글 포함 여부, 시간 버킷)은 변별력 근거가 약하면 빼라. 슬롯이 적을수록 학습이 빠르다.

### 시도 결과 표기

- `first_try`: **메타에 존재하는 후보 중 본문 우선순위가 첫 번째로 시도한 슬롯**과 그 결과. 메타에 슬롯이 아예 없어 강제 스킵된 경우는 first_try에 기록하지 않음 (자기상관 가짜 신호 방지)
- `result`: `success` 또는 `fail:<reason>`
- `reason`: quirk 파일명과 1:1 매핑되는 enum. 자유 텍스트 금지. 매핑 불가하면 `unknown`
- `success`: 최종 성공 슬롯. 모든 슬롯 실패 시 `none`

### 승격 임계치

같은 카테고리 라벨 안에서, 슬롯별로 active 라인은 가중 1.0, archive 라인은 가중 0.3으로 (성공 - 실패) 합산한다. 합산값이 ≥ 2인 슬롯이 있으면 다음 실행 시 그 슬롯을 본문 우선순위 맨 앞으로 끌어올린다. 합산값이 ≥ 2인 슬롯이 **2개 이상이면** 합산값이 가장 큰 슬롯을 우선 채택하고, 합산값마저 동률이면 본문 원래 우선순위가 더 앞에 있는 슬롯을 채택한다. 추천 슬롯 시도가 실패하면 본문 나머지를 원래 순서대로 순회한다.

### Decay·Archive 정책

- 단일 정책: 90일 초과 라인은 `## archive` 섹션으로 이동, 가중치 0.3으로 합산
- 30/60일 가중치는 두지 않는다 — 호출 빈도가 낮은 환경에서는 장식 비용
- `priority_version`이 본문 우선순위 변경으로 바뀌면 `## active` 전체를 `## archive`로 일괄 이동

### 카운트 제외 규칙

다음은 PATTERNS.md에 append하지 않는다 (통계 오염 방지):

- 사용자가 슬롯을 명시 지시한 실행 (예: "한국어 자막으로 시도해봐")
- 메타 추출 자체가 실패한 입력 (카테고리 라벨 생성 불가)
- 다음 두 조건을 모두 만족하는 단발 quirk 우회는 PATTERNS.md에 append하지 않는다 (해당 quirk 파일에서 따로 추적). 두 조건은 **본문 또는 quirk 파일 frontmatter/본문에 명시 진술이 있어야** 적용된다 — 명시 진술이 없으면 본 제외 규칙은 적용하지 않고 정상 append 한다 (디폴트 = append).
  - (1) 시도 슬롯과 무관하게 같은 quirk 적용이 모든 슬롯에 동일하게 작용한다고 명시
  - (2) 그 quirk를 적용하지 않으면 어떤 슬롯도 성공하지 않는다고 명시

  판정은 단위 작업별 append 직전 메인 에이전트가 수행하며, 적용 시 어느 quirk 파일의 어느 라인을 근거로 했는지 사용자 보고에 1줄 포함한다.

  - **Do:** quirk 파일 본문에 "이 우회는 슬롯 무관 공통 적용"·"미적용 시 전 슬롯 실패" 두 진술이 모두 있을 때만 제외
  - **Don't:** 메인 에이전트 추론으로 두 조건이 "성립할 것 같다"고 판정해 제외 — 명시 부재 시 무조건 append

### 다음 실행 시 사용 절차

1. PATTERNS.md를 Read. `priority_version` 검증 (현재 본문 우선순위 hash와 일치)
2. 입력 메타에서 카테고리 라벨 생성
3. 같은 라벨 라인을 grep, success 슬롯별 (성공 - 실패) 합산 (active 1.0, archive 0.3)
4. 임계치 ≥ 2인 슬롯이 있으면 본문 우선순위 맨 앞으로 재정렬, 없으면 본문 그대로
5. 시도 실행
6. 결과 보고 후 **단위 작업별로 1줄 append** (제외 규칙 적용). "단위 작업"의 정의는 적용 스킬이 결정한다 — yt-summary는 영상 1개, API 폴백 스킬은 호출 1건, 셀렉터 폴백 스킬은 페이지 1개 등.
7. 90일 초과 라인을 archive 섹션으로 이동

### 본문과의 결합

본문 우선순위 자체와 quirk 적용 코드(헤더·재시도 등)는 본문이 그대로 책임진다. PATTERNS는 **첫 시도 슬롯만 결정**하고, 그 슬롯의 실행 코드는 본문이 정의한 흐름을 따른다.
