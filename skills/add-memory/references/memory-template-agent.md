# Persistent Agent Memory

이 에이전트는 호출된 작업을 마치기 직전, **메모리 저장 여부를 판단**하고 해당 스폰에서 얻은 재사용 가능한 패턴을 `~/.claude/agent-memory/{{AGENT_NAME}}/` 하위에 누적 기록한다. 목적은 다음번 이 에이전트가 같은·비슷한 상황으로 스폰되었을 때 **다시 탐색하지 않고 바로 실행**하는 것이다.

## 저장 타이밍

이 에이전트의 모든 단계가 끝나고, 호출자에게 결과를 반환하기 **직전** 한 번만 판단한다. 긴 작업 중간에는 저장하지 않는다.

## 메모리 타입 (4가지)

<type>

    <when_to_save>사용자의 역할, 전문성, 선호, 책임 범위에 대한 정보가 드러날 때.</when_to_save>
</type>
<type>
    <name>feedback</name>
    <description>사용자가 이 에이전트의 접근법을 교정하거나 승인한 내용. 다음번 같은 상황에서 같은 안내를 받지 않도록.</description>
    <when_to_save>사용자가 "그게 아니라", "그렇게 하지 마", "그 방식이 맞았어" 같은 신호를 주었을 때. 교정뿐 아니라 **비자명한 접근이 통과된 경우**도 저장. 본문은 규칙 + **Why:** + **How to apply:** 구조로 작성.</when_to_save>

<type>

    <when_to_save>사용자·작업 맥락에서 외부 리소스 경로가 드러날 때.</when_to_save>

## 저장 조건 (완화판)

기본 에이전트 메모리는 "3회 이상 반복 가능성이 있는 패턴"을 기준으로 하지만, 이 에이전트는 **완화된 기준**을 적용한다:

- **탐색·시행착오 끝에 도달한 방법**은 아래 **중 하나라도 해당**하면 "자원 소모가 컸다"로 판정하여 저장한다:
  - 서로 다른 방법을 **3회 이상** 시도한 뒤 성공
  - 조사·구현에 **10분 이상** 소요 (체감 기준, 여러 도구 호출 누적)
  - **2개 이상의 외부 문서·페이지·응답**을 비교해야 해법이 나옴
  - 공식 문서에 **없는 동작**을 실험으로 확인해야 했음
- **다음번 같은·비슷한 작업에서 바로 참조할 수 있는 시퀀스**는 저장한다.
- **API·라이브러리의 quirks**(간헐 오류, 중복 방지 필요 등)는 저장한다.
- **코드로 파악 불가한 설계 의도·구조적 이유**는 저장한다.

## 저장 제외 (아래는 저장하지 않는다)

- CLAUDE.md·루트 규칙 파일에 이미 문서화된 내용
- 일회성 오타·임시 상태·해결된 당일 버그
- 코드를 읽으면 바로 파악되는 구조·파일 경로·호출 관계
- 민감 정보(계정·비밀번호·토큰 평문)

## 저장 구조

저장 디렉토리: `~/.claude/agent-memory/{{AGENT_NAME}}/`

```
~/.claude/agent-memory/{{AGENT_NAME}}/
  MEMORY.md                           # 인덱스. 다음 스폰 시 항상 먼저 읽음
  <topic-slug>.md                     # 개별 메모리 파일
  ...
```

### MEMORY.md 포맷 (인덱스만)

```markdown
# {{AGENT_NAME}} MEMORY

- [제목](slug.md) — 한 줄 요약
```

200줄 제한. 본문을 여기 직접 쓰지 않는다.

### 개별 메모리 파일 포맷

```markdown
---
name: {{메모리 제목}}
description: {{한 줄 설명 — 다음번 관련성 판정 기준}}
type: {{user | feedback | project | reference}}
date: YYYY-MM-DD
---

{{본문}}

**Why:** {{이 규칙·사실이 나온 원인}}
**How to apply:** {{언제·어디서 이 메모리를 꺼내 써야 하는지}}
```

feedback·project 타입은 **Why** / **How to apply** 두 줄을 필수로 유지한다. 이유가 빠지면 엣지 케이스에서 판단하지 못한다.

## 다음 스폰 시 사용 방법

이 에이전트가 다시 스폰되면 **작업 시작 전에 `~/.claude/agent-memory/{{AGENT_NAME}}/MEMORY.md`를 Read**한다. 아래 **관련성 판정 기준** 중 **하나라도 충족**하는 인덱스 항목의 개별 파일을 Read하여 컨텍스트에 올린다.

**관련성 판정 기준:**

1. **대상 식별자 일치**: 호출 프롬프트·입력 파라미터에 포함된 파일 경로·도메인·프로젝트명·함수명이 인덱스 항목의 제목 또는 description에 **부분 문자열로 포함**
2. **작업 유형 일치**: 현재 스폰의 역할(예: "코드 리뷰", "테스트 실행", "보안 점검")이 인덱스 항목의 description에 명시된 유형과 일치
3. **사용자·프로젝트 맥락 일치**: 호출자가 언급한 사용자·팀·프로젝트가 `user`/`project` 타입 메모리의 대상과 동일

한 번에 3개 이상 항목이 매칭되면 **상위 3개만** 로드한다 (description 기준 정확도 순). feedback 타입은 **매 스폰마다 전수 로드**한다 — 과거 교정 지시는 항상 유효한 것으로 간주.

**검증 의무**: 메모리에 기록된 파일 경로·함수명·플래그는 "그때 존재했다"는 주장일 뿐이다. 추천·실행 전에 현재 상태를 확인한다. 메모리와 현재 상태가 충돌하면 현재 상태를 따르고, 해당 메모리는 업데이트 또는 삭제한다.

**인용 표시**: 로드한 메모리를 이번 실행에 실제로 적용했으면 호출자에게 보내는 보고문에 `<!-- mem: agent-memory/{{AGENT_NAME}}/<파일명>.md -->` 한 줄을 남긴다. 보고문당 최대 3개, 같은 파일 중복 금지.

> **Do:** 메모리 본문(우회 경로·과거 교정·담당자 정보 등)이 이번 응답의 판단·문구에 실제로 반영됐을 때 그 파일을 표시한다
> **Don't:** 인덱스만 읽고 본문을 안 썼거나, 읽었으나 현재 상태와 달라 무시한 파일을 표시한다

**사용자가 "메모리 무시"를 지시한 경우**: MEMORY.md를 빈 파일처럼 간주한다. 기록된 내용을 적용·인용하지 않는다.

## 저장 절차

저장이 필요하다고 판단되면:

1. 기존 `MEMORY.md`를 Read하여 중복 후보 확인
2. 유사 항목이 있으면 기존 파일 업데이트, 없으면 새 파일 생성
3. `MEMORY.md` 인덱스에 한 줄 추가 (중복 없이)
4. 호출자에게 반환 메시지에 한 줄로 포함: "메모리에 `<제목>` 저장됨"

저장이 불필요하면 알림 없이 종료.
