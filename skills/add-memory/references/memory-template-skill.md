# Persistent Skill Memory

이 스킬은 실행을 마치기 직전, **메모리 저장 여부를 판단**하고 해당 세션에서 얻은 재사용 가능한 패턴을 `~/.claude/skill-memory/{{SKILL_NAME}}/` 하위에 누적 기록한다. 목적은 다음번 이 스킬이 같은·비슷한 상황을 만났을 때 **다시 탐색하지 않고 바로 실행**하는 것이다.

## 저장 타이밍

이 스킬의 모든 단계가 끝나고, 사용자에게 결과 보고를 마친 **직후** 한 번만 판단한다.

## 저장 대상 (아래 중 하나라도 해당하면 저장 후보)

- **탐색·시행착오 끝에 도달한 방법**: 처음엔 여러 경로를 시도했으나 결국 특정 방식이 유일하게 동작했을 때. 반복 횟수는 불문 — 아래 **중 하나라도 해당**하면 "자원 소모가 컸다"로 판정하여 저장한다:
  - 서로 다른 방법을 **3회 이상** 시도한 뒤 성공
  - 조사·구현에 **10분 이상** 소요 (체감 기준, 여러 도구 호출 누적)
  - **2개 이상의 외부 문서·페이지·응답**을 비교해야 해법이 나옴
  - 공식 문서에 **없는 동작**을 실험으로 확인해야 했음
- **다음번 유사 작업 시 바로 재사용 가능한 시퀀스**: 명령어 조합, API 호출 순서, 우회 경로, 특정 입력에 대한 검증된 파라미터.
- **API·라이브러리·외부 시스템의 quirks**: 문서에 없는 실제 동작, 간헐적 실패 조건, 중복 방지 필요 사유.
- **코드·문서만으로는 알 수 없는 설계 의도**: 왜 이렇게 처리했는지의 맥락.
- **프로젝트·환경 특이 설정**: 이 스킬이 특정 프로젝트에서 반복 호출될 때 매번 달라지는 조건(경로, 자격 증명 위치, 빌드 명령 등).

## 저장 제외 (아래는 저장하지 않는다)

- 프로젝트 CLAUDE.md·루트 규칙 파일에 이미 문서화된 내용
- 이 스킬의 SKILL.md 본문만 읽으면 파악되는 구조·단계
- 일회성 오타·임시 상태·해결된 당일 버그
- 민감 정보(계정·비밀번호·토큰 평문)

## 저장 구조

저장 디렉토리: `~/.claude/skill-memory/{{SKILL_NAME}}/`

```
~/.claude/skill-memory/{{SKILL_NAME}}/
  MEMORY.md                           # 인덱스. 다음 실행 시 항상 먼저 읽음
  <topic-slug>.md                     # 개별 메모리 파일
  ...
```

### MEMORY.md 포맷 (인덱스만)

```markdown
# {{SKILL_NAME}} MEMORY

- [제목](slug.md) — 한 줄 요약
```

200줄 제한. 각 줄 150자 이내. 내용 본문을 여기 직접 쓰지 않는다.

### 개별 메모리 파일 포맷

```markdown
---
name: {{메모리 제목}}
description: {{한 줄 설명 — 다음번 관련성 판정 기준}}
type: {{pattern | quirk | reference}}
date: YYYY-MM-DD
---

{{본문}}

**Why:** {{이 패턴·우회가 필요했던 원인}}
**How to apply:** {{언제·어디서 이 메모리를 꺼내 써야 하는지}}
```

타입 구분:
- **pattern**: 재사용 가능한 작업 시퀀스·레시피
- **quirk**: API·라이브러리·외부 시스템의 특이 동작
- **reference**: 외부 리소스·경로·대시보드 포인터

## 다음 실행 시 사용 방법

이 스킬이 다시 호출되면, **1단계 시작 전에 `~/.claude/skill-memory/{{SKILL_NAME}}/MEMORY.md`를 Read**한다. 아래 **관련성 판정 기준** 중 **하나라도 충족**하는 인덱스 항목의 개별 파일을 Read하여 컨텍스트에 올린다. 충족 항목이 없으면 인덱스만 읽고 진행한다.

**관련성 판정 기준:**

1. **대상 식별자 일치**: 현재 입력에 포함된 도메인·URL·API 이름·티커·파일 경로가 인덱스 항목의 제목 또는 description에 **부분 문자열로 포함**
2. **작업 유형 일치**: 현재 스킬 호출의 파라미터 유형(예: "ETF 티커 조회", "특정 사이트 스크래핑")이 인덱스 항목의 description에 명시된 유형과 일치
3. **타입 + 맥락 일치**: 현재 작업이 quirk 회피가 필요한 단계(예: 응답 파싱·선택자 사용)이고 해당 타입(`quirk`) 항목이 같은 대상을 가리킴

한 번에 3개 이상 항목이 매칭되면 **상위 3개만** 로드한다 (description 기준 정확도 순).

**검증 의무**: 메모리에 기록된 파일 경로·함수명·URL은 "그때 존재했다"는 주장일 뿐이다. 추천·실행 전에 실제로 존재하는지 확인한다. 기록과 현재 상태가 충돌하면 현재 상태를 따르고, 해당 메모리는 업데이트 또는 삭제한다.

**인용 표시**: 로드한 메모리를 이번 실행에 실제로 적용했으면 최종 응답에 `<!-- mem: skill-memory/{{SKILL_NAME}}/<파일명>.md -->` 한 줄을 남긴다. 응답당 최대 3개, 같은 파일 중복 금지.

> **Do:** 메모리의 우회 경로·파라미터를 실제로 써서 단계를 건너뛰었을 때 그 파일을 표시한다
> **Don't:** 인덱스만 읽고 본문을 안 썼거나, 읽었으나 현재 상태와 달라 무시한 파일을 표시한다

## 저장 절차

저장이 필요하다고 판단되면:

1. 기존 `MEMORY.md`를 Read하여 중복 후보 확인
2. 유사 항목이 있으면 기존 파일을 업데이트, 없으면 새 파일 생성
3. `MEMORY.md` 인덱스에 한 줄 추가 (중복 없이)
4. 사용자에게 한 줄로 알림: "메모리에 `<제목>` 저장됨"

저장이 불필요하면 알림 없이 종료.
