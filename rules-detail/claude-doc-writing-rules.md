# 클로드 대상 문서 작성 규칙

## 적용 대상

Claude 자신이 읽고 따라야 하는 문서를 작성·수정할 때 적용한다:
- `CLAUDE.md` (프로젝트별, 루트)
- `agents/` 에이전트 정의 파일
- `skills/` 스킬 정의 파일
- `rules/` 전역 규칙 파일
- `.claude/` 하위 설정·지시 파일

일반 마크다운 노트, 세션 기록, 사용자용 문서에는 적용하지 않는다.

## Cardinal Rule - Simplicity First

지시문이 길어질수록 턴당 비용이 폭증한다. 반드시 핵심만 간결하게 서술한다.
개별 문장도 의미가 전달되는 선에서 최대한 압축한다.

다음 경우에 한해 아래 패턴 중 하나를 적용하여 지시의 범위를 좁히고 의미를 명확히 한다.

1. 결과가 사용자에게 피해를 줄 수 있는 지시.
2. 일반적인 LLM이 오해할 가능성이 **높은** 문구 (대부분 의도대로 동작할 만하면 적용 금지).
3. 사용자가 오동작을 지적한 후 지시문을 추가, 수정하는 경우.

### 1. Do & Don't 대조 패턴

지시 문구가 추상적이거나 다르게 해석될 여지가 있을 때, **해야 할 일과 하지 말아야 할 일을 나란히 배치**하여 행동 범위를 좁힌다.

**예시:**
- **지시문:** "요청 외 인접 코드는 손대지 않는다"
- 블록 추가:
>**Do:** 요청받은 함수만 수정, 그 위아래 함수의 스타일·주석·import는 그대로 둔다
>**Don't:** 같은 파일 안의 다른 함수를 리팩터링하거나 import 순서를 정리한다

### 2. 수치 기준 명시

"적당히", "간결하게", "필요하면" 같은 모호한 표현 대신 **측정 가능한 기준**을 넣는다.

**예시:** "최종 응답은 100단어 이내", "도구 호출 사이 텍스트는 25단어 이내"

### 3. 금지와 대안을 세트로 제공

금지만 명시하지 말고 **대신 해야 할 행동**을 함께 적는다.

**예시:** "결과를 조작하지 마라 → 대신 현재 상태를 보고해라"

## 일반 원칙

- 기존 지시문을 수정·추가할 때 형식·문체를 맞춘다.
- 지시문에 이유·배경·변경 이력을 함께 적지 않는다.
- 규칙은 범용적이어야 한다. 추가 시점의 특정 상황 문구를 적지 않는다.

## frontmatter description 작성 규칙 (스킬·에이전트)

스킬(`skills/**/SKILL.md`)·에이전트(`agents/*.md`) frontmatter의 `description` 필드는 **핵심 기능 1줄 설명 + 트리거 관련 사항(언제 사용·발화 패턴·인접 분기 안내)** 만 적는다. 그 외 정보는 **본문**에 기록한다.

**구성 요소:**
- 핵심 기능 1줄 ("X를 Y하는 스킬/에이전트")
- 트리거 키워드 4~8개 (사용자가 실제로 쓸 법한 발화 패턴, `/<커맨드>`·자연어 표현 혼합)
- 인접 스킬·에이전트와의 분기 안내 1줄(괄호 안에 짧게)

**예시:**
* "설치된 Claude 스킬·커맨드 전체를 체크리스트 + AI 전체 판단으로 정기 감사하는 스킬. 사용자가 /skill-stocktake, \"스킬 감사\", \"스킬 점검해줘\", \"스킬 정리해줘\" 등 의도를 표현하면 이 스킬을 사용한다. (공통 패턴 룰 승격은 /rules-distill, 단일 문장 감사는 prompt-reviewer)"

## 문서화 범위 구분 

- **문서화할 것:** 단일 파일만 읽어서는 알 수 없는 설계 의도, 파일 간 관계, 주의사항
- **문서화하지 말 것:** 해당 파일 하나만 열면 바로 파악되는 내용 (기본 역할, 함수 시그니처, import 구조 등)
