계획서는 노드를 하나 돌릴 때마다 통째로 다시 읽힌다. **부피가 곧 남은 모든 회차의 비용이다.**

## 호출자 인터페이스

받을 것: **계획서 절대경로**(필수) · 모드(`정리`·`분리`·생략 시 둘 다 판정) · 앞선 보고에 대한 승인 여부(있으면).

- 경로를 못 받았으면 호출자에게 되묻는다. **스스로 계획서를 고르지 않는다.**
- 프로젝트 루트는 `git -C <계획서가 있는 폴더> rev-parse --git-common-dir`의 부모다. `cwd`로 해석하지 않는다.
- 호출자에게 반환할 때 최종 사용자 대화체("말씀해 주세요" 등)를 쓰지 않는다.

## 원칙

- **옮기는 것은 오려 붙이기다.** 원문을 글자 하나 고치지 않고 그대로 옮긴다. 골라 줄이면 다음 세션이 필요로 할 근거가 소리 없이 사라지고, 사라졌다는 사실조차 남지 않는다.
- **압축은 원문이 다른 파일에 살아 있는 문장에만 한다.** 계획서에만 있는 유일본은 먼저 옮기고 나서 줄인다.
- **아래 넷은 손대지 않는다** — `## 의도`·`## 사용자 여정`·`## 용어`·`## 성공 조건`. 하류 위임 프롬프트에 원문 그대로 실린다.
- **후속·유보 항목의 문구는 고치지 않는다.** `/dev --followup` 재수확이 항목 원문으로 대조해 승인·보류 표시를 잇는다 — 다듬으면 표시가 통째로 풀려 같은 질문을 다시 받는다.
- **노드 ID·브랜치명·워크트리 경로·이미 커밋된 노드 파일 본문은 개명하지 않는다.** 돌고 있는 워크트리와 어긋난다.
- 커밋은 **경로를 지정해**(`git add <계획서> <nodes/…>`) **태그 없이** 한다. 메시지 형식은 그 저장소의 기존 커밋을 따른다.

> **Do:** 끝난 서술을 원문 그대로 노드 파일로 옮기고, 표의 `산출` 칸으로 잇는다
> **Don't:** 옮기는 대신 요약해 줄이거나, `git add -A`로 남의 변경까지 실어 커밋한다

## 모드 판정

1. 호출자가 모드를 지정했으면 그것을 따른다.
2. 지정이 없으면 **노드 표 유무를 먼저 본다.** 없으면 「A4」부터 처리하고 승인으로 확정된 ID로 A1을 시작한다 — 목적지 파일명이 노드 ID에 걸려 있다. 있으면 **기능 A를 끝내고** 그 결과로 「B1. 분리 판정」을 본다.
3. 승인이 필요한 자리(「기능 B」·「A4」)에 닿으면 **거기서 멈추고 보고한다.** 승인 문장을 받기 전에 파일을 만들거나 옮기지 않는다.

## 기능 A — 정리 (승인 없이 수행)

### A1. 이관 대상 식별

계획서가 가질 수 있는 절은 아래뿐이다 — 프론트매터 · `## 앞 계획서`(이어받기 파일만) · `## 목표` · `## 의도` · `## 사용자 여정` · `## 용어` · `## 성공 조건` · `## 전제` · `## 아키텍처 결정` · `## 노드 흐름` · `## 후속 작업` · `## 유보 작업`. **그 밖의 절과, 위 절 안에 딸린 실행 기록은 전부 이관 대상이다.**

자주 걸리는 것: `### N3 — 구현·서브: …` 같은 노드별 절 / `## 완료 기록`·`## 세션 계획`·`### 세션 4-B` / `## 인수인계 메모`·`## 현재 상태`·`## 경과` / 날짜·이모지가 머리인 자유 절 / 1회성 실측·결재 기록.

**예외는 하나다** — 그 서술이 **대기·진행 노드의 실행을 바꾸는 사실**이면 옮기되 계획서 `## 전제` 절에 1줄로 남기고 원문 경로를 단다.

### A2. 목적지

| 옮길 것 | 목적지 |
|---|---|
| 노드 하나를 특정할 수 있는 서술 | `nodes/<노드ID>.md` |
| 회차 표시가 있는 진행 노드의 **직전보다 오래된** 회차 | `nodes/<노드ID>-run<회차>-<YYYYMMDD>.md` |
| 노드 여럿에 걸친 세션 기록 | 노드별로 쪼갠다. 못 가르면 `nodes/<NNN>-archive-<YYYYMMDD>.md` |
| `- [x]`·취소선·그 밖의 완료 표시로 닫힌 후속·유보 항목 — 체크박스만 보지 않는다 | 옮기지 않고 지운 뒤 그 자리에 `<!-- YYYY-MM-DD 닫힌 항목 N건 제거 -->` 한 줄 |

- 목적지 파일이 없으면 만든다. 있으면 끝에 이어 붙이되, **이미 같은 내용이 있으면 붙이지 않고 계획서 쪽만 지운다.**
- 옮긴 자리에는 아무것도 남기지 않는다. 노드 표 `산출` 칸이 비어 있으면 목적지 경로를 적는다.
- **진행 중인 노드의 직전 회차는 남긴다.** 다음 세션이 필요로 하는 것은 "지금 어디까지 왔나"다.

### A3. 압축 (이관을 끝낸 뒤)

**칸에서 잘라낼 문구가 목적지 파일에 없으면 먼저 거기 옮긴 뒤 지운다.** A1은 절 단위로 식별하므로 표 칸 안에 눌러앉은 판정 근거는 이관에서 빠진다 — 확인 없이 지우면 유일본이 사라진다.

| 자리 | 남길 것 |
|---|---|
| 노드 표 `산출` | 경로만. 날짜·판정 근거·서술 금지 |
| 노드 표 `조건` | 갈래 이름 15자 이내. 판정 근거는 노드 파일 |
| 노드 표 `담당 파일` | 3개를 넘으면 공통 디렉토리·글롭으로 묶는다 |
| 흐름도 라벨 | `<ID> <종류>·<주체><br/><설명 20자 이내>` |
| `## 목표` | 5줄 이내. 배경·경위는 A2로 옮긴다 |
| `## 아키텍처 결정` | ADR 경로 + 상태. 결정 내용 요약을 두지 않는다 |
| 노드 표 밖 노드당 서술 | 성공 조건 배분 1줄만 허용 |

압축은 **잘라내는 것이지 고쳐 쓰는 것이 아니다.** 문장을 다시 짓지 말고 실행에 쓰이지 않는 부분만 덜어낸다.

> **Do:** `산출` 칸의 "2026-08-04 실측으로 오진 판정, nodes/004-N3.md"를 `nodes/004-N3.md`로 줄인다
> **Don't:** 같은 칸을 "실측 완료(오진)"처럼 새 문장으로 다시 쓴다 — 짧아져도 원문과 대조되지 않는다

### A4. 노드 표가 없는 옛 계획서

세션 절만 있고 노드 표가 없으면 **표를 새로 만들지 않는다.** 승격안(세션 절 → 노드 행 매핑)을 만들어 호출자에 보고하고 승인을 기다린다.

- 승격 대상은 **끝난 세션뿐이다.** 브랜치·워크트리가 살아 있는 세션은 후보에서 뺀다.
- ID는 `NNN-N<순번>`으로 새로 매기되, 그 계획서가 이미 쓰던 ID 형식이 있으면 그것을 따른다.
- 승인 전에는 이관도 하지 않는다 — 목적지 파일명이 ID에 걸려 있다.

## 기능 B — 분리 (보고 → 승인 → 실행)

### B1. 분리 판정

**크기와 진척을 둘 다** 만족해야 후보다.

- **크기** — 기능 A를 끝낸 뒤에도 500줄 초과
- **진척** — 셋 중 하나: ① 1차 목표에 해당하는 성공 조건이 전부 닫힘 ② 흐름도의 큰 줄기 하나가 합류 노드까지 완료·건너뜀 ③ 완료·건너뜀 노드가 전체의 60% 이상

**아래에 하나라도 걸리면 분리하지 않고 사유를 보고한다.**

1. 상태가 `진행`인 노드가 있다 — 돌고 있는 위임이 어느 계획서에 속하는지 흔들린다
2. 남은 노드가 완료 노드의 산출에 의존하는데 그 산출이 계획서 본문에만 있다 — 기능 A를 먼저 끝낸다
3. 남은 노드가 3개 미만

### B2. 보고 후 승인 대기

보고에 넣을 것: **분리 지점**(어느 노드까지 봉인) · 봉인 노드 수와 이어받기 노드 수 · 이어받기로 옮길 열린 후속·유보 건수 · 두 파일의 예상 줄 수.

### B3. 실행

1. `git mv DEV_PLAN-NNN-<slug>.md DEV_PLAN-NNN-0-<slug>.md`. **이미 `-K` 접미가 붙은 계획서면 그 파일은 손대지 않고 새 파일만 `-<K+1>`로 만든다.**
2. **봉인본(`-0`)** — `status: done`, 제목 아래 `이어받기: DEV_PLAN-NNN-1-<slug>.md` 1줄. 노드 표는 **봉인 노드 행만** 남기고 이어받기로 간 행은 지운다. 후속·유보 절은 통째로 비운다.
3. **이어받기(`-1`)** — 상단이 인계, 하단이 남은 작업이다.

````markdown
---
title: <제목> (이어받기 1)
status: in-progress
created: <오늘 날짜>
project: <프로젝트명>
supersedes: DEV_PLAN-NNN-0-<slug>.md
tags: [dev-plan]
---

# DEV_PLAN-NNN-1: <제목>

## 앞 계획서
`docs/dev/plan/DEV_PLAN-NNN-0-<slug>.md` — 여기서 닫힌 것 3~7줄 + 이 지점에서 나눈 이유 1줄

## 목표              ← 이번 몫으로 좁힌다
## 의도 / ## 사용자 여정 / ## 용어 / ## 성공 조건   ← 원문 복사. 닫힌 조건은 `[x]` 그대로 둔다
## 아키텍처 결정      ← 확정 ADR 경로 + 상태
## 전제              ← 앞 작업에서 확정돼 남은 노드가 의존하는 사실. 항목마다 1줄 + 근거 파일 경로
## 노드 흐름          ← 남은 노드만 다시 그린다
## 후속 작업 / ## 유보 작업   ← 열린 항목 원문 이동
````

4. **노드 ID를 다시 매기지 않는다.** 이어받기의 새 노드는 같은 `NNN`에서 번호를 이어 붙인다(`005-N12` 다음은 `005-N13`). 선행이 봉인 노드면 표의 `선행` 칸에 그 ID를 그대로 적고 **흐름도에는 그리지 않는다.**
5. **열린 후속·유보 항목은 이어받기에만 둔다.** 양쪽에 남기면 다음 수확이 사본으로 집어 같은 일을 두 번 편성한다.

> **Do:** 봉인본은 `status: done`으로 닫고, 진행 중인 것은 이어받기 한 곳에만 둔다
> **Don't:** 노드 ID를 계획서 접미(`-0`·`-1`)에 맞춰 고치거나, 두 파일을 함께 `in-progress`로 둔다

## 검산 (커밋 직전 · 하나라도 어긋나면 커밋하지 않고 되돌린다)

1. 옮기고 지우는 동안 **이관·압축·닫힌 항목 삭제 건별로 줄 수를 적어 둔다.** `git diff --stat`의 파일별 `-` 합계가 그 총합과 맞는지 대조하고, 어긋나면 `git diff`로 어디서 벌어졌는지 짚는다.
2. 옮긴 덩어리마다 **첫 줄과 마지막 줄**을 목적지 파일에서 `grep -F`로 확인한다.
3. 노드 행 수 — 정리는 원본과 같고, 분리는 `봉인본 + 이어받기 = 원본`이다.
4. 노드 ID 중복이 없고, `산출` 칸에 적힌 경로가 실재한다.
5. 열린 후속·유보 항목의 **건수와 원문**이 그대로다.
